# Inbox: selfhost

Ideas and gaps found during work, not yet nodes. Triage with the user.

- 2026-10-30, same review: `TestSelfhostBuiltins` checks fixed-signature builtins with a one-way compile probe, so a Go parameter widened beyond the Narra table, or a result that is a subtype, passes. A Go-side dump of `checkFixed` signatures would make it exact.
- 2026-11-01, from the std-iterator discussion: async generators (`async function*`, "not in the first version" in SPEC section 8) would let `std/iterator` operators work on async streams, like IxJS AsyncIterable. Add time operators (`debounce`, `throttle`, `merge`) to `std/async` with them. Needs async and generators first.
- 2026-11-01, user direction: make closures more powerful and closer to TypeScript semantics after m11-closures. Candidates to weigh: inferring `escaping` where the cost is still visible in tooling, capturing `let` from escaping closures through an automatic `Cell`, and async closures. Each needs a decision record; run a goal debate before planning.
- 2026-11-02: compound assignment (`+=`, `-=` and the rest), increment and decrement (`++`, `--`), user request. Added as outline node compound-assign.
- 2026-11-05, from refining std-io-more: Path.basename suffix form (Node's basename(path, ext)) or a stem helper, if callers need it.
- 2026-11-05, from the PR #82 review: outside a parameter list, a `uses` list on a type takes every following `, name` as another effect (`parseUsesList`). So `#[Generator<int> uses io, int]` and `Map<Generator<int> uses io, int>` parse as one generator with effects `io, int`, and `#[Generator<int> uses io, Array<int>]` is a parse error. A trailing comma after `... uses E` in a parameter list gives `expected a name, found ")"`. Function types with `uses` have the same problem. A type with `uses` can only come last in a type list. Needs a language decision (for example parentheses around the effect list, or effects only after a name that is a known effect).
- 2026-11-07: named arguments decided (D87, `roadmaps/selfhost/debate/named-arguments/debate.md`): `move(x: 1, y: 2)`, any order, every argument passed. Planned as nodes after arg-eval-order. Parameter defaults are a separate debate, not started.
- 2026-11-07: async blocks and generator blocks parked (D88, `roadmaps/selfhost/debate/suspending-blocks/debate.md`). Rerun the debate when a program needs one.
- 2026-11-07, user approved for planning: tagged template literals, `tag\`text ${value}\``, with TypeScript's meaning. The tag is a function named at the use site, so no call is hidden. Open: the tag's signature (an `Array<string>` of parts and a typed list of values, or one call per value type), how values of different types pass without varargs (D12), effects of the tag, and whether std ships tags (for example a JSON or shell-quoting tag).
- 2026-11-07, user approved for planning: compile-time evaluation of pure functions. A function whose inferred or declared effects are empty (D58, section 7) can run at compile time, so a top-level `const` can call it instead of being limited to constant expressions (section 10, D61). Open: an interpreter in the compiler or compiling and running C, limits on time and memory, which builtins count as pure, `alloc` (pure in practice but an effect today), and how results are written into the generated C.
- 2026-11-07, user approved for planning: or-patterns, `Token.Plus | Token.Minus => ...`, after ReasonML. Alternatives can nest inside a pattern (`Some(1 | 2)`). Rules that keep union types out (D73): every alternative binds the same names with the same types (`Circle(r) | Sphere(r)`), a guard covers the whole or-pattern, and a binding of the whole value keeps the full type (no narrowing to the listed constructors). Exhaustiveness and unreachable-arm checks cover each alternative. Allow them in `match`; in `is` only without narrowing, or not at all. Bindings are copies as in other patterns (D81). Needs a `narrac fmt` layout for long alternative lists.
- 2026-11-09, from effect-variable-values (D91): a function value with effect variables that passes through a generic type parameter still loses the variable's binding; the call through the value does not charge the bound effects. Out of scope for D91.
- 2026-11-09, from spec-samples-test: the SPEC sample for `@unique` is skipped citing audit finding F15, which has no node. Plan it or drop the sample.
- 2026-11-09, from the D95 discussion: refinement types on distinct types, `distinct type Port = int requires >= 1 && <= 65535`, `distinct type Method = string requires "GET" | "POST"`. `Port.from(raw): Option<Port>` checks at runtime; the prover knows the predicate inside. Json.decode of such a type returns Err when the check fails (standard-schema style). Uses the D95 contract patterns.
- 2026-11-09, from type-aliases: diagnostics decorate a type with its alias by type, not by what the source wrote: once `type Tok = Token` exists in a package, every message about `Token` shows `Tok (Token)`, and aliases of primitives are never shown. Showing the alias only where it was written needs the written name carried through the checker. Also: constructors through a generic alias (`Alias.Ctor`) are not available.
- 2026-11-11, from shared-write-error: E0978 accepts a `mutable` write after another name's last use, but that name keeps the value until its scope ends, so the write still copies at run time (`const team = teams[0]; resetTeam(mutable team)` with `teams` unused afterwards). Either treat a name as live until its scope ends (more errors) or release a value at its last use in the emitter.
- 2026-11-11, from shared-write-error: the debug copy check counts copies on a payload box, not holders, so when the original holder releases first one copy's credits end early and a later legitimate copy can be reported (exit 103). Track holders to close it.
- 2026-11-11, from the batch-6 review: the shared-write rule does not track elements that share one value. `if (Arrays.filled([0, 0], 3) is Some(rows)) { let grid = rows; grid[0][0] = 5 }` compiles and copies at run time (exit 103 under NARRA_CHECK_COPIES=1); `[row, row]` is the same. SPEC section 6 lists it as a known gap. Treat heap elements of such arrays as shared, or keep it documented.
- 2026-11-11, from unsafe-ptr: an implementation's `alloc` and `io` are not limited to what its trait function declares, so a `Show.show` implementation can print and callers through the trait never see `io` (`unsafe` is enforced since batch-8). Enforcing it broke 21 cases, because pure trait functions such as `Show.show` have allocating implementations: closing it means adding `uses alloc` to such trait functions in the guide, SPEC, samples and `packages/traits`, and changing `effects_impl_through`. Needs a maintainer decision first. Also: SPEC could say in one line that creating an unsafe generator is allowed outside `unsafe`, and only running it is flagged.
- 2026-11-11, from hidden-copy-fix: a debug-built compiler (seed built without `-DNARRA_RELEASE`, run with `NARRA_CHECK_COPIES=1`) still reports hidden copies outside `loadFile`: `check testdata/arrays.nra` gives `array 3, map 1`, `emit selfhost` about 950 array and 964 map copies and exits 103. They come from the checker and emitter. A node should find the patterns behind them (likely more of the "write after the other name's last use" gap) before the debug check can run in CI.
- 2026-11-12, from fmt-block-hug: `std/src/coroutine.nra` and `std/src/option.nra` are not formatted, because the `sources` suite does not check `std/src`. Extend the suite to `std/src` and format them.
- 2026-11-12, from the fmt-block-hug review: when a block is not the last operand of an assignment chain (`const mid = x + {...} + y`), oxfmt prints all operands level, but `narrac fmt` keeps the extra indent because `endsWithBlock` (`selfhost/src/fmtexprs.nra`) checks only the rightmost operand.
- 2026-11-12, from the seed-switch review: `driver.nra` returns 1 with a full release when `startProgram` fails after a build (could exit through `exitWithoutRelease`), and `buildtarget.nra` compares the host target by its text.
