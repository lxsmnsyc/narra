# Errors

Every diagnostic code of `narrac`, with its message and, where there is one, its explanation. `narrac explain CODE` prints the same text. In a message, `%s`, `%q`, `%d`, `%c` and `%v` mark a name, text, number or character that the compiler fills in. A code with several messages is reported in several situations.

This page is generated by `scripts/errors/generate.nra` from `narrac explain --list --json`. Do not edit it.

Fix: add a `return` on that path, such as an `else` branch or a final `return` after the `if`.

#### E0970

```text
this arrow function must return %s on every path, but %s
```

An arrow function with a result type must end every path with `return value`. The message names a path that can reach the end without one.

Fix: add a `return` on that path, such as an `else` branch or a final `return` after the `if`.

#### E0971

```text
%s would be a second name for the %s in %s; use %s, or copy(%s) for %s of its own
```

Binding a struct, Array, Map, FixedArray, Box, StringBuilder or generator to a second bare name would name one value twice. A write through one name would not show in the other.

Fix: use the original name, or `copy(name)` for a value of its own. `narrac apply-fix` adds the copy.

#### E0972

```text
type alias %s refers to itself; a recursive type needs an enum
```

A type alias is another name for a type, so it cannot contain itself.

Fix: declare an enum for a recursive type.

#### E0973

```text
type alias %s takes %s type arguments, found %s
```

A generic type alias takes one type argument for each type parameter it declares.

Fix: give the right number of type arguments, as in `Pair<int>` for `type Pair<T> = Array<T>`.

#### E0974

```text
this alternative is unreachable: the arms and alternatives before it already match every value it matches
an `is` test takes one pattern, not alternatives; use `match` to list alternatives
a destructuring takes one pattern, not alternatives; use `match` to list alternatives
```

An alternative that the earlier arms and alternatives already match never runs. An `is` test and a destructuring take one pattern, not alternatives.

Fix: remove the unreachable alternative. To test several patterns, use `match`.

#### E0975

```text
copy takes one argument, found %s
copy does not change its argument; remove `mutable`
copy of %s copies nothing: a value of this type is never changed in place; remove the call
```

`copy` takes one value whose contents can change in place, such as a struct or an Array, and returns a copy of its own. A value that never changes in place, such as an int or a string, needs no copy. `copy` never changes its argument.

Fix: remove the call, or remove `mutable` from the argument. `narrac apply-fix` removes the call.

#### E0976

```text
the result shares parameter %q; write `from %s` after the result type
the result shares parameter %q, but the from marker names %q; return a copy with copy(...)
the arrow function returns a value that shares captured %q; a from marker can name only a parameter, so return a copy with copy(...)
the async block returns a value that shares captured %q; return a copy with copy(...)
the arrow function returns a value that shares its parameter %q, which its function type does not allow; return a copy with copy(...)
the arrow function returns a value that shares its parameter %q; write the result type with `from %s`, or return a copy with copy(...)
from names %s, which is not a parameter of %s
from names %s, which is not a parameter of this function type; name the parameter, as in `(%s: T) => R from %s`
from names %s, which is not a parameter of this arrow function; a from marker can name only a parameter
```

A function whose result shares a parameter says so with `from` after the result type, so callers see it in the signature. A result that shares a parameter without the marker, and a `from` that names no parameter, are errors.

Fix: add `from name`, as in `function cells(row: Row): Array<int> from row`, or return `copy(value)`. `narrac apply-fix` does this.

#### E0977

```text
this function's result shares its parameter %s, but the expected type %s has no matching from; add `from` naming that parameter to the expected type
```

A function whose result shares a parameter fits a function type only when that type also names the parameter with `from`.

Fix: add `from` to the expected function type, as in `(grid: Grid) => Array<int> from grid`. `narrac apply-fix` adds it.

#### E0978

```text
%s may change %s, which %s still uses at line %s%s
%s may change %s, which %s still holds for the caller%s
%s may change %s, which captured %s still holds%s
%s may change %s, which the cell %s still holds%s
%s may change %s, which constant %s still holds%s
%s may change %s, which the loop over %s still holds; change it after the loop, or loop over a copy(...)
```

While another name that is still used shares a place, a write to that place is an error. The write would copy the value, and the other name would not see the change. Sharing starts where a value is read into a second name and ends after that name's last use.

Fix: write after the last use of the other name, or take `copy(...)` where a separate value is meant.

#### E0979

```text
the divisor must be a non-zero constant or a name checked against zero first; %s
```

Integer `/` and `%` compile only when the divisor is proven not to be zero. It must be a non-zero constant, or a local checked first in the same function.

Fix: check the divisor, as in `if (count != 0) { return total / count }`.

#### E0980

```text
the shift count must be a constant from 0 to %s or a name checked against both ends first; %s
```

A shift count must be proven in range. It must be a constant from 0 to the bit width minus 1, or a local checked against both ends first.

Fix: check the count, as in `if (n >= 0 && n < 64) { return 1 << n }`, or use a constant in range.

#### E0981

```text
typeof %s refers to its own declaration; write the type out
typeof %s is part of the cycle %s; write one of the types out
```

`typeof name` takes the type of a declaration, so it cannot name the declaration it is part of, directly or through a cycle.

Fix: write the type out, as in `const count: int = 1`.

#### E0982

```text
typeof needs a value, but %q is a type; write the type itself, or the name of a const, let, parameter or function
typeof needs a value, but %q is a module; name a const, let, parameter or function
typeof %s has no function type to write: a generic function, one with effect variables and one with a mutable parameter cannot be used as a value
typeof %s has no function type to write: a function with requires cannot be used as a value
```

`typeof` takes the type of a value: a const, let, parameter or function. A type or a module is not a value. A generic function, one with effect variables, one with a `mutable` parameter and one with `requires` have no function type to write.

Fix: write the type itself, or name a value.

#### E0983

```text
this arm is unreachable: the arms before it already match every value it matches
```

An arm that the unguarded arms before it already match never runs, such as an arm after `_` or a repeated constructor.

Fix: remove the arm, or move it before the arm that covers it. `narrac apply-fix` removes it.

#### E0984

```text
requires is not allowed on a function of an implement block; a call through the trait cannot prove it
requires compares integer parameters with integer constants or with each other, joined by && and ||; %s
requires needs a function body; a trait function has none, so state it on the implementations
```

A `requires` condition compares integer parameters with integer constants or with each other, joined by `&&` and `||`. It needs a function body, and a function of an implement block cannot have one, because a call through the trait cannot prove it.

Fix: rewrite the condition in that form, as in `requires index >= 0 && index < 64`.

#### E0985

```text
this argument is not proven to meet `requires %s` of %s; pass a constant, or a name checked first with an `if`
%s does not satisfy `requires %s` of %s
%s do not satisfy `requires %s` of %s
```

Each call of a function with `requires` proves the condition from its arguments. An argument proves it when it is a constant, or a name checked first by an `if`, a `while` or an early return.

Fix: check the argument before the call, as in `if (n >= 0) { return slot(n) }`.

#### E0986

```text
function %s has a requires condition, so it cannot be used as a value; call it directly
```

A function type carries no condition, so a call through a function value could pass an argument that was never proven. A function with `requires` cannot be used as a value.

Fix: call the function directly.

#### E0987

```text
the comparison pattern `%s` needs an integer value, found %s
ensures describes the result, and this function returns nothing
an ensures pattern binds no names, found %s; write `_` for any value
the bound of `%s` does not fit the type %s
the literal %s cannot be proven for type %s; the prover keeps integers as int and cannot prove 2^63 - 1, -(2^63 - 1) or a u64 from 2^63 up
ensures needs a function body; a trait function has none, so state it on the implementations
the bound of `%s` must be an integer constant: a literal or a top-level const
an ensures pattern cannot be an array pattern; the prover keeps no facts about array lengths
```

An `ensures` line is a pattern that every result must match. A comparison such as `>= 0` needs an integer place and an integer constant that fits its type. `ensures` needs a function body and a result, binds no names, and takes no array patterns.

Fix: write `_` for any value and a constant bound, as in `ensures Ok(> 0) | Err(_)`.

#### E0988

```text
this value is not proven to match `ensures %s`; write a constant, a constructor, or a name checked first with an `if`
the values of yield* are not proven to match `ensures %s`; yield each value after a check
```

Every returned value is proven against each `ensures` line. A value is proven when it is a constant, a constructor or literal written in place, or a name narrowed by a check. The result of a call is not proven, and neither are the values of `yield*`.

Fix: check the value with an `if` before returning it, and yield each value of a `yield*` after a check.

#### E0989

```text
std/build has no target for this host (%s); the supported targets are %s
could not determine the host: %s
```

std/build describes the target the program is built for, so the host must be one of the supported targets.

Fix: build on a supported host. `narrac targets` lists them.

#### E0990

```text
`@%s` is written once, before a function declaration
unknown attribute @%s; the known attributes are %s
`@%s` is not allowed in an implement block; only @trusted is
@%s %s takes a variant such as Os.Windows
@target needs os, arch or both, such as @target(os = Os.Windows)
@target takes os and arch, not %s
@target names %s twice
@%s takes one string, as in @%s("name"), found %s
%s of std/build has no variant %s
@target takes %s from std/build here, not %s
```

The attributes are `@target`, `@trusted`, `@extern` and `@const`. Each is written once, on the lines before a function declaration, and an implement block allows only `@trusted`. `@target` takes `os`, `arch` or both, each a variant of `Os` or `Arch` from std/build.

Fix: use a known attribute in that place, as in `@target(os = Os.Windows)`.

#### E0991

```text
%s exists only on @target(%s), but this use is compiled for %s; use it inside an if on Build.os or Build.arch that keeps it only on that target
%s is not available on Wasi, but this use is compiled for %s; use it inside an if on Build.os that drops Os.Wasi
```

A `@target` function exists only on its target, so a use must sit where only that target compiles it: inside an `if` on `Build.os` or `Build.arch` that the other targets drop, or inside a `@target` function with the same or a narrower target. An ordinary `if`, a `match` and an early `return` do not count.

`narrac check` checks the host only; `narrac check --all-targets` checks every supported target.

Example: `print(linuxName())` becomes `if (Build.os == Os.Linux) { print(linuxName()) }`.

#### E0992

```text
a constant type parameter must have type int, found %s
constant type parameters are allowed only on functions and structs
a type argument cannot compute with `%s`; write an integer literal or a constant parameter
```

A constant type parameter is written `const N: int` in the type parameters of a function or a struct. Its kind is `int`; enums, type aliases and other integer kinds do not take one. A type argument is a type, an integer literal or a constant parameter in scope; it never computes.

Example: `Vector<N + 1>` is rejected; pass the length as its own constant parameter, `function grow<const N: int, const M: int>(vector: Vector<N>): Vector<M>`.

#### E0993

```text
%s is a constant, not a type; only a constant type parameter takes it
%s is a constant type parameter, not a type
the constant %s for %s does not fit an int
constant parameter %s takes an integer literal or a constant parameter, found %s
```

A constant parameter takes an integer literal or a constant parameter in scope, and a type parameter takes a type; the two do not mix. A local, a type or a top-level constant cannot stand for a constant parameter, and a constant cannot stand for a type.

Example: `Vector<count>` becomes `Vector<3>`, and `value: N` becomes `value: int` with `N` read in the body.

#### E0994

```text
index %s is out of range for %s, whose indexes are %s%s
the index of %s must be proven to be %s; %s%s
```

Indexing a FixedArray has no runtime check, so every index is proven at compile time. A constant index must be from 0 to N - 1. Any other index must be a plain name that a check puts in that range: an `if` or `while` condition such as `i >= 0 && i < 4`, the condition of `for (let i = 0; i < N; i++)`, or `for (const i of Ranges.upTo(N))`. An assignment to the name ends what the check proved. `FixedArrays.get(values, i)` returns an Option for any index.

Example: `values[i]` becomes `if (i >= 0 && i < 4) { use(values[i]) }`.

#### E0995

```text
the length of a FixedArray cannot be negative, found %s
the length %s of a FixedArray does not fit an int
the length of a FixedArray is an integer literal or a constant parameter, found %s
FixedArray takes an element type and a length, as in FixedArray<int, 4>
a literal cannot build %s: its length is a constant parameter, which the generic declaration does not know
%s needs %s elements, found %s
%s takes more than %s bytes, the limit for a FixedArray; use an Array
```

`FixedArray<T, N>` takes an element type and a length. The length is an integer literal or a constant type parameter, and never negative. One FixedArray value takes at most 1048576 bytes (1 MiB); use an Array for more. A literal builds a FixedArray when the expected type is one, and gives every element.

Example: `const point: FixedArray<f64, 3> = [1.0, 2.0, 3.0]`.

#### E0996

```text
%s is unsafe; call it inside an `unsafe { }` block
%s runs unsafe code; iterate it inside an `unsafe { }` block
```

A call of a std/ptr function or of a function with the unsafe effect may break memory safety, so it is allowed only inside an `unsafe { ... }` block. The function that holds the block gets the unsafe effect, unless it is marked `@trusted`.

Example: `const value = Ptr.read(items)` becomes `let value = 0` followed by `unsafe { value = Ptr.read(items) }`.

#### E0997

```text
@trusted on %s, which has no `unsafe` block; remove @trusted
%s is @trusted, so it does not have the unsafe effect; remove `uses unsafe`
```

`@trusted` states that a function's `unsafe` blocks were checked by hand, and stops the unsafe effect there: callers need no `unsafe` block. A function without an `unsafe` block has nothing to trust, and a `@trusted` function does not declare `uses unsafe`.

Example: remove `@trusted` from a function that has no `unsafe` block.

#### E0998

```text
Ptr takes one type argument
Ptr<%s> is not allowed: %s; a pointer may point at numbers, bool, char, Ptr and structs of those
%s takes a Ptr, found %s
%s takes its element type from where the result goes, as in `%s`
```

A `Ptr<T>` is a raw pointer with no reference count. It may point at numbers, `bool`, `char`, another `Ptr` and structs whose fields are all such values, because a pointer to a string, array, map, box, enum or closure would bypass reference counting. The std/ptr functions take a `Ptr`; `Ptr.alloc`, `Ptr.null` and `Ptr.cast` take the element type from where the result goes.

Example: `Ptr<string>` is rejected; `const items: Ptr<int> = Ptr.alloc(4)` works.

## E1000 to E1099: C interop and unsafe code

#### E1000

```text
@extern is written on a function inside an `extern { } from` block
an extern block ends with `from "library"`, found %s
%q is not a library name; write the name cc takes after -l, such as "m"
an extern block declares at least one C function
@%s is not written on a function of an extern block; only @extern is
an extern block holds only function signatures, found %s
%s in an extern block cannot be generic or a generator
%s in an extern block has the unsafe effect already; remove `uses`
%s in an extern block has no body; the C library provides it
unknown key %s in [link]; [link] takes search
```

C functions are declared in a block that names their library: `extern { function sqrt(value: f64): f64 } from "m"`. A member is a signature with no type parameters, no `uses` and no body; it has the unsafe effect. Only `@extern("name")` may stand before a member. The libraries come from `from`, so `[link]` in narra.toml takes only `search`.

Example: `[link] libraries = ["m"]` is removed; write `from "m"` after the extern block.

#### E1001

```text
"%s" is not a C name; a C name is letters, digits and _, not starting with a digit
the C name %s clashes with %s that the compiler writes; give the function another name with @extern
```

A C function is linked by its C name, the member's name or the one `@extern` gives. That name must be a C identifier and must not be one the compiler writes itself: `main`, names starting with `narra_` or `lstr_`, string literal names such as `L1`, and the generated names of the program's functions and types, alone or with a helper's operation before or a suffix after (`release_E_Option_e088c655`).

Example: `@extern("narra_alloc")` is rejected; call the C function by its own name.

#### E1002

```text
%s of C function %s has type %s; a C function takes numbers, bool and Ptr<T>
C function %s returns %s; a C function returns numbers, bool, Ptr<T> or nothing
```

A C function takes and returns values C can pass: the number types, `bool` and `Ptr<T>`, and may return nothing. Strings, arrays and other counted values have no C form; pass a `Ptr<u8>`, for a string `CStrings.pointer` of a CString.

Example: `function strlen(text: string): u64` becomes `function strlen(text: Ptr<u8>): u64`.

#### E1003

```text
the type of constant %q is not known here; write it as `const %s: Type = ...`
```

`typeof` of a constant needs the constant's type, and a constant without a written type has its type only after its value is checked. In a declaration of the same module (a signature, a field, an alias) that type is not known yet, so write it.

Example: `const limit = 3` becomes `const limit: int = 3`.

#### E1004

```text
a source line or column must be below %s; split the file or the line
```

The compiler tracks a position as a line and a column below 1048576 each. A token past either limit is rejected, since it would share a record with another position. Split the file, or break the long line.

#### E1010

```text
a tuple index must be a constant integer; use a pattern such as `const #[first, second] = pair` to read the elements
```

A tuple element is read with a constant index, `pair[0]`, so the read is a field read and cannot fail. An index that is a `let`, a parameter or any other computed value is rejected, because the element type would depend on it. A top-level `const` works. To read every element, destructure the tuple.

Example: `pair[count]` becomes `const #[first, second] = pair`.

#### E1011

```text
index %d is out of range for %s, whose indexes are 0 to %d
```

A tuple has a fixed number of elements, and a constant index must name one of them, counting from 0. Tuple elements are read-only, so `pair[0] = 2` is E0226.

Example: for `#[int, string]`, the indexes are 0 and 1; `pair[2]` and `pair[-1]` are rejected.

#### E1012

```text
cannot derive %s for %s: its base type %s does not implement %s
```

A distinct type has the representation of its base type, so a derived trait is the base type's: `distinct type UserId = int derives Show` prints as an int. The derive needs the base type to implement the trait.

Example: `distinct type Handle = Ptr<int> derives Show` is rejected, since a pointer has no Show; write an `implement Show for Handle` block and list `implements Show`.

#### E1013

```text
%s cannot be used as a value: %s; wrap it in an arrow function, such as `%s`
```

A standard function is a value when its signature is fixed: `Int.toString`, `Str.length`, `Fs.readText`. A function whose types depend on the call (`Arrays.length`, `Maps.size`), one with a `mutable` parameter and one that takes a function argument have no single signature, so they are not values.

Example: write the arrow function `(items) => Arrays.length(items)` instead of `Arrays.length`.

#### E1014

```text
cannot implement %s for %s: %s on a distinct type compares the base value
```

`==`, `!=` and map keys on a distinct type compare and hash the base value, so an `implement Equatable` or `implement Hashable` block for it would never run and is rejected. Write the comparison as a function of the declaring module, or wrap the value in a struct.

Example: `implement Equatable for UserId` is rejected for `distinct type UserId = int`.

#### E1020

```text
%s does not implement %s, which %s needs for type parameter %s
%s does not implement %s, which %s needs for type parameter %s; declare it as <%s: %s>
```

A struct or enum can require traits of its type parameters, as in `struct Labeled<T: Show>`. Every use of the type with arguments must meet them: a written type, a struct literal and an enum constructor. A type parameter of the enclosing function or type meets a constraint only when it declares the same trait; constraints are not implied.

Example: `function first<T>(pair: Labeled<T>)` is rejected; write `function first<T: Show>(pair: Labeled<T>)`.

#### E1021

```text
`implement %s for %s` must name the type as %s, with the type parameters of its declaration in order
```

An implement block for a generic struct or enum names the type with the type parameters of its declaration, by the same names and in the same order. The block adds no constraints of its own: the members see the constraints the declaration gives, and the block holds for every instance.

Example: for `struct Pair<T>`, `implement Show for Pair<int>` and `implement Show for Pair` are rejected; write `implement Show for Pair<T>`.

#### E1022

```text
Dynamic takes one trait argument
Dynamic takes a trait, and %s is not a trait
```

`Dynamic<Trait>` holds a value of any type that implements one trait, so its one type argument is a trait name. `Dynamic<int>`, `Dynamic` alone and `Dynamic<Show, Ordered>` are rejected.

Example: write `Dynamic<Show>`.

#### E1023

```text
Dynamic<%s> needs Self as the first parameter of every function of %s, and %s.%s does not take it first
Dynamic<%s> needs Self only as the first parameter of every function of %s, and %s.%s names it elsewhere
```

A call through a `Dynamic<Trait>` passes the Dynamic where the trait writes `Self`, and the table of the stored type does the rest. That works only when every function of the trait takes `Self` as its first parameter, once and not inside another type, and mentions `Self` nowhere else, the result included. `Equatable` and `Ordered` take two values, and `Shape.fromValue` returns `Self`.

Example: `trait Drawable { function draw(value: Self): string }` can be used as `Dynamic<Drawable>`.

#### E1024

```text
Dynamic has no function %s; Dynamic.of(value) is its only function
Dynamic.of takes one value
Dynamic.of needs an expected Dynamic<Trait> type; annotate it, as in `const item: Dynamic<Show> = Dynamic.of(value)`
```

`Dynamic.of(value)` takes the trait from the expected type: an annotation, a parameter type, a field type or a result type. It takes one value and is the only function of `Dynamic`.

Example: `const item: Dynamic<Show> = Dynamic.of(42)`.

#### E1025

```text
%s.%s takes a mutable Self, and a Dynamic<%s> cannot be passed to it: its value is shared by every copy
```

Every copy of a Dynamic shares one stored value, so a trait function that takes `mutable value: Self` cannot be called through a Dynamic: the change would reach the other copies.

Example: call the function on the concrete value before wrapping it with `Dynamic.of`.

#### E1050

```text
@const function %s %s; an @const function takes and returns numbers, bool, char, string, bytes, Array, Map, FixedArray, Option, Result, tuples, and structs, enums and distinct types made of these
```

The compiler runs an @const function while it compiles and writes the result into the C, so its parameters and result hold only values the compiler can build and write: numbers, bool, char, string, bytes, Array, Map, FixedArray, Option, Result, tuples, and structs, enums and distinct types made of these. A function value, Cell, Ptr, Shared, a generator, a trait-constrained type parameter or an effect parameter has no compile-time value.

Fix: remove @const, or change the signature.

#### E1051

```text
@const function %s declares `uses %s`; an @const function may use only alloc
@const function %s uses %s%s; an @const function may use only alloc
```

An @const function runs inside the compiler, where nothing outside it can observe what it does. It may allocate, and nothing else: no io and no unsafe code.

Fix: move the effect out of the function, or remove @const.

#### E1052

```text
@const function %s %s; an @const function calls only @const functions, constructors and the std functions of %s that take no function
constant %s cannot be computed while compiling: %s
```

An @const function calls other @const functions, constructors and the std functions of std/string, std/array, std/map, std/int, std/float, std/range, std/char, std/option, std/result, std/regex, std/math, std/bytes, std/fixedarray, std/f32 and the sized number modules that take no function. It cannot use an arrow function, call through a function value or run a user implement block (through ==, a map key or a direct call).

Fix: mark the called function @const, compute the value another way, or remove @const.

#### E1053

```text
constant %s panicked while the compiler computed it: %s
```

The compiler computes a constant that calls an @const function while it compiles. A panic, a failed assert, an index out of range or a std function that would panic stops the computation, and the error shows the chain of calls from the constant to where it stopped.

Fix: change the arguments or the function so it does not panic.

#### E1054

```text
constant %s needs more than %s evaluation steps; %s
```

A constant may take 10 million evaluation steps (one per expression, statement and loop turn, plus one per 8 bytes or elements a std call goes through), so a mistake such as an endless loop cannot hang the compiler.

Fix: compute a table this large at run time in a function, or generate a source file; for Regexes.checked, compile the pattern at run time with Regexes.compile.

#### E1055

```text
constant %s needs more than 64 MiB of values (%s); %s
```

The values a constant builds while it is computed may take 64 MiB, counted as 8 bytes per number, element, field and entry, string lengths rounded up to 8, and 16 per array and map; `copy(...)` and storing a value read from a place count its outer level again. A std call whose result would pass the limit is stopped before it runs.

Fix: compute a table this large at run time in a function, or generate a source file; for Regexes.checked, compile the pattern at run time with Regexes.compile.

#### E1056

```text
constant %s makes more than %s nested calls; a self-call in tail position runs as a loop and does not count
constant %s holds a value nested more than %s levels deep; the compiler writes a computed value only up to that depth
constant %s nests calls, blocks and expressions more than %s deep; a self-call in tail position runs as a loop and does not count
```

A constant may make 1000 nested calls while it is computed, nest calls, blocks, loops and expressions 5000 deep, and build values nested 1000 levels deep, which keeps the compiler stack safe. A function that calls itself as its last step (`return f(...)`) runs as a loop and does not count.

Fix: write the recursion as a loop or as a tail call.

#### E1057

```text
constant %s is read by an @const function while it is computed, so it is defined in terms of itself
```

An @const function may read top-level constants. A constant whose computation reads the constant itself has no value to start from.

Fix: break the cycle, for example by passing the value as an argument.

## E1100 to E1199: Concurrency

#### E1100

```text
await is allowed only in an async function, an async arrow or an async block, not %s
```

`await` waits for a task, so it can stand only where the body is itself a task: an async function, an async arrow or an async block. A `function*` body and an arrow that is not async are bodies of their own, also inside an async body.

Fix: make the function or arrow async, or pass the handle on and await it in an async body.

#### E1102

```text
await takes an Async<T>, found %s; only the handle of a task can be awaited
```

`await` takes the handle of a task, an Async\<T\>, and gives its value.

Fix: await the call that returns the handle, or use the value without await.

#### E1103

```text
this Async handle is not used; await it, keep it, pass it on, or let the task run with Async.detach(handle)
```

A call of an async function, an async arrow or an `async { ... }` block starts a task and gives its handle. A handle that nobody uses hides a task that keeps running; `const _ =` does not let it go.

Fix: await the handle, keep it in a name, pass it on, or call Async.detach(handle) to let the task run with nobody waiting.

#### E1104

```text
async function %s cannot take a mutable parameter %s; its task outlives the call
```

A task outlives the call that starts it, so it cannot keep a pointer into the caller's variable.

Fix: take the value as a plain parameter and return the new value from the task.

#### E1105

```text
`for await (mutable ...)` is not allowed: a stream's values are not elements to change in place; write `for await (const x of stream)`
`for (mutable ...)` is not allowed in an async body; change the elements through an index, as in `items[index].field = value`
```

A `for (mutable ...)` loop holds a pointer to the element it changes, which cannot be kept in a task frame across an await. `for await (mutable ...)` is rejected too: the values of a stream are not elements of a place.

Fix: change the elements through an index; read a stream with `for await (const x of stream)`.

#### E1106

```text
cannot use == on %s: a task handle is shared by identity; await the handles and compare the values
cannot use == on %s: a stream is shared by identity; read the values and compare them
%s cannot be a map key: %s
```

A handle is an identity type: copies share one task, so == and a map key would compare tasks, not values.

Fix: await the handles and compare or key by the values.

#### E1108

```text
async must be followed by function, an arrow function or a block, found %s
```

`async` starts an async function, an async arrow or an async block.

Fix: write `async function`, `async (x) => ...` or `async { ... }`.

#### E1109

```text
Async takes one type argument, the value of the task
```

Async\<T\> takes the type of the task's value as its one type argument.

Fix: write Async\<T\>, with Async\<void\> for a task that gives no value.

#### E1110

```text
an async arrow or block cannot capture %s, which is %s: the task copies its captures when it starts; keep state that changes in a Cell from std/cell
an async arrow or block cannot change captured %s: the task copies its captures when it starts; keep state that changes in a Cell from std/cell
```

An async arrow or block copies what it captures when its task starts, so a `let`, a `mutable` parameter or a captured value it changes would no longer be shared with the code around it.

Fix: keep state that changes in a Cell from std/cell, or pass the value in and return the new one.

#### E1111

```text
parameter %s of async function %s has a function type, so it must be `escaping`: the task outlives the call
```

An async function keeps its parameters in its task, which outlives the call, so a function parameter must be one that may be stored.

Fix: declare the parameter as `escaping`.

#### E1112

```text
async generator %s must declare its return type as AsyncGenerator<T>, not Generator<T>; write AsyncGenerator<T>
async generator %s must declare its return type as AsyncGenerator<T>
```

An `async function*` produces a stream of values that may wait between them, read with `Async.next` or `for await`. Its result names that stream, with the effects of the body on it.

Fix: write the result as `AsyncGenerator<T>`, as in `async function* lines(): AsyncGenerator<string> uses io`.

#### E1113

```text
generator %s cannot return AsyncGenerator<T>, which needs an async body; declare it as `async function* %s`
```

An AsyncGenerator\<T\> body may wait between its values, so only an async generator can return one from its own body. A plain or async function may still return a stream it got elsewhere.

Fix: write `async function*`, or return a Generator\<T\>.

#### E1114

```text
AsyncGenerator takes one type argument, the type of the values it yields
```

AsyncGenerator\<T\> takes the type of the values the stream yields as its one type argument.

Fix: write AsyncGenerator\<T\>.

#### E1115

```text
`const %s = yield value` needs a coroutine, and an async generator has no input; write `yield value`
```

An async generator yields values to its readers and gets nothing back: there is no async coroutine.

Fix: write `yield value` as a statement, and pass input to the stream through its arguments or a Cell.

#### E1116

```text
yield* in an async generator needs a %s, found %s; write `for (const x of g) { yield x }`
yield* in an async generator needs a %s, found %s
```

`yield*` in an async generator passes on every value of another AsyncGenerator\<T\> with the same T, one per step of the outer stream.

Fix: delegate to an AsyncGenerator\<T\>; for a Generator\<T\>, write `for (const x of g) { yield x }`.

#### E1122

```text
for await is allowed only in an async function, an async arrow, an async block or an async generator, not %s
```

`for await` waits for each value of a stream, so it can stand only where the body is itself a task: an async function, an async arrow, an async block or an async generator. A `function*` body and an arrow that is not async are bodies of their own, also inside an async body.

Fix: make the function or arrow async, or read the stream with Async.next in an async body.

#### E1123

```text
for await reads an AsyncGenerator<T>, found %s; read a Generator<T> with `for (const x of g)`, which works in an async body
for await reads an AsyncGenerator<T>, found %s; loop with `for (const handle of handles)` and `await handle` in the body
for await reads an AsyncGenerator<T>, found %s
```

`for await` reads an AsyncGenerator\<T\>, the stream an `async function*` gives, one step at a time.

Fix: for a Generator\<T\> or an array, write `for (const x of items)`, which works in an async body; for an Array\<Async\<T\>\>, loop over the handles and `await` each one.

#### E1124

```text
for ... of cannot read %s, whose values may wait; write `for await (const x of stream)` in an async body
```

The values of an AsyncGenerator\<T\> may wait, so a plain `for ... of` cannot read them.

Fix: write `for await (const x of stream)` in an async body, or read one step with `await Async.next(stream)`.

#### E1150

```text
%s cannot take an Async<void>: type parameter %s would be void outside Async<%s>, and a task with no value gives none
```

An Async\<void\> handle binds the type parameter of its Async\<T\> to void. A generic function whose signature also uses that parameter as a value, such as Async.peek (Option\<T\>), Async.all (Array\<T\>) or Async.race (Option\<T\>), would need a void value, which does not exist.

Fix: await the handles one by one, or give the task a value, such as a bool.

#### E1190

```text
%s: %s is not Sendable%s
```

A value that crosses to another thread (a capture or the result of a thread function, the items of Parallel.map) must be Sendable. Sendable is automatic: a type is Sendable when nothing in it, at any depth, is a function, a Dynamic, a Ptr, a Cell, an Async, a generator or coroutine, a Scope, a Thread or a socket handle. These hold state that one thread changes in place without a lock.

Fix: share changing state through Shared from std/shared, send plain data, and declare a type parameter that crosses as \<T: Sendable\>.

#### E1191

```text
%s holds a Scope; a Scope can be passed to a function, but not stored in a field, element, tuple or constructor
a function cannot return a Scope (%s): every thread of a Scope ends when its Thread.scope returns
a generator, coroutine, stream or task cannot hold a Scope (%s): it can run after its Thread.scope returns
an escaping closure or a task cannot capture Scope %q; pass the Scope to a function as a parameter, or open a new Thread.scope inside the closure
```

A Scope joins its threads when its Thread.scope returns, so it must not outlive that call. It can be passed to functions, but not stored in a field, element, tuple or constructor, returned, captured by an escaping closure such as a thread function, or kept in the frame of a generator, coroutine, stream or task (a parameter or a capture), which can run after Thread.scope returns.

Fix: pass the Scope as a parameter to the function that starts threads, or open a new Thread.scope where it is needed.

#### E1192

```text
Thread.start takes a plain function; use Thread.startAsync to run an async function on a thread
```

Thread.start calls its function and keeps what it returns. An async function returns an Async handle, which belongs to the event loop of the thread that made it. Thread.startAsync runs the task on the new thread's own event loop and keeps the value the task gives.

Fix: write `Thread.startAsync(scope, async () => work())`, or pass a plain function to Thread.start.

#### E1193

```text
a thread function must be an arrow function written at the call or the name of a top-level function, so its captures can be checked
```

The checker must see what a thread function captures, and a function value does not show its captures in its type. So the function passed to Thread.start or Parallel.map is an arrow function written at the call or the name of a top-level function.

Fix: write the arrow at the call, as in `Thread.start(scope, () => work(input))`.

#### E1194

```text
cannot write `%s Sendable`: the compiler implements Sendable for every type whose parts can cross a thread
```

Sendable is only automatic: the compiler implements it for every type whose parts can cross a thread, so a type cannot list, derive or implement it.

Fix: remove the `implement Sendable`, `implements Sendable` or `derives Sendable`.

#### E1195

```text
cannot use == on %s: %s is shared by identity; compare the values it gives
%s cannot be a map key: %s
```

A Thread, a Scope, a Sender, a Receiver, a Shared or an Atomic is a handle shared by identity, so `==`, `!=` and map keys on it are errors, as for a Cell and an Async.

Fix: compare the values the handles give, for example the results of Thread.join or Shared.get.

## E1200 to E1299: Types and parameters: templates, defaults, refinements, effect lists, SIMD, ranges

#### E1200

```text
a template after an expression is a tagged template, and only a name or a dotted name can be its tag
a tag takes no type arguments; the tag's parameters give its type
```

A template right after a name is a tagged template: `tag`a${x}b`` calls `tag(["a", "b"], [x])`. Only a name or a dotted name can be the tag, so the function called is named where it is used.

Fix: put the tag in a constant first (`const tag = make()`, then `tag`...``), or write a space-free name before the template.

#### E1201

```text
a tag must be a function of (Array<string> or Template.Raw, Array<T>) with no mutable parameter, found %s
```

A tag is a function of two parameters: the parts, `Array<string>` (escapes decoded) or `Template.Raw` from std/template (the source text), and the values, `Array<T>`. Neither parameter can be `mutable`.

Fix: give the tag that signature, for example `function tag(parts: Array<string>, values: Array<string>): string`.

#### E1202

```text
value %s of the tagged template is %s, but the tag takes values of type %s; convert it inside the ${}
value %s of the tagged template is void; a value must have the tag's value type
```

Every `${}` value of a tagged template has the tag's value type T, the element type of its second parameter. A generic tag takes T from the first value.

Fix: convert the value inside the `${}`, for example `${Int.toString(count)}`.

#### E1203

```text
a template at the start of a line is not tagged by the name that ends the line before; join the lines to tag it
```

A line break ends the statement, so a template at the start of a line is not tagged by the name at the end of the line before.

Fix: write the tag and the template on one line, `const x = tag`a``, or remove the template.

#### E1210

```text
a parameter without a default cannot follow one with a default; give %q a default or move it before %q
```

Parameters with defaults come last, so a call can leave them out from the end.

Fix: give the parameter a default, or move it before the first parameter with one.

#### E1211

```text
a mutable parameter cannot have a default
```

A `mutable` parameter refers to a value that the caller passes, so it cannot have a default.

Fix: remove the default.

#### E1212

```text
a parameter default must be a constant
```

A parameter default is a compile-time constant: a literal, a unary operator on a constant, a constructor with constant arguments, or an array of constants. It cannot read another parameter, a local, a top-level constant or a function.

Fix: write the value as a literal, or take `Option<T> = None` and compute the value in the body.

#### E1213

```text
an arrow function parameter cannot have a default
a function type cannot have parameter defaults
```

Only declared functions take parameter defaults. An arrow function parameter and a function type parameter have none.

Fix: remove the default and pass the value at each call.

#### E1214

```text
a trait function cannot have parameter defaults
```

A trait function and the functions of its implement blocks cannot have parameter defaults.

Fix: remove the default and pass the value at each call.

#### E1215

```text
a function of an extern block cannot have parameter defaults
```

The functions of an `extern` block cannot have parameter defaults.

Fix: remove the default and pass the value at each call.

#### E1216

```text
optional parameters are written with a default; write %q
an arrow function parameter cannot be optional; write %q
```

An optional parameter is written with a default, not with `?`. An arrow function parameter cannot be optional.

Fix: `name?: string` becomes `name: Option<string> = None`. In an arrow function, write `name: Option<string>`.

#### E1220

```text
a distinct type's `requires` needs a pattern here, found %s
a distinct type takes one `requires` list; join its patterns with `&&`
`implements` and `derives` come before `requires` on a distinct type
```

A distinct type takes one `requires` list of patterns joined by `&&`, after its `implements` and `derives` lists.

Fix: write it as in `distinct type Port = int derives Show requires >= 1 && <= 65535`.

#### E1221

```text
distinct type %s cannot have a requires list: its base %s is not an integer type or string
```

Only a distinct type over an integer type or `string` can have a `requires` list.

Fix: remove the list, or base the type on an integer type or `string`.

#### E1222

```text
%s refines string, so its patterns are string literals; `%s` compares integers
the bound of `%s` does not fit %s's base %s
the bound of `%s` must be an integer constant: a literal or a top-level const
the literal %s cannot be proven for %s's base %s; the prover keeps integers as int and cannot prove 2^63 - 1, -(2^63 - 1) or a u64 from 2^63 up
the literal %s is not a value of %s's base %s
a refinement pattern is a comparison, a literal or alternatives of them, found %s
```

The patterns of a distinct type's `requires` fit its base. An integer base takes comparisons with a constant bound that fits the type, and integer literals. A `string` base takes string literals only.

Fix: write patterns such as `>= 1 && <= 65535` or `"GET" | "POST"`.

#### E1223

```text
%s does not satisfy %s (%s)
%s.from needs %s to satisfy %s; check it first or call %s.check
```

`T.from(value)` is proven at compile time against the type's `requires` patterns. Nothing is checked at run time.

Fix: pass a constant that matches, check the value first with an `if`, or call `T.check(value)`, which returns an Option and tests at run time.

#### E1240

```text
a type's `uses` list takes one effect, or several in parentheses: `uses (%s, %s)`
```

In a type, `uses` takes one effect, or a comma list in parentheses: `() => int uses io`, `Generator<int> uses (io, alloc)`. A `,` after the one effect ends the type, so the type can stand in a list of types or parameters. A function's own list, after its result type, is a bare comma list.

Fix: put the type's effects in parentheses, `Generator<string> uses (io, alloc)`. A function that makes a generator writes its own list after it: `(): Generator<string> uses (io, alloc) uses alloc`.

#### E1241

```text
`%s` is an effect, not a type
`%s` is an effect, not a type; a type takes several effects in parentheses: write `uses (%s)`
```

`io`, `alloc`, `unsafe` and effect variables name effects, which only a `uses` list holds; they are not types. In a list of types such as `Map<Generator<int> uses io, alloc>`, the `,` ends the generator's one effect, so `alloc` stands where a type belongs.

Fix: write the effects in parentheses, `Map<Generator<int> uses (io, alloc), int>`, or move the name into a `uses` list.

#### E1242

```text
`%s` is listed twice in this `uses` list
```

A `uses` list names each effect once, in a type and in a function's own list.

Fix: delete the repeated name: `uses (io, io)` in a type and `uses io, io` on a function both become `uses io`.

#### E1250

```text
%s is not defined on %s; compare the lanes with %s
%s is not defined on %s: no SIMD instruction divides integer lanes; read the lanes with v[i] and divide them one at a time
%s is not defined on %s; shift the lanes with %s
%s is not defined on %s, whose lanes are floats; it takes integer vectors
```

Vector operators work lane by lane, and some have no lane form. These are `<` and the other ordered comparisons, integer `/` and `%`, `<<` and `>>`, and the bit operators on float lanes.

Fix: call the std/simd function the message names, such as `Simd.shiftLeft`.

#### E1251

```text
%s needs two vectors of the same type, found %s and %s
%s needs two vectors of the same type, found %s and %s; make a vector of the scalar with Simd.splat(...)
```

Both operands of a vector operator have the same vector type. A scalar is not a vector.

Fix: `v * 2.0` becomes `v * Simd.splat(2.0)`.

#### E1252

```text
a lane of %s cannot be assigned, since a vector is a value; write `v = Simd.withLane(v, i, x)`
```

A vector is a value, so one lane cannot be assigned.

Fix: `v[i] = x` becomes `v = Simd.withLane(v, i, x)`.

#### E1253

```text
%s needs %d lanes, found %d
```

An array literal for a vector gives exactly one value per lane.

Fix: give as many values as the vector has lanes, as in `const unit: F32x4 = [1.0, 0.0, 0.0, 0.0]`.

#### E1254

```text
%s takes its vector type from where the result goes or from a type argument, as in `const ones: F32x4 = Simd.splat(1.0)` or `Simd.splat<F32x4>(1.0)`
%s takes its vector type from where the result goes or from a type argument, as in `const lanes: Option<F32x8> = Simd.load(items, 0)` or `Simd.load<F32x8>(items, 0)`
```

`Simd.splat` and `Simd.load` cannot tell from their arguments which vector type to build.

Fix: annotate the target, as in `const ones: F32x4 = Simd.splat(1.0)`, or pass a type argument, as in `Simd.splat<F32x4>(1.0)`.

#### E1255

```text
%s has no vector type: a vector holds 16 or 32 bytes of i8 to u64, f32 or f64 lanes
%s takes a FixedArray of known length, found %s
```

A vector holds 16 or 32 bytes of i8 to u64, f32 or f64 lanes. `Simd.fromFixed` needs a FixedArray of known length whose element type and length make such a vector.

Fix: pass a matching FixedArray, such as `FixedArray<f32, 4>` for F32x4.

#### E1256

```text
%s takes a vector, found %s
```

This std/simd function takes a vector, such as an F32x4, and the value passed is not one.

Fix: pass a vector, or build one with `Simd.splat`.

#### E1260

```text
the lanes of %s are a list literal of constants, one per lane, as in `Simd.shuffle(v, [3, 2, 1, 0])`
%s takes %d lanes for %s, found %d
lane %d is out of range for %s, whose lanes are 0 to %d
a lane of %s must be a constant, as in `Simd.shuffle(v, [3, 2, 1, 0])`
```

`Simd.shuffle` takes the lane order as a list literal of constants, one per lane, each a lane of the vector.

Fix: write it as in `Simd.shuffle(v, [3, 2, 1, 0])`.

#### E1261

```text
%s does not take %s, whose lanes are floats; it takes integer vectors
%s does not take %s, which is unsigned; it takes signed and float vectors
%s takes the mask %s for %s, found %s
%s writes %s into an Array<%s>, found %s
```

Some std/simd functions take only some vector types: integer vectors only, or signed and float vectors only. A mask must match the vector, and a store writes into an Array of the lane type.

Fix: pass the vector, mask or array type that the message names.

#### E1270

```text
the step of Ranges.stepped is 0, so the range is always empty; use a step other than 0
```

`Ranges.stepped` with a step of 0 never produces a value.

Fix: use a positive step to count up, or a negative step to count down.

## E1300 to E1399: Standard library modules for tools

#### E1360

```text
%s can only be the value of a top-level const; use %s
```

Regexes.checked compiles its pattern while the compiler runs, so a bad pattern is a compile error (E1053) instead of a panic. That works only where the compiler computes the value: the value of a top-level const. Anywhere else, including a function body or a use as a function value, the call would run in the program and could panic.

Fix: move the call into a top-level const, or call Regexes.compile and handle its RegexError.

## E1400 to E1499: Channels, Shared and Atomic

#### E1410

```text
the callback of %s cannot be async: it runs while the lock is held, and a task must not suspend there
```

Shared.update and Shared.read hold the lock while their callback runs. An async callback would give an Async whose task runs later, after the lock is released, or suspend while other threads wait for the lock.

Fix: pass a plain function, and await the work before or after the call.

#### E1411

```text
Atomic<%s> is not allowed: an Atomic holds bool or an integer type up to 64 bits; keep other values in a Shared from std/shared
```

An Atomic\<T\> uses the processor's atomic operations, which work on bool and the integer types up to 64 bits (int, i8 to i32, u8 to u64). A type parameter is not allowed either, since no bound says "an integer type".

Fix: use an integer type, or keep the value in a Shared from std/shared.

#### E1412

```text
Atomic.add needs an integer type, found Atomic<bool>; use Atomic.store or Atomic.compareExchange
```

Atomic.add adds to an integer. An Atomic\<bool\> has no sum.

Fix: use Atomic.store, Atomic.exchange or Atomic.compareExchange to change a flag.

## E1500 to E1599: Unreachable statements and unused let

#### E1500

```text
this statement is unreachable: the statement before it always leaves the block
```

A statement after `return`, `break`, `continue`, a call to `panic` or `Process.exit`, an `if` and `else` that both leave, a `match` whose arms all leave, or a `while (true)` loop without a `break` never runs.

Fix: delete the statements from the first dead one to the end of the block, or move the code before the statement that leaves.

#### E1510

```text
%q is never reassigned; declare it with `const`
```

A `let` tells the reader that the name gets a new value later. A name that is never assigned, never changed with `+=` or `++`, and never has a field, an element or a `mutable` argument written is a `const`.

Fix: write `const` instead of `let`.

## E1600 to E1699: Build targets

#### E1600

```text
unknown target %s; the targets are %s
```

`--target` takes a name from the target table.

Fix: use one of the names in the message. `narrac targets` prints them.

#### E1601

```text
-sanitize cannot build for %s: sanitizer runtimes do not cross-link; build without -sanitize
```

The sanitizer runtimes do not link into a build for another target.

Fix: build without `-sanitize`, or build on the target itself.
