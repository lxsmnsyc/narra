# Inbox: selfhost

Ideas and gaps found during work, not yet nodes. Triage with the user.

- 2026-11-01, from the std-iterator discussion: async generators (`async function*`, "not in the first version" in SPEC section 8) would let `std/iterator` operators work on async streams, like IxJS AsyncIterable. Add time operators (`debounce`, `throttle`, `merge`) to `std/async` with them. Needs async and generators first.
- 2026-11-01, user direction: make closures more powerful and closer to TypeScript semantics after m11-closures. Candidates to weigh: inferring `escaping` where the cost is still visible in tooling, capturing `let` from escaping closures through an automatic `Cell`, and async closures. Each needs a decision record; run a goal debate before planning.
- 2026-11-05, from refining std-io-more: Path.basename suffix form (Node's basename(path, ext)) or a stem helper, if callers need it.
- 2026-11-07: named arguments decided (D87, `roadmaps/selfhost/debate/named-arguments/debate.md`): `move(x: 1, y: 2)`, any order, every argument passed. Planned as nodes after arg-eval-order. Parameter defaults are a separate debate, not started.
- 2026-11-07: async blocks and generator blocks parked (D88, `roadmaps/selfhost/debate/suspending-blocks/debate.md`). Rerun the debate when a program needs one.
- 2026-11-09, from effect-variable-values (D91): a function value with effect variables that passes through a generic type parameter still loses the variable's binding; the call through the value does not charge the bound effects. Out of scope for D91.
- 2026-11-09, from type-aliases: diagnostics decorate a type with its alias by type, not by what the source wrote: once `type Tok = Token` exists in a package, every message about `Token` shows `Tok (Token)`, and aliases of primitives are never shown. Showing the alias only where it was written needs the written name carried through the checker. Also: constructors through a generic alias (`Alias.Ctor`) are not available.
- 2026-11-11, from unsafe-ptr: an implementation's `alloc` and `io` are not limited to what its trait function declares, so a `Show.show` implementation can print and callers through the trait never see `io` (`unsafe` is enforced since batch-8). Enforcing it broke 21 cases, because pure trait functions such as `Show.show` have allocating implementations: closing it means adding `uses alloc` to such trait functions in the guide, SPEC, samples and `packages/traits`, and changing `effects_impl_through`. Needs a maintainer decision first. Also: SPEC could say in one line that creating an unsafe generator is allowed outside `unsafe`, and only running it is flagged.
- 2026-11-12, from checker-emitter-copies: storing a value that shares one parameter into a `mutable` parameter (`into.pairs = other.pairs` in `mergeInto`) leaves the caller's two arguments sharing after the call, and no rule checks it (1785 of the 1927 hidden copies came from it; that site now uses `copy(...)`). Treat such a store like a result without `from`. Listed in SPEC section 6 and D104.
- 2026-11-12, from checker-emitter-copies: a part taken out of a temporary copy of a heap enum (`let row = takeLeftRow(copy(tree)); row.cells[0] = 9`) compiles and copies (exit 103 under the debug copy check). D104 item 4 and a SPEC known gap. Needs a decision.
- 2026-11-12, from const-eval-design: a top-level literal table constant builds one store per element in its D61 getter, so clang takes 25 s at -O2 for 4096 elements. const-functions writes scalar arrays as `static const` plus memcpy; literal constants should use the same writer.
- 2026-11-12, from const-functions: the language service computes `@const` constants before the shared-write check (its cache keeps effect and shared-write errors apart); `check`, `build` and `emit` do it after. A compiler built at -O0 can overflow its stack before the evaluator limits. Arrays of strings in `@const` results are written one store per element (16,384 strings take clang 16 s at -O2).
- 2026-11-12, from the batch-11 bench: `narrac emit selfhost` on the batch-10 source takes 2.408G instructions with the batch-10 compiler and 2.453G with the batch-11 compiler (+1.9%). A per-commit bisect puts the one lasting step at array-patterns (about +30M, +1.3%), but builds of an unchanged tree vary by up to 2% from C code layout. Profile the pattern passes on code with no array patterns before calling it a regression.
- 2026-11-13, from the batch-12 review fixes: a function value's type cannot tell an async function from a plain function that returns `Async<T>`, so a plain function with `from` that returns a handle shares its argument through the handle when called by name, but only through the awaited value when called through a function value. Also, `await h` of a stored handle tracks no shared result (documented gap in D109 item 9); carrying `from` through stored handles needs the marker in the `Async<T>` type.
- 2026-11-14, from threads-channels: void type arguments work only through std/thread (`Thread<void>`) and std/async (`Async<void>`), each as a special case. A general rule (void locals, void fields, void pattern bindings) would replace both.
- 2026-11-14, from threads-shared: the callback of `Shared.update` gets a borrowed parameter, so changing the value needs `copy(...)` and every update copies it once. A real in-place update needs a way to give a callback ownership of its parameter (for example a `mutable` arrow parameter for `(mutable items) => Arrays.push(mutable items, x)`). Needs a language decision.
- 2026-11-14, from the field-shorthand review: the language service has no hover, go-to-definition or rename for fields yet. When rename lands, a field with `isShorthand` must be rewritten as `x: newName`, not `newName`.
- 2026-11-14, from slot-shared-writes: the std functions that store their argument (Cells, Shared, Channel, Atomic, Arenas) are listed in a compiler table, `selfhost/src/slotstores.nra`. Replace it with a parameter marker in std signatures once the seed compiles one.
- 2026-11-14, from the const-functions-std review: the compiler refuses float literals with more than about 15 significant digits or a large exponent (`0.49999999999999994`, `1e300`), although both are valid doubles. Check it on main with a failing test; a literal should be accepted when it reads back to a finite double.
- 2026-11-15, from wasi-runtime: the std functions WASI cannot back are listed in three tables in `selfhost/src/buildconditions.nra`, because `@target` takes one OS and builtins carry no attribute. A new such std function needs a row there. A target list on `@target` would replace the tables.
- 2026-11-15, from deps-fetch: `Process.run` cannot set environment variables, so deps-fetch runs git as `sh -c 'GIT_TERMINAL_PROMPT=0 exec git "$@"'`. A `Process.run` variant with an environment would remove the wrapper.
- 2026-11-16, from the batch-16 distribution fixes: on Windows the entry function's `args` come from `main(argc, argv)` in the ANSI code page, while `Env.args()` now reads UTF-8 from `CommandLineToArgvW`. The emitted `main` could take its list from the same runtime call under `_WIN32`; that changes the emitted C of every program, so every golden file.
- 2026-11-20, from lsp-hover-parity: a private function in a package with errors shows no `uses` line in the LSP hover or `narrac query hovers`, because the effect pass runs only on bodies without errors (golden `testdata/lsp/hover_errors` records it). Showing effects there means inferring them over bodies with errors. Needs a decision.
- 2026-11-20, from the lsp-hover-parity review: the `describeMember` call and member hover are still written twice in `selfhost/src/tools/query.nra` (`collectImportHovers` and `describeModuleUse`); the qualifier-token path for `Alias.Enum.Variant` looks up aliases by token text with no scope check (a local of that name there is already a type error). The `narrac decls` dump and the module hover still show the real module path, not the export key the importer wrote.
- 2026-11-20, from manifest-reference: the manifest loader skips unknown keys in `[package]` when the value is a string, array or inline table (a bare number is E0409), and skips unknown tables without checking their lines, so a typo such as `[dependecies]` passes silently. `[fmt]` errors have no code. Decide whether unknown keys and tables are errors.
- 2026-11-20, from guide-system-io: std has no sort (no `Arrays.sort` builtin, no sort in `std/src`), so the chapter 11 sample prints a folder's entry count instead of its sorted names. A first user will look for one.
- 2026-11-20, from guide-cell-and-state: the website highlighter fails the build on `Cell<Option<() => int>>` (a function type inside nested type arguments); the chapter uses a type alias to avoid it.
- 2026-11-20, from guide-c-interop: `const x = unsafe { ... }` is rejected (as SPEC says) with only `expected the end of the statement, found "{"`; a message that says `unsafe` blocks are statements would help. `return` inside an `unsafe` block works but SPEC does not say so. A package cannot compile C sources yet, so C interop samples can only call libc and libm.
- 2026-11-20, from guide-proofs: the E0985 hint for a `requires` clause with `||` tells the reader to check the name with an `if`, but checking the whole `||` does not prove it; a hint to check one side would be clearer.
- 2026-11-20, from const-function-effects: an array or `? :` that mixes a function without effects and one with effects (`[quiet, describe]`) still fails to infer a common type; writing the type works. An untyped const holding a private function with no `uses` list that allocates gets its effects only after the effect pass, so it still fails.
- 2026-11-20, from the std-registry-signatures review: the LSP has no signature help, and hover on a std builtin shows the checker's type of the call (`(int) => string uses alloc`), not the registry display data (`signature`, `parameterNames`, `note` on `StdFunc`). Signature help for builtin calls could print the same text as `narrac query interface std/<module>` and mark the parameter under the cursor.
- 2026-11-20, from std-gap-survey (`roadmaps/selfhost/std-gap-survey.md`): after the release, in survey order: `Process.run` options (stdin, environment, working folder, passed-through output), path `relative`/`normalize`/`resolve`/`stem`, folder walk and glob, calendar time and ISO 8601, hex and base64, SHA digests, `Maps.values`/`has`/`clear`, secure random bytes and UUID, HTTP client and server with URL and query strings, deque, priority queue and ordered map, open-file streaming and seek, file metadata, temporary files, logging, `Str.sliceFrom`/`charAt`/`nextChar` returning `Option` (SPEC section 5), async time operators, `Opaque<T>` (D122), signals, semver, thread cancellation, CSV and YAML, compression, SQLite and password hashing, big integers and locale formatting, UDP and DNS. Plan them as nodes after first-release.
- 2026-11-20, from the Crystal std comparison (orchestrator): after the release, also `std/log` (levels to stderr), a deque, `std/signal` (SIGINT/SIGTERM for clean shutdown), `std/semver` (the package manager compares versions), `Fs.info` (size, times) and `Fs.glob`/`Fs.walk`, and a CPU-count function in `std/thread`. Left to packages by design: HTTP, OpenSSL and crypto, bcrypt, OAuth, XML, YAML, INI, CSV, compression, big numbers, MIME; not a fit: macros (ECR), reflection, GC and weak references, symbols.
- 2026-11-20, from the async-thread-functions review: std module header comments in `std/src` cite SPEC sections and D-numbers (for example `std/thread`: "SPEC.md section 8, D111", "D111 item 2"), which the code-comment rule forbids. Clean them in one pass with the embedded std text regenerated.
- 2026-11-20, from batch-23: `programs/async_api_all_cancel.nra/debug` orders two 1 ms timers and failed under load near 25 (twice in batch-23 runs); it passes alone. Widen the gap between the timers or order by something other than wall time.
- 2026-11-20, from compiler-std-files: the dependency cache still shells out for `chmod -R a-w` and `mktemp -d`. `Fs.setReadOnly` (or `Fs.chmod`) and `Fs.createTempDir` would remove both; the git call stays until `Process.run` takes an environment.
- 2026-11-20, from compiler-std-sets: looping over a `Set` goes through `Sets.values`, which copies the members into an array, while `for ... of Maps.keys` loops over the map directly. Let `for ... of` take a `Set`, or lower `Sets.values` in a loop like `Maps.keys`.
- 2026-11-20, from compiler-std-sorts: the `std/char` classes take a `char`, so the lexer and `driver/manifest.nra`, which read bytes as `int`, keep their own checks. An `int` form of the classes would let them share one definition (the lexer still counts `_` as a letter).
- 2026-11-26, from batches 25 and 26: full `test.sh` runs under load failed once each in four worker runs, on `programs/async_api_all_cancel.nra/debug` (the 2026-11-20 entry above, still open), `programs/io_fs_more.nra/debug` (twice; maybe a shared temp folder between parallel runs), and once on a suite nobody captured. All passed alone and on rerun. Worth a `diagnose` node: the flakes cost a rerun of 4 to 7 minutes each time.
