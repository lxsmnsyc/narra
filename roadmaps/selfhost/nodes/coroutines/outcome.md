# Outcome: coroutines

## Built

`Coroutine<In, Out>`, `const input = yield value` and `Co.resume`, in the Go compiler and in `selfhost/` together. The two emit byte-identical C for the new samples.

- Type. Go `GeneratorType` gained `In Type` (nil for a `Generator<T>`; `types.go`), selfhost `Type.TGenerator` gained a fifth field `input` (`TVoid` for a generator). A coroutine type prints `Coroutine<In, Out>` plus its `uses` list, and carries effects, Binder, Origin and Bound exactly like a generator type (D78). `sameType`, `substitute`, `unify`, `containsOpen`, `templateEdges`, the C type id (`C_<In>_<Out>_<effects>`) and `expectType` compare or walk `In`. A coroutine and a generator never unify (`sameInput`).
- Syntax. `Coroutine<In, Out> uses ...` parses like `Generator`. `function*` accepts either as its return type (E0195 reworded: "must declare its return type as Generator<T> or Coroutine<In, Out>"). `Coroutine` with other than two type arguments is E0197. The statement `const x = yield v` / `let x = yield v` (no annotation, one name) parses to `YieldStmt` with a binding: Go `YieldStmt{Bind, Mutable, Name, NamePos, Local}`, selfhost `Stmt.YieldStmt(pos, value, delegate, binding)` with `ast.YieldBinding{id, isMutable, name, pos}` (the binding has a node id, like a `VarStmt`). `pos` is the `yield` token, the binding's pos is the `const`/`let` token. AST dump: `yield L:C [delegate] [let] [name=""]`. Types dump: the binding's `local` line comes before the value. `narrac fmt` prints `const name = yield value`.
- Checks (`check_stmt.go yieldStmt`, selfhost `stmts.nra checkYield`): the binding in a plain generator is E0293 ("the value of yield is available only in a coroutine; ..."), `yield*` in a coroutine is E0293, `for ... of` over a coroutine is E0293. The bound local has type `In`. A bare `yield v` in a coroutine is valid and drops the input.
- Emitter. A coroutine is the same state machine as a generator. The body reads the input at the label after the yield: `T x = *(T*)f->h.in` (retained, since the caller of resume owns the input). `narra_gen` got one field `const void* in` at the end of the header; plain generators write the same C as before (`(narra_gen){1, 0, resume, clone, drop}` leaves `in` null).
- Runtime (`runtime.h`, mirrored in `selfhost/src/runtimetext.nra`): `narra_co_next(narra_gen** p, void* out, const void* in, bool guard)` clones a shared generator, sets `in`, resumes, and returns 1 (value), 0 (done) or -1 (panicked, guarded calls only). `narra_panic` longjmps to the guard when `narra_panic_jmp` is set, after copying the message to `narra_panic_text`.
- std. `std/coroutine` is Narra source (`std/src/coroutine.nra`, text in `std_sources.go` and `selfhost/src/stdtext.nra`): `export enum Step<Out> derives Show, Equatable { Yielded(value), Done, Panicked(message) }`, `resumeGenerator<T, effect E>` and `resumeCoroutine<In, Out, effect E>`. The call `Co.resume(mutable g)` / `Co.resume(mutable g, input)` through an alias of `std/coroutine` is mapped to one of the two by argument count in `moduleCall` (`modules_check.go`; selfhost mirrors it in `calls.nra`). Their effects (`uses E, alloc`) make D78 work through the existing generator-parameter effect binding. The primitives are builtins of `std/internal/coroutine` (`std_coroutine.go`, `selfhost/src/stdlib.nra`, `stdcalls.nra` `checkCoResume`, `emitstd.nra` `emitCoResume`): `next`, `resume`, `panicked`, `panicMessage`.
- Panics (test builds only, `Emitter.tests`): the guard uses `setjmp`; a caught panic finishes the coroutine (`state = -1`), resets `narra_live` to its value before the resume and returns `Step.Panicked(message)` with the bare message. Memory the coroutine held is not freed.
- Tests: samples `compiler/testdata/coroutine.nra` (running total, a generator resumed until `Done`, zipping two generators), `coroutine_heap.nra` (string and array inputs and outputs, dropped unfinished, a never-resumed coroutine, a copy, an io coroutine), `coroutine_tests.nra` (a `test` file: `Panicked` from a division by zero and from `panic`, then `Done`); 11 error tests `compiler/testdata/errors/coroutine_*.nra`. `run_test.go` and `selfhost_emit_test.go` run the test blocks of files named `coroutine_tests*`.
- Docs: SPEC.md section 8, `DECISIONS.md` D79, `compiler/README.md` (Supported, Differences from the spec; the "not yet" line is gone).

Codes used: E0197 (Coroutine type arguments; import of `resume` by name), E0293 (four formats: binding outside a coroutine, `yield*`, `for ... of`, missing `mutable`). Decision D79. E0195's first format was reworded (code kept).

## Deviations

- Files outside the brief's lists, each small: `std/src/coroutine.nra` (new std source), `compiler/internal/narra/std_sources.go` and `selfhost/src/stdtext.nra` (generated by `TestStdSources`), `runtime.h` and `selfhost/src/runtimetext.nra` (generated), `modules_check.go` (the `Co.resume` mapping), `emit.go` (`Emitter.tests`), `run_test.go` and `selfhost_emit_test.go` (run the test blocks of `coroutine_tests*`), `selfhost/src/{ast,parser,astdump,idcheck,typesdump,trivia,fmt,stmts,resolve,exprs,generics,check,declsdump,cnames,types,calls,emitgenerators,emitstmts,emitstd,stdlib,stdcalls}.nra`, `compiler/testdata/errors/generator_return_*.nra` (reworded E0195; `generator_return_wrong.nra` used a coroutine as the wrong type, now `Array<int>`).
- Brief item 2 says `Co.resume` for generators and coroutines "change `g` in place". It does. It is one name for two source functions chosen by argument count, so `import { resume } from "std/coroutine"` is not supported (README, D79).
- `Co.resume` charges `alloc` besides the effects of `g` (the `Step` payload is allocated). A pure function resuming a pure generator must declare `uses alloc`.
- A missing `mutable` ("Co.resume changes the generator; ..." E0293) and effect errors ("through `Co.resume`") name `Co.resume`. A wrong input type reuses "expected int, found string". A generator passed with an input fails as "expected Coroutine<int, int> uses E, found Generator<int>" (recorded in D79). `import { resume }` gives E0197 with a hint.
- A panic inside a coroutine in a test build leaks what the coroutine held (D79). The leak counter is reset so the test's leak check stays quiet; AddressSanitizer's own leak detection (Linux) would see it.
- Selfhost uses `TVoid` as "no input" in `TGenerator`; a `Coroutine<void, T>` cannot be written in either compiler, so the encodings agree.

## Stubs left

- None.

## Gotchas

- Any new statement-level construct that declares a local needs a node id in the selfhost parser (`YieldBinding.id`) and a `local` line in both types dumps, in the order "local, then value".
- `YieldStmt.Pos` is the `yield` token, the binding position is the statement start. Comments attach to the statement start (`trivia.nra`).
- Test blocks run only for `tests.nra`, `std_test*` and now `coroutine_tests*` (`run_test.go`, `selfhost_emit_test.go`).
- `narra_co_next` is in `runtime.h` (not `Module.Runtime`), because `narra_gen` and `narra_panic` are there; every program carries it.
- A source std module can mix with builtins only through `std/internal/<name>`; the user-facing function is a Narra function. `moduleCall` is the only place that knows the name `resume`.

## Proposed learnings

- A new field on a shared Go struct or selfhost variant (`GeneratorType`, `TGenerator`) needs every walker updated: `containsTypeParam`, `substitute`, `unify`, `templateEdges`, `containsOpen`, `typeID`, `sameType` | a missing case silently drops the new field | compiler/internal/narra, selfhost/src | no
- Put a std function that needs a Narra enum in a source module and its primitives in `std/internal/` | builtins cannot name a module enum | compiler/internal/narra | no
