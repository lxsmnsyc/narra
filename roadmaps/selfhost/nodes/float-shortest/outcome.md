# Outcome: float-shortest

## Built

- `lstr_from_f64` and `lstr_from_f32` in `selfhost/runtime/runtime.h` find the shortest digits with `%.*e`, and the new `lstr_from_scientific` lays them out like JavaScript's `Number.prototype.toString`: plain digits up to 21 integer digits, `0.000001` and down to six leading zeros, otherwise `d.ddde+X` or `e-X` with no zero padding in the exponent (`1e+21`, `1.5e-7`).
- A whole number keeps `.0` (`20.0`, `100.0`, `10000000000.0`), as the existing goldens do (`3.0`). JavaScript would print `20`. SPEC does not say. Decision for the maintainer: drop the `.0` only if floats should print without it everywhere (Json output, `Show`).
- `nan`, `inf`, `-inf` and `-0.0` print as before.
- `Float.toString`, `F32.toString`, `Show`, `print` of floats, template holes and `emitconstvalues.writeFloat` all use these two functions. The seed was not regenerated, so the compiler's own const evaluator and C literal writer print floats the old way until the batch seed update (a C literal `2e+01` is still valid C).
- `selfhost/src/runtimecore.nra` regenerated by `sh scripts/test.sh --suite generated --update`.
- `testdata/float_shortest.nra` and `.out`.

## Proof

- base: feat/batch-15 6c616a46, `narrac run -release testdata/float_shortest.nra`: `20.0` prints `2e+01`, `100.0` prints `1e+02`, `1e-7` prints `1e-07`, `F32.toString(20.0)` prints `2e+01`.
- branch: same command: `20.0`, `100.0`, `1e-7`, `1e+21`, `1.5e-7`, `-0.0`, `nan`, `inf`, `-inf`, `1.7976931348623157e+308`, `5e-324`, f32 `20.0` and `3.4028235e+38`; each finite f64 parsed back with `Json.parse` equals the input.

## Deviations

- The brief says `Float.parse` and `Float.max`; neither exists. The sample reads back with `Json.parse` (`std/internal/float` is not importable from a sample) and writes the maximum as a literal.
- Goldens changed: `testdata/f32.out` (`1e+10` is `10000000000.0`), `json_floats.out` (`1.2345678901234567e+19` is `12345678901234567000.0`), `simd/lanes.out`, `simd/operators.out`, `traits.out` (`1e+01` is `10.0`, `2e+01` is `20.0`, `-1e+01` is `-10.0`). `--update` does not rewrite `.out` files of the programs suite, so they were rewritten from a release run.
