# Errors

Every diagnostic code of `narrac`, with its message and, where there is one, its explanation. `narrac explain CODE` prints the same text. In a message, `%s`, `%q`, `%d`, `%c` and `%v` mark a name, text, number or character that the compiler fills in. A code with several messages is reported in several situations.

This page is generated by `scripts/errors/generate.nra` from `narrac explain --list --json`. Do not edit it.

## E0000 to E0099: Lexer and parser

#### E0001

```text
unterminated block comment
```

A block comment starts with `/*` and must end with `*/`. The file ended first.

Fix: add `*/` where the comment ends.

#### E0002

```text
a character literal holds exactly one character; use double quotes for strings
```

Single quotes write a `char`, which holds exactly one character. Text of any other length is a string.

Fix: use double quotes.

Example: `'ab'` becomes `"ab"`.

#### E0003

```text
semicolons are not used; end the statement with a line break
```

Narra has no semicolons. A line break ends a statement.

Fix: delete the `;`.

Example: `return 0;` becomes `return 0`.

#### E0004

```text
unexpected character %q
```

This character cannot start any token, such as `\` outside a string or a symbol Narra does not use.

Fix: delete the character, or put it inside a string or a comment.

#### E0005

```text
unterminated escape
```

A backslash in a string or character literal starts an escape, and the file ended right after it.

Fix: finish the escape, for example `\n`, and close the literal.

#### E0006

```text
expected { after \u
```

A `\u` escape writes its code point in braces.

Fix: `"\u0041"` becomes `"\u{41}"`.

#### E0007

```text
invalid \u escape
```

A `\u{...}` escape holds only hexadecimal digits and ends with `}`.

Fix: write the code point in hexadecimal, as in `"\u{1F600}"`.

#### E0008

```text
unknown escape \%c
```

The character after the backslash is not an escape. The escapes are \`\\n\`, \`\\t\`, \`\\r\`, \`\\0\`, \`\\\\\`, \`\\"\`, \`\\'\`, \`\` \\\` \`\`, \`\\$\` and \`\\u{...}\`.

Fix: use one of these escapes, or write `\\` for a backslash.

#### E0009

```text
unterminated literal
```

A string or character literal must close on the line where it starts.

Fix: add the closing quote. For text over several lines, use `\n` or a template string.

#### E0010

```text
unterminated template string
```

A template string starts with a backtick and must end with one. The file ended first.

Fix: add the closing backtick, and check that every `${` has its `}`.

#### E0011

```text
expected %q, found %s
```

The parser needs a particular symbol here, such as a closing parenthesis or brace, and found another token.

Fix: add the symbol the message names, or remove the extra token before it.

Example: `(1 + 2` becomes `(1 + 2)`.

#### E0012

```text
expected a name, found %s
```

A name is needed here, for example after `const` or `function`. A keyword is not a name.

Fix: write a name, or rename a name that is a keyword.

Example: `const if = 1` becomes `const cond = 1`.

#### E0013

```text
expected the end of the statement, found %s
```

A statement ends at a line break or a `}`. Another token follows the statement on the same line.

Fix: put the next statement on its own line.

Example: `const x = 1 const y = 2` becomes two lines.

#### E0014

```text
use `import * as Name from "path"` or `import { a, b } from "path"`; there are no default imports
```

Imports name the module as a namespace or list the names. There is no default import.

Fix: `import X from "std/int"` becomes `import * as X from "std/int"`.

#### E0015

```text
expected a module path string
```

An import names its module with a string literal after `from`.

Fix: `from std/array` becomes `from "std/array"`.

#### E0016

```text
implement blocks cannot be exported; export the trait and the type
```

An implement block cannot be exported. Other modules use it through the trait and the type.

Fix: remove `export` from the implement block, and export the trait and the type.

#### E0017

```text
tests cannot be exported
```

A test is run by the test runner and is never called from code, so it cannot be exported.

Fix: remove `export` before `test`.

#### E0018

```text
expected the test name as a string
```

A test is named with a string literal.

Fix: `test parsesInts { ... }` becomes `test "parses ints" { ... }`.

#### E0019

```text
expected a declaration, found %s
```

The top level of a file holds only declarations, such as imports, functions, constants, types, traits, implement blocks and tests. A statement such as `let` or a call belongs inside a function.

Fix: move the statement into a function, or declare a `const` instead of a `let`.

#### E0020

```text
there is no `T[]` array type; write `Array<T>`
```

Arrays are written `Array<T>`, not `T[]`.

Fix: `xs: int[]` becomes `xs: Array<int>`.

#### E0023

```text
a trait has no type parameters; use Self for the implementing type
```

A trait takes no type parameters. Inside the trait, `Self` stands for the type that implements it.

Fix: `trait Describe<T> { function describe(value: T): string }` becomes `trait Describe { function describe(value: Self): string }`.

#### E0024

```text
a trait has functions only, found %s
```

A trait body holds function signatures only. Fields, constants and other declarations cannot go in it.

Fix: move the item out of the trait, or turn it into a function signature.

#### E0025

```text
trait functions have no default implementation; remove the body
```

A trait function is a signature without a body. Each implement block writes the body for its type.

Fix: delete the body in the trait, and write it in each `implement` block.

#### E0026

```text
functions in an implement block cannot be exported
```

Functions in an implement block are called through the trait, so they take no `export`.

Fix: remove `export`, and export the trait instead.

#### E0027

```text
an implement block has functions only, found %s
```

An implement block holds function definitions only.

Fix: move constants and other declarations out of the block.

#### E0028

```text
arrow function parameters cannot be mutable
```

An arrow function cannot take a `mutable` parameter.

Fix: remove `mutable`, or write a named function for the code that changes the parameter.

#### E0029

```text
unexpected end of file inside a block
```

A block opened with `{` was not closed before the end of the file.

Fix: add the missing `}`.

#### E0030

```text
write `for (const item of items)`
write `for await (const item of stream)`
```

A `for ... of` loop declares its item, as in `for (const item of items)`. A `for await` loop declares it with `const`.

Fix: `for (item of items)` becomes `for (const item of items)`.

#### E0031

```text
use `of`; `for ... in` is not part of the language
```

A `for` loop goes over its items with `of`. There is no `for ... in`.

Fix: `for (const item in items)` becomes `for (const item of items)`. For the keys of a map, loop over `Map.keys`.

#### E0032

```text
a block must belong to a statement such as if or while
```

A `{` at the start of a statement opens a block, and a block must belong to a statement such as `if`, `while` or `for`.

Fix: remove the braces, or put the block under the statement it belongs to.

#### E0033

```text
use `%s`; there is no strict equality operator
```

There is no strict equality. `==` already compares without conversions.

Fix: `===` becomes `==`, and `!==` becomes `!=`.

#### E0035

```text
a map key that is not a literal is written [key]: value
```

In a `Map { ... }` literal, a key that is a literal is written as it is. Any other key, such as a name, goes in brackets.

Fix: `Map { k: 1 }` becomes `Map { [k]: 1 }`, or `Map { "k": 1 }` for the text.

#### E0036

```text
a struct literal has at most one spread, and it comes first
```

A struct literal may copy one other value with `...`, and the spread comes before the fields it changes.

Fix: `Point { x: 3, ...base }` becomes `Point { ...base, x: 3 }`.

#### E0038

```text
there is no %s; use `None` with an `Option` type
```

There is no `null` or `undefined`. A value that may be missing has type `Option<T>`.

Fix: `null` becomes `None`.

#### E0039

```text
expected an expression, found %s
```

An expression is needed here, such as a value, a name or a call, and this token cannot start one.

Fix: write the missing value, or remove the extra token.

#### E0040

```text
unterminated ${ in template string
```

A `${` in a template string opens an expression that must close with `}` inside the string.

Fix: add the `}` that closes the expression.

#### E0041

```text
in template string: %v
```

The expression inside `${...}` in a template string has an error in its characters. The text after the colon gives that error.

Fix: correct the expression inside `${...}`.

#### E0042

```text
expected a number after - in a pattern, found %s
```

In a pattern, `-` may only start a negative number.

Fix: write the number right after the `-`, as in `-1 => ...`.

#### E0043

```text
only an exported type can be opaque; write `export opaque`
```

`opaque` hides a type's contents from other modules, so it applies only to an exported type.

Fix: write `export opaque struct`, or remove `opaque`.

#### E0044

```text
expected `type` after `distinct`, found %s
```

A distinct type is declared with the two words `distinct type`.

Fix: `distinct UserId = int` becomes `distinct type UserId = int`.

#### E0045

```text
expected `struct` or `distinct type` after `opaque`, found %s
```

`opaque` applies only to a struct or a distinct type.

Fix: write `export opaque struct` or `export opaque distinct type`, or remove `opaque`.

#### E0046

```text
a generator must be a top-level function; declare `function*` at module level
`yield` needs a value: write `yield value`, or `yield* generator`
`yield` is a statement, so it cannot be part of an expression
```

A generator, declared with `function*`, must be a top-level function, not a function in a trait or an implement block. Inside it, `yield` always takes a value and is a statement of its own.

Fix: move the generator to the module level, write `yield value`, or put the `yield` on its own line.

#### E0047

```text
`from` needs the name of a parameter, found %s
```

`from` after a result type names the parameter that the result shares.

Fix: write a parameter name after `from`, as in `function first(items: Array<Item>): Item from items`, or remove `from`.

## E0100 to E0199: Declarations and types

#### E0100

```text
unknown module %q (this compiler supports %s)
```

The import path names no module this compiler has. The message lists the modules it supports.

Fix: correct the path, for example `"std/arrays"` becomes `"std/array"`.

#### E0101

```text
module %q has no export %q
```

The module exists, but it exports no name like this one.

Fix: check the spelling, or add `export` to the declaration in that module.

#### E0102

```text
function %q is declared twice
```

Two functions in one module have the same name, counting imported functions. Each function name is used once.

Fix: rename one of the functions, or import the other one under a new name with `as`.

#### E0103

```text
%q is already declared in this function; shadowing is not allowed
```

A name cannot be declared again while it is still in scope in the same function, even in an inner block. Parameters count, and `_` is exempt.

Fix: pick a new name, or assign to the existing `let` with `=`.

#### E0104

```text
type %q is declared twice
```

Two types in one module have the same name. Structs, enums, distinct types, aliases and imported types share one set of names.

Fix: rename one of the types.

#### E0105

```text
field %q is declared twice
```

A struct declares two fields with the same name.

Fix: rename or delete one of the fields.

#### E0106

```text
a field default must be a constant
```

A field default must be a constant value, such as a literal or a top-level `const`. A function call is not allowed.

Fix: use a constant value, or set the field where the struct is built.

#### E0108

```text
generic type %s contains %s, so each instance needs a larger one without end; every instance needs its own C type, so polymorphic recursion is not supported (use the same type arguments, or an enum or Box)
```

A generic type refers to itself with larger type arguments, as in `struct Nested<T> { inner: Option<Nested<Array<T>>> }`. Each instance needs its own C type, so the instances would never end.

Fix: refer to the type with its own type arguments, as in `Nested<T>`, or hold the value in an enum or a `Box`.

#### E0109

```text
type %s contains itself; put the recursive field in an enum, Box or array
```

A struct that holds itself directly would have no finite size.

Fix: put the field in an enum, a `Box` or an array.

Example: `next: Node` becomes `next: Option<Node>`.

#### E0110

```text
Box takes one type argument
```

`Box<T>` takes exactly one type argument, the type of the boxed value.

Fix: write one type argument, as in `Box<Node>`.

#### E0111

```text
Map takes two type arguments
```

`Map` takes two type arguments, the key type and the value type.

Fix: write both, as in `Map<string, int>`.

#### E0112

```text
Array takes one type argument
```

`Array` takes exactly one type argument, the element type.

Fix: write one type argument, as in `Array<int>`.

#### E0113

```text
there is no `number`; use `int` or `f64`
```

Narra has no `number` type. Integers and floats are separate types.

Fix: use `int` for whole numbers or `f64` for floats.

#### E0114

```text
use `bool`
```

The boolean type is `bool`.

Fix: `boolean` becomes `bool`.

#### E0115

```text
%s takes %d type arguments
```

A generic type takes one type argument for each of its type parameters.

Fix: write all of them. For `struct Pair<A, B>`, `Pair<int>` becomes `Pair<int, string>`.

#### E0116

```text
there is no Tuple type; write a tuple type as #[A, B]
```

A tuple type is written `#[A, B]`. There is no `Tuple` type name.

Fix: `Tuple<int, string>` becomes `#[int, string]`.

#### E0117

```text
type %s is not generic
```

This type has no type parameters, so it takes no type arguments.

Fix: remove the `<...>` after the type name.

#### E0118

```text
unknown type %q
```

No type with this name is declared or imported here.

Fix: check the spelling, declare the type, or import it from its module.

#### E0119

```text
expected %s, found %s
```

The value has a different type from the one this place needs. Types are never converted on their own, so an `int` is not an `f64` and a distinct type is not its base type.

Fix: pass a value of the expected type, or convert it with a function such as `Float.from`.

#### E0120

```text
distinct type %s cannot be defined in terms of itself
```

The base of a distinct type must be a type that is already known. It cannot be the type itself or a distinct type declared after it.

Fix: declare the base type first, or use a type such as `int` as the base.

#### E0190

```text
constant %q is declared twice
```

A top-level constant has the same name as another constant, a function, a type or an import in the module.

Fix: rename one of them.

#### E0191

```text
constant %q is defined in terms of itself
```

A constant's value refers back to the constant, directly or through other constants.

Fix: write a value without the cycle for one of the constants.

#### E0192

```text
constant %q cannot call function %q; a top-level constant holds literals, constructors, structs, arrays, function names and other constants
```

A top-level constant holds only literals, constructors, struct and array literals, function names and other constants. It cannot call a function.

Fix: write the value out, or compute it inside a function.

#### E0193

```text
constant %q cannot use %s; a top-level constant holds literals, constructors, structs, arrays, function names and other constants
```

A top-level constant holds only literals, constructors, struct and array literals, function names and other constants. An element read, a closure, a `match`, an `is` test, a block expression and `await` are not allowed in it.

Fix: write the value out, or compute it inside a function.

#### E0194

```text
enum %s declares the constructor %q twice
```

Each constructor of an enum needs its own name.

Fix: rename or delete one of the two constructors.

#### E0195

```text
generator %s must declare its return type as Generator<T> or Coroutine<In, Out>
the effects of generator %s are written on its return type, as in `Generator<T> uses io`
Generator takes one type argument
```

A generator, declared with `function*`, returns `Generator<T>`, or `Coroutine<In, Out>` when it takes an input on each resume. Its effects go on that return type.

Fix: write the return type, as in `function* count(): Generator<int> uses io`.

#### E0196

```text
generator %s cannot take a mutable parameter %q; a generator is a value that is resumed later
```

The body of a generator runs later, each time the generator is resumed. A `mutable` parameter would then refer to a caller's variable after the call has returned.

Fix: take the parameter without `mutable`.

#### E0197

```text
Coroutine takes two type arguments
%s is not an export you can import by name; write `import * as Co from "std/coroutine"` and call Co.resume
```

`Coroutine<In, Out>` takes two type arguments, the input type and the output type. The functions of `std/coroutine` are called through the module and are not imported by name.

Fix: write both type arguments, and use `import * as Co from "std/coroutine"` with `Co.resume`.

## E0200 to E0299: Expressions and statements

#### E0200

```text
integer literal %s does not fit in int
```

An integer literal must fit in `int`, a 64-bit signed integer.

Fix: use a smaller value, or a sized type such as `u64` when the value fits in it.

#### E0201

```text
a template string part must be a string, found %s; convert it, for example with Int.toString
```

Each `${...}` part of a template string must be a string. Numbers and other values are not converted on their own.

Fix: convert the part, as in `${Int.toString(count)}`.

#### E0202

```text
a module is not a value
```

A module imported with `import * as` is a name for its functions and types, not a value.

Fix: use a name from the module, as in `Arrays.length(xs)`.

#### E0203

```text
unknown name %q
```

No variable, constant, parameter or function with this name is in scope here.

Fix: check the spelling, declare the name, or import it.

#### E0204

```text
struct %s has no field %q
```

The struct has no field with this name. This applies to field reads, struct literals and patterns.

Fix: check the spelling against the struct declaration.

#### E0205

```text
this %s may hold any of its variants; check it with `is` or `match` before reading %q
```

An enum value may hold any of its constructors, and the field belongs to only some of them. The value must be narrowed to one constructor first.

Fix: test it with `is` or `match`, as in `if (shape is Shape.Circle(_)) { return shape.radius }`.

#### E0206

```text
%s has no field %q
```

The value is narrowed to this enum constructor, and the constructor has no field with this name.

Fix: check the field names of the constructor in the enum declaration.

#### E0207

```text
%s has one field, value
```

A `Box<T>` has one field, `value`.

Fix: read the boxed value with `.value`.

#### E0208

```text
there is no .length; use Array.length(x) or Str.length(x)
```

Narra has no `.length` field. Length is a function of the module for the type.

Fix: `xs.length` becomes `Arrays.length(xs)` with `import * as Arrays from "std/array"`. A string uses the `length` function of `std/string`.

#### E0209

```text
%s has no fields
```

This type has no fields to read with `.`, for example `int` or `string`.

Fix: remove the field read, or call a module function on the value.

#### E0210

```text
only arrays can be indexed, found %s
```

Only arrays, maps, fixed arrays, vectors and tuples can be indexed with `[...]`.

Fix: index a value of one of those types, or read a field of the value.

#### E0211

```text
- needs a number, found %s
```

Unary `-` negates a number, and the operand is not a number.

Fix: negate a number, or use `!` for a `bool`.

#### E0212

```text
the type of [] is unknown; add a type annotation
```

An empty array literal `[]` gives no element type, and nothing around it names one.

Fix: annotate the variable, as in `let xs: Array<int> = []`.

#### E0213

```text
unsupported expression
```

#### E0214

```text
cannot compare %s with %s
```

`==` and `!=` compare two values of the same type. Values of different types are never equal and are not converted.

Fix: convert one side so that both sides have the same type.

#### E0215

```text
cannot order %s and %s
```

`<`, `<=`, `>` and `>=` need two values of the same type, and that type must be a number, `char`, `string` or `bytes`.

Fix: compare values of one of those types, for example a field of the value.

#### E0216

```text
strings are joined with a template string, not +
```

Strings are joined with a template string.

Fix: `a + "x" + b` becomes `` `${a}x${b}` ``. The fix is offered when every operand is a string name or literal.

#### E0217

```text
%s needs two numbers of the same type, found %s and %s
```

Arithmetic needs two numbers of the same type. An `int` and an `f64` are not mixed, and neither side is converted on its own.

Fix: convert one side, as in `Float.from(count) * 0.5`.

#### E0218

```text
%s needs two integers, found %s and %s
```

`&`, `|`, `^`, `<<` and `>>` need two integers of the same type.

Fix: use integer operands of one type, and convert a float or a different integer type first.

#### E0219

```text
unknown operator %s
```

#### E0220

```text
cannot tell type parameter %s of %s here; add a type annotation
cannot tell constant parameter %s of %s here; write it, as in %s<3>(...)
cannot tell constant parameter %s of %s here; write it, as in %s<3> { ... }
cannot tell constant parameter %s of %s here; a function with a constant parameter cannot be a value
```

The compiler cannot work out a type parameter or constant parameter of a generic function or type from the arguments or from the expected type.

Fix: write the type arguments, as in `none<int>()`, or annotate the variable that receives the value.

#### E0221

```text
%q is not a struct
```

A literal `Name { ... }` builds a struct, and this name is not a struct type.

Fix: use the name of a struct, or build the value with a constructor or a function of its type.

#### E0222

```text
the struct type is unknown here; write `TypeName { ... }`
```

A struct literal without a type name works only where the expected type is a struct, such as an annotated variable or a parameter.

Fix: write the type name, as in `Point { x: 1, y: 2 }`.

#### E0223

```text
field %q is given twice
```

A struct literal gives the same field twice.

Fix: delete one of the two.

#### E0224

```text
missing field %q of %s
```

A struct literal must give every field that has no default.

Fix: add the missing field, or give the field a default in the struct declaration.

#### E0225

```text
this expression has no value
```

The expression gives no value, for example a call to a function that returns nothing, so it cannot be stored.

Fix: call the function as a statement of its own, or make the function return a value.

#### E0226

```text
only variables, fields and array elements can be assigned
```

Only a variable, a field or an array element can be assigned. A map entry takes `=` but not a compound assignment such as `+=`.

Fix: assign to a variable, field or element. For a map entry, compute the new value and write `m[key] = value`.

#### E0227

```text
%q is constant; declare it with `let` to change it
parameter %q is read-only; declare it as `mutable %s` to change the caller's value, or copy it first with `copy(%s)`
```

A `const` cannot be reassigned, and a parameter is read-only unless it is declared `mutable`.

Fix: declare the variable with `let`. For a parameter, declare it as `mutable name` to change the caller's value, or change a `copy(name)`.

#### E0228

```text
this expression does nothing
```

This expression on its own line has no effect, such as `x + 1` or a bare name, so its value would be lost.

Fix: assign the value, return it, or delete the line.

#### E0229

```text
this call returns a Result that is not checked; handle it, or discard it with `const _ = ...`
```

This call returns a `Result`, and the code ignores it, so a failure would go unnoticed.

Fix: handle the `Result` with `match` or `is`, or discard it on purpose with `const _ = ...`.

#### E0230

```text
this function must return a %s
```

The function declares a result type, so every `return` gives a value of that type.

Fix: write the value after `return`.

#### E0231

```text
this function returns nothing
```

The function declares no result type, so `return` cannot give a value.

Fix: add a result type, as in `function f(): int`, or write `return` alone.

#### E0232

```text
for ... of needs a Range, an Array, a Generator, Str.chars, Array.entries, Map.keys or Map.entries, found %s
```

`for ... of` goes over a Range, an Array, a Generator, `Str.chars`, `Array.entries`, `Map.keys` or `Map.entries`. Other values cannot be looped over directly.

Fix: loop over one of these, for example `Map.keys` for the keys of a map.

#### E0233

```text
break must be inside a loop
```

`break` leaves a loop, so it must be inside one.

Fix: delete the `break`, or use `return` to leave the function.

#### E0234

```text
continue must be inside a loop
```

`continue` goes to the next turn of a loop, so it must be inside one.

Fix: delete the `continue`, or use `return` to leave the function.

#### E0235

```text
cannot read field %q of %s: it is an opaque struct of module %q
```

An opaque struct hides its fields from other modules. Only the module that declares it can read them.

Fix: call a function of that module that returns the field.

#### E0236

```text
cannot spread %s: it is an opaque struct of module %q
```

Spreading a struct with `...` reads all of its fields, and an opaque struct hides its fields outside its module.

Fix: build the value with the functions of the declaring module.

#### E0237

```text
the type arguments make %s, but the expected type is %s
```

The type arguments written on a struct or map literal make a type that differs from the type expected here.

Fix: change the type arguments to match, or delete them and let the expected type decide.

#### E0290

```text
constant %q cannot be changed; copy it into a local first with `copy(%s)`
constant %q cannot be changed; copy it into a local first, as in `let %s = %s`
```

A top-level constant cannot be changed, not even one field or element of it.

Fix: copy it into a local first, as in `let table = copy(TABLE)`, and change the local.

#### E0291

```text
%s cannot be used %s; it is valid only directly in a function* body
yield* needs a %s, found %s
```

`yield` and `yield*` work only directly in a `function*` body, not inside an arrow function or a block expression. `yield*` takes a generator with the same element type.

Fix: move the `yield` into the generator body, or pass `yield*` a generator of the right type.

#### E0292

```text
return in a generator takes no value; yield the value, then return
```

A `return` in a generator ends it and takes no value. Values leave a generator through `yield`.

Fix: `return value` becomes `yield value` followed by `return`.

#### E0293

```text
the value of yield is available only in a coroutine; declare %s as Coroutine<In, Out>, or write `yield value` without a name
yield* is not valid in a coroutine; a delegated generator has no input to receive
Co.resume changes the generator; write Co.resume(mutable g) or Co.send(mutable g, input)
for ... of cannot iterate a coroutine, which needs an input on each resume; call Co.send(mutable g, input)
```

A coroutine is a generator that takes an input on each resume. Only a coroutine can receive a value from `yield`. A coroutine cannot use `yield*`, and `for ... of` cannot loop over it. Resuming changes the generator, so it is passed as `mutable`.

Fix: follow the message, for example `Co.resume(g)` becomes `Co.resume(mutable g)`.

#### E0294

```text
integer literal %s does not fit in %s
```

An integer literal must fit in the sized type it has here, for example 0 to 255 for `u8`.

Fix: use a value in range, or a larger type.

#### E0295

```text
%s needs two integers of the same type, found %s and %s; convert one side with %s.from, %s.tryFrom or %s.wrap
%s needs two floats of the same type, found %s and %s; convert one side with F32.from or Float.from
```

Integers of different sizes are not mixed in one operation, and neither are `f32` and `f64`. Neither side is converted on its own.

Fix: convert one side with the function the message names.

#### E0296

```text
- cannot negate %s, which is unsigned
```

An unsigned integer or vector has no negative values, so unary `-` is not allowed on it.

Fix: use a signed type, or subtract the value from another one.

#### E0297

```text
float literal %s does not fit in f32
```

A float literal of type `f32` must be finite in `f32`, and this value is too large.

Fix: use a smaller value, or the type `f64`.

## E0300 to E0399: Calls and constructors

#### E0300

```text
constructor %s is ambiguous: %s all have it; write %s.%s
```

#### E0301

```text
%s takes %d fields, found %d
```

An enum constructor takes one value for each of its fields. The call or pattern gives a different number.

Fix: pass one value per field. For `Rect(width: f64, height: f64)`, write `Shape.Rect(2.0, 3.0)`.

#### E0302

```text
cannot tell the type of %s here; add a type annotation
```

The compiler cannot work out the type arguments of a generic constructor or function here. A bare `None` with no expected type is one case.

Fix: annotate the variable, as in `const first: Option<int> = None`.

#### E0303

```text
constructor fields are not mutable
```

A constructor stores its field values, so a constructor argument cannot be `mutable`.

Fix: remove `mutable` before the argument.

#### E0304

```text
enum %s has no constructor %q
```

The enum has no constructor with this name.

Fix: check the spelling against the enum declaration.

#### E0305

```text
unknown function %q
```

No function with this name is declared or imported in this module.

Fix: check the spelling, declare the function, or import it.

#### E0306

```text
module %q has no function %q
```

The module has no function with this name.

#### E0307

```text
unknown function %s
```

#### E0308

```text
unknown module %q; import it first, for example `import * as %s from "std/..."`
```

The name before the `.` is not an imported module.

#### E0309

```text
there are no method calls; call a module function such as Module.%s(value, ...) (value has type %s)
```

Narra has no method calls. Functions belong to modules.

Fix: `xs.push(v)` becomes `Arrays.push(mutable xs, v)`.

#### E0310

```text
too many instances of generic functions; %s may recurse with ever larger types
```

Each use of a generic function with new type arguments makes a new copy of it. This function calls itself with ever larger type arguments, so the copies would never end.

#### E0311

```text
%s takes %d arguments, found %d
```

A built-in function was called with a different number of arguments from the number it takes.

Fix: pass the number of arguments the message gives.

#### E0312

```text
%s changes its argument; write `mutable` before it
```

This built-in function changes its argument, so the call marks the argument with `mutable`.

Fix: write `mutable` before the argument.

#### E0313

```text
%s does not change its arguments; remove `mutable`
```

This built-in function does not change its arguments, so no argument takes `mutable`.

Fix: remove `mutable`.

#### E0314

```text
a mutable argument must be a variable, a field or an element
```

A `mutable` argument is changed in place, so it must be a variable, a field or an array element. A literal or a call result is not.

Fix: store the value in a `let` variable first, and pass that variable.

#### E0315

```text
parameter %q is read-only; declare it as `mutable %s` to pass it on as mutable
```

A parameter without `mutable` is read-only, so the function cannot pass it on as `mutable`.

Fix: declare the parameter as `mutable name`, or pass a copy.

#### E0316

```text
this call passes %d arguments, the function takes %d
this call passes %d arguments, the function takes %d to %d
```

The call passes a different number of arguments from the number the function takes. A range such as `1 to 3` means the last parameters have defaults.

Fix: pass one argument for each parameter without a default.

#### E0317

```text
parameter %q is mutable; write `mutable` before the argument
```

This parameter is declared `mutable`, so the call marks its argument with `mutable` too.

Fix: write `mutable` before the argument.

#### E0318

```text
parameter %q is not mutable; remove `mutable`
```

This parameter is not declared `mutable`, so its argument takes no `mutable`.

Fix: remove `mutable`, or declare the parameter `mutable` if the function changes it.

#### E0319

```text
%q is passed as mutable in this call, so no other argument can use it
```

A value passed as `mutable` can change during the call, so no other argument of the same call may use it.

Fix: read the value into a local first, then pass the local.

Example: `set(mutable xs, xs[0])` becomes `const first = xs[0]` and `set(mutable xs, first)`.

#### E0320

```text
cannot build %s with a literal: it is an opaque struct of module %q; use that module's functions
```

Only the module that declares an opaque struct can build it with a literal.

Fix: call a function of that module that creates the value.

#### E0321

```text
%s.%s is not available outside module %q: %s is an opaque distinct type
```

An opaque distinct type keeps `from`, and `check` for a refined type, to its own module. Only that module can create values.

Fix: call a function of the declaring module that creates the value.

#### E0322

```text
%s has no function %q; a distinct type has %s
```

A distinct type has only its generated functions, `from` and the unwrap function such as `toInt`, plus `check` when it is refined.

Fix: call one of those functions, or a function of the declaring module.

#### E0323

```text
constructor %s needs its enum; write %s.%s
```

A constructor of a user enum is always written with its enum, in expressions and in patterns. Some, None, Ok and Err stay bare.

Fix: `Circle(1.0)` becomes `Shape.Circle(1.0)`.

#### E0324

```text
constructor %s needs its enum; %s all have it, for example %s.%s
```

Two enums visible here have this constructor, so the compiler cannot pick one.

Fix: write Enum.Name for the one you mean, for example `Level.Low`.

#### E0325

```text
expected %s, found %s; the argument does not fit the generic parameter
```

A generic function was called with an argument that cannot match its parameter, for example an int where Option\<T\> is expected.

Fix: pass a value of the shape the parameter asks for.

#### E0326

```text
%s is not a generic function, so it takes no type arguments%s
```

Explicit type arguments, as in f\<int\>(x), only go with a generic function or a trait function.

Fix: delete the type arguments, or call a generic function.

#### E0327

```text
%s takes %d type arguments, found %d
```

A generic function takes one type argument per type parameter, all or none. A trait call takes one, the type that Self stands for.

Fix: write every type argument, or none and let the arguments decide.

#### E0328

```text
%s has no parameter %q
%s has no parameter %q; did you mean %q?
```

The named argument matches no parameter of the function.

Fix: use the parameter's name. When the message suggests a close name, the fix renames the argument.

#### E0329

```text
parameter %q is passed twice
```

The call gives the same parameter twice, by position and by name, or by name twice.

Fix: pass each parameter once.

#### E0330

```text
a positional argument cannot follow a named one; name it, or move it before the named arguments
```

Positional arguments come first. After a named argument, every argument is named.

Fix: name the argument, or move it before the named arguments.

#### E0331

```text
this call passes no argument for parameter %q
```

Each parameter without a default needs an argument.

Fix: pass the argument, by position or by name.

#### E0332

```text
%s has no parameter names; pass its arguments by position
```

Only a declared function takes named arguments. A function value, a built-in function, a constructor and the function of a distinct type take arguments by position.

Fix: remove the names, and pass the arguments in order.

## E0400 to E0499: Modules, packages and narra.toml

#### E0400

```text
the entry function must be `export function %s(args: Array<string>): int`
```

The entry function starts the program. It takes the command-line arguments as one `Array<string>` and returns the exit code as an `int`. It may be `async`.

Fix: write it as `export function run(args: Array<string>): int`.

#### E0401

```text
unknown module %q; package %s has no file src/%s.nra
```

An import path that starts with the package name points at a file under `src/`. The path `app/util` is the file `src/util.nra`, and that file does not exist.

Fix: correct the path, or create the file.

#### E0402

```text
%q is not exported by module %q; add `export` to its declaration
```

Other modules can use only the declarations marked `export`.

Fix: add `export` before the declaration, or stop importing the name.

#### E0403

```text
unknown module %q in type %s; import it with `import * as %s from "..."`
```

A type written as `Name.Type` must start with the alias of an imported module. No import in this file has that alias.

Fix: import the module with `import * as Name from "..."`, or correct the alias.

#### E0404

```text
%s is not a type
```

The module exports this name, but it is a function or a constant. Only a struct, enum, distinct type or type alias can be used as a type.

Fix: use the name of a type that the module exports.

#### E0405

```text
expected `]]`
```

In `narra.toml`, a line that starts with `[[` opens an array of tables, such as `[[binary]]`, and must end with `]]`.

Fix: end the line with `]]`.

#### E0406

```text
expected `]`
```

In `narra.toml`, a line that starts with `[` names a table, such as `[package]`, and must end with `]`.

Fix: end the line with `]`.

#### E0408

```text
expected `key = value`
```

In a known table of `narra.toml`, every line that is not a table header or a comment must be `key = value`.

Fix: add the `=` and the value, or delete the line.

#### E0409

```text
%s: %v
```

A value in `narra.toml` could not be read. A value is a quoted string, an array of strings, or an inline table in `[dependencies]` and `[overrides]`. The message says what is wrong, for example a string that is not closed.

Fix: write the value in one of these forms, such as `version = "1.0.0"`.

#### E0410

```text
package name must be a string of letters, digits and `_`, starting with a letter
```

The package name is the first part of every import path of the package. It must be letters, digits and `_`, and start with a letter.

Fix: `name = "my-app"` becomes `name = "my_app"`.

#### E0411

```text
package name "std" is reserved for the standard library
```

Import paths that start with `std` name the standard library, so a package cannot have that name.

Fix: choose another `name` in `[package]`.

#### E0412

```text
%s must be a string
```

This key takes one string. The `version` of `[package]` and the `name` and `entry` of a `[[binary]]` are strings.

Fix: `entry = ["main.run"]` becomes `entry = "main.run"`.

#### E0413

```text
%s must be an array of strings
```

The `search` key of `[link]` takes an array of strings, even for one folder.

Fix: `search = "/opt/lib"` becomes `search = ["/opt/lib"]`.

#### E0414

```text
[package] needs a name
```

Every package needs a name in its `[package]` table. Only a workspace root without a `[package]` table can leave it out.

Fix: add `name = "app"` under `[package]`.

#### E0415

```text
each [[binary]] needs a name and an entry such as "cli.run"
```

Each `[[binary]]` table makes one program. It needs the `name` of the executable and the `entry`, the function that starts it, written as `"module.function"` with the module path relative to `src/`.

Fix: add both keys, for example `name = "app"` and `entry = "main.run"`.

#### E0416

```text
two [[binary]] entries are named %q
```

Each `[[binary]]` builds an executable named by its `name`, so two tables with one name would write the same file.

Fix: rename one of the binaries.

#### E0417

```text
modules %q and %q have the same C name hash; rename one file
```

Each module gets a short hash that is part of its names in the generated C code. Two modules of the build got the same hash, so their names would clash.

Fix: rename one of the two files.

#### E0418

```text
import cycle: %s
```

Modules cannot import each other in a cycle. The message lists the modules in the cycle.

Fix: move the shared declarations into a new module that both import, or merge the modules.

#### E0419

```text
no entry function; declare `export function run(args: Array<string>): int`
```

A program built from one file starts at an exported function `run`, and the file has none.

Fix: add `export function run(args: Array<string>): int`. Its result is the exit code.

#### E0420

```text
binary %q: no entry function %q; declare `export function %s(args: Array<string>): int` in module %q
```

The `entry` of a `[[binary]]` names a module and a function, as in `"main.run"`. That module has no exported function with that name.

Fix: declare `export function start(args: Array<string>): int` in the module, or correct the `entry`.

#### E0421

```text
the import alias %s is also a type name; rename it, for example `import * as %s from %q`
```

An import alias has the name of a type of this module. Both are written before a `.`, as in `Shape.Circle`, so the compiler could not tell them apart.

Fix: rename the alias, for example `import * as Shapes from "..."`. The compiler offers this fix.

#### E0422

```text
two imports use the alias %s; give one of them another alias
```

Each alias in a file names one module. Two imports with one alias would make `Alias.name` ambiguous.

Fix: give one of the imports another alias.

#### E0423

```text
imported name %q is already declared in this module; rename the import with `as`
```

A name imported with `import { name }` has the name of a function, constant or alias of this module.

Fix: rename the import with `as`, as in `import { length as textLength } from "std/string"`.

#### E0424

```text
imported name %q is already imported from another module; rename one with `as`
```

Two imports bring in the same name from different modules, so a call to that name would be ambiguous.

Fix: rename one of them with `as`, as in `import { parse as parseJson } from "..."`.

#### E0425

```text
%q is a constructor of %s; import the enum and write %s.%s
```

Importing a constructor by name is not allowed. Import the enum; its constructors come with it.

Fix: `import { Teacher }` becomes `import { SchoolPerson }`, and uses become `SchoolPerson.Teacher`.

#### E0430

```text
dependency %s needs a git and a version
```

A dependency is downloaded from a git repository at a tagged version, so its inline table needs both `git` and `version`.

Example: `json = { git = "https://example.com/narra-json", version = "1.2.0" }`.

#### E0431

```text
version %q is not MAJOR.MINOR.PATCH
```

A version has three numbers, `MAJOR.MINOR.PATCH`.

Fix: `"1.0"` becomes `"1.0.0"`.

#### E0432

```text
dependency %s has an unknown or repeated key %q; it takes git and version
```

The inline table of a dependency takes `git` and `version`, each once. A member of the same workspace takes `workspace = true` alone.

Fix: remove the unknown or repeated key.

#### E0433

```text
a dependency cannot be named %s: it is the standard library or this package
```

`std` is the standard library, which every package can import, and a package cannot depend on itself.

Fix: remove the entry from `[dependencies]` or `[overrides]`.

#### E0434

```text
two dependencies are named %q
```

The name of a dependency is the first part of its import paths, so it can stand for one package only.

Fix: delete one of the two entries.

#### E0435

```text
dependency %s is not a valid inline table: %s
```

A dependency is an inline table of quoted strings, such as `{ git = "...", version = "1.2.0" }`, or `{ workspace = true }`. The value could not be read as one. A trailing comma or an unquoted value also causes this error.

Fix: write the table in that form.

#### E0436

```text
dependency name %q must be letters, digits and `_`, starting with a letter
```

The name of a dependency is the first part of its import paths. It must be letters, digits and `_`, and start with a letter.

Fix: use the `name` from the `[package]` table of the dependency.

#### E0437

```text
bad line: %s
```

A line of `narra.lock` is not `[[package]]` or `key = "value"`, or a value has the wrong form. `narrac build` writes this file, and it is not meant to be edited by hand.

Fix: undo the edit, or delete `narra.lock` and run `narrac build` to write it again.

#### E0438

```text
entry %s has the unknown key %s
entry %s is missing the key %s
entry %s repeats the key %s
entry %s has the tag %s, which is not the tag of version %s
```

An entry of `narra.lock` has an unknown, missing or repeated key, or a `tag` that does not belong to its `version`. `narrac build` writes this file.

Fix: undo the edit, or delete `narra.lock` and run `narrac build` to write it again.

#### E0439

```text
two entries are named %q
```

Two entries of `narra.lock` have the same name. Each package has one entry.

Fix: undo the edit, or delete `narra.lock` and run `narrac build` to write it again.

#### E0440

```text
git was not found on PATH
```

`narrac` runs `git` to fetch dependencies, and found no `git` program on `PATH`.

Fix: install git, or add its folder to `PATH`.

#### E0441

```text
cannot read the repository %s: %s
```

`narrac` could not list the tags of the repository with `git ls-remote`. The URL or path may be wrong, the network may be down, or the repository may need access rights. The message shows the first line of the git error.

Fix: check the `git` value of the dependency, and that git can reach the repository.

#### E0442

```text
the repository %s has no tag %s
```

A version is fetched by its tag, and the repository has no tag with that name. The tag is `v1.2.0` for version `1.2.0`, or `json/v1.2.0` in a repository that holds several packages.

#### E0443

```text
the cached version %s has tree %s, but %s was expected
```

A version in the cache has a `.hash` file next to it that records its commit and tree hashes. That file is missing or damaged, or the tree hash differs from the one `narra.lock` records.

Fix: delete the cached folder and its `.hash` file, then run `narrac build` to fetch it again.

#### E0444

```text
no cache folder: set NARRA_CACHE or HOME
```

Dependencies are cached in `$NARRA_CACHE`, or in `$HOME/.cache/narra` when that variable is not set. Neither variable is set.

Fix: set `NARRA_CACHE` or `HOME`.

#### E0445

```text
cannot check out %s of %s: %s
```

Fetching a version into the cache failed while creating a folder, cloning the repository or checking out the tag. The message gives the step and the error.

Fix: check the free disk space and the permissions of the cache folder, then build again.

#### E0450

```text
package %s is required from two repositories, %s and %s, and [overrides] has no entry for it
package %s is a member of the workspace and is also required from %s
```

A package name stands for one source in a build. Here two packages require it from different repositories, or a workspace member has the name and a git dependency asks for it too.

#### E0451

```text
the repository %s has no tag for version %s of %s
```

The repository has no tag for the version asked for, neither `v1.2.0` nor `json/v1.2.0` for version `1.2.0` of `json`.

Fix: check the `version` of the dependency, or tag that version in the repository.

#### E0452

```text
narra.lock records commit %s and tree %s for %s %s, but the repository has commit %s and tree %s
```

`narra.lock` records the commit and tree hash of each version. The repository now has other hashes for the same tag, for example because the tag was moved. The build stops so that changed code is not used without notice.

#### E0453

```text
the manifest of %s %s names the package %q
```

The `narra.toml` of the fetched version has a `[package]` name that differs from the key in `[dependencies]`.

Fix: use the name of the package as the key, or check the `git` URL.

#### E0454

```text
[overrides] is allowed in the root manifest of a build only, not in %s
```

Only the root `narra.toml` of a build may replace repositories with `[overrides]`. A dependency or a workspace member cannot.

#### E0455

```text
[overrides] has an entry for %s, but no package requires it
```

An entry of `[overrides]` names a package that no package in the build requires.

Fix: delete the entry, or correct its name.

#### E0456

```text
the override for %s names version %s, which has no tag in %s
```

The version that an override names has no tag in the repository of the override.

#### E0457

```text
%s has no narra.toml
```

The fetched version has no `narra.toml` where the package should be, so it is not a Narra package.

#### E0458

```text
cannot read or write %s: %s
```

`narrac` could not read or write `narra.toml` or `narra.lock`. The message gives the path and the system error.

#### E0460

```text
%s %s is not in the cache; run narrac build to fetch it
```

`narra.lock` names a version that is not in the cache. Tools that read the cache without fetching, such as `narrac lsp`, report this.

#### E0461

```text
narra.lock has no entry for %s %s from %s; run narrac build to update it
```

A dependency has no matching entry in `narra.lock`, often after `[dependencies]` changed. Tools that do not fetch, such as `narrac lsp`, report this.

#### E0462

```text
the dependency %s has no .nra files in src/
```

A dependency must hold Narra code, at least one `.nra` file under `src/`.

#### E0463

A package may import only itself, `std` and the packages in its own `[dependencies]`. A package that another dependency brings in does not count.

#### E0470

```text
export key %s must be the package name %s or start with %s
```

A key of `[exports]` is the import path that other packages write. It must be the package name, or start with the package name and `/`.

#### E0471

```text
export %s must be a string, the module file such as "src/index.nra"
export %s names %s, but the package has no such file
```

#### E0472

```text
two exports are named %q
```

Two keys of `[exports]` are the same import path.

#### E0473

```text
%s does not expose %s; it exposes %s
```

The package has an `[exports]` table, so other packages may import only the paths it lists. The message shows them.

#### E0474

Modules under `std/internal/` and `std/ext/` are parts of the standard library that only the library itself imports. The message lists the modules you can import.

#### E0480


#### E0487

#### E0488

#### E0489

#### E0490

`==` on a value of a type parameter needs the parameter to be Equatable.

```text
%s does not implement Equatable
```

## E0800 to E0899: Effects

#### E0800


#### E0801

```text
%s cannot be a map key: %s
```

#### E0902

```text
Map.remove changes the map; write Map.remove(mutable m, key)
```

`Maps.remove` and `Maps.update` change the map they are given, so the call marks it `mutable`.

#### E0904

```text
%s needs an array, found %s
```

`Arrays.length`, `Arrays.values` and `Arrays.entries` take an array, and the value passed is not one.

```text
Array.push changes the array; write Array.push(mutable items, value)
```

`Arrays.push` and `Arrays.truncate` change the array they are given, so the call marks it `mutable`.

#### E0906

```text
%s needs an array, found %s
```

The first argument of `Arrays.push` or `Arrays.truncate` is the array to change, and the value passed is not an array.

#### E0907

```text
%s can only be called inside a `test` block
```

The functions of std/test, such as `Test.eq`, are assertions for test blocks. A call outside a `test` block is an error. The import itself may stay in a file that is also built as a program.

```text
%s.%s needs an import; add `import * as %s from %q`
```

`Array`, `Map`, `Box`, `Option`, `Range` and `Result` are types, not modules. Their functions live in a std module that must be imported.



This argument of a std/result or std/map function is called as a function, so it must be one.

#### E0912


The callback of `Results.andThen` returns the next Result. A callback that returns a plain value fits `Results.map`.

#### E0913

```text
%s needs a function that returns a value
```

The value the callback returns goes into the result of the call, so a callback that returns nothing has no value to give.

Fix: return a value from the callback.

#### E0914

```text
%s.%s names a type; this module imports %q as %s
```

A type name is not a module. The std module for this type is already imported, under another name.

#### E0915

A `mutable` parameter and a `for (mutable ...)` loop element refer to a value that the caller or the loop owns. Returning one or storing it in another value would keep that reference after the call or loop ends.

#### E0916

Only a `for` or `while` loop can carry a label, because only loops are left with `break label` and `continue label`.

```text
%s exists only on @target(%s), but this use is compiled for %s; use it inside an if on Build.os or Build.arch that keeps it only on that target
%s is not available on Wasi, but this use is compiled for %s; use it inside an if on Build.os that drops Os.Wasi
```

A `@target` function exists only on its target, so a use must sit where only that target compiles it: inside an `if` on `Build.os` or `Build.arch` that the other targets drop, or inside a `@target` function with the same or a narrower target. An ordinary `if`, a `match` and an early `return` do not count.

`narrac check` checks the host only; `narrac check --all-targets` checks every supported target.

Example: `print(linuxName())` becomes `if (Build.os == Os.Linux) { print(linuxName()) }`.

#### E0992

```text
a constant type parameter must have type int, found %s
constant type parameters are allowed only on functions and structs
a type argument cannot compute with `%s`; write an integer literal or a constant parameter
```

A constant type parameter is written `const N: int` in the type parameters of a function or a struct. Its kind is `int`; enums, type aliases and other integer kinds do not take one. A type argument is a type, an integer literal or a constant parameter in scope; it never computes.

Example: `Vector<N + 1>` is rejected; pass the length as its own constant parameter, `function grow<const N: int, const M: int>(vector: Vector<N>): Vector<M>`.

#### E0993

```text
%s is a constant, not a type; only a constant type parameter takes it
%s is a constant type parameter, not a type
the constant %s for %s does not fit an int
constant parameter %s takes an integer literal or a constant parameter, found %s
```

A constant parameter takes an integer literal or a constant parameter in scope, and a type parameter takes a type; the two do not mix. A local, a type or a top-level constant cannot stand for a constant parameter, and a constant cannot stand for a type.

Example: `Vector<count>` becomes `Vector<3>`, and `value: N` becomes `value: int` with `N` read in the body.

#### E0994

```text
index %s is out of range for %s, whose indexes are %s%s
the index of %s must be proven to be %s; %s%s
```

Indexing a FixedArray has no runtime check, so every index is proven at compile time. A constant index must be from 0 to N - 1. Any other index must be a plain name that a check puts in that range: an `if` or `while` condition such as `i >= 0 && i < 4`, the condition of `for (let i = 0; i < N; i++)`, or `for (const i of Ranges.upTo(N))`. An assignment to the name ends what the check proved. `FixedArrays.get(values, i)` returns an Option for any index.

Example: `values[i]` becomes `if (i >= 0 && i < 4) { use(values[i]) }`.

#### E0995

```text
the length of a FixedArray cannot be negative, found %s
the length %s of a FixedArray does not fit an int
the length of a FixedArray is an integer literal or a constant parameter, found %s
FixedArray takes an element type and a length, as in FixedArray<int, 4>
a literal cannot build %s: its length is a constant parameter, which the generic declaration does not know
%s needs %s elements, found %s
%s takes more than %s bytes, the limit for a FixedArray; use an Array
```

`FixedArray<T, N>` takes an element type and a length. The length is an integer literal or a constant type parameter, and never negative. One FixedArray value takes at most 1048576 bytes (1 MiB); use an Array for more. A literal builds a FixedArray when the expected type is one, and gives every element.

Example: `const point: FixedArray<f64, 3> = [1.0, 2.0, 3.0]`.

#### E0996

```text
%s is unsafe; call it inside an `unsafe { }` block
%s runs unsafe code; iterate it inside an `unsafe { }` block
```

A call of a std/ptr function or of a function with the unsafe effect may break memory safety, so it is allowed only inside an `unsafe { ... }` block. The function that holds the block gets the unsafe effect, unless it is marked `@trusted`.

Example: `const value = Ptr.read(items)` becomes `let value = 0` followed by `unsafe { value = Ptr.read(items) }`.

#### E0997

```text
@trusted on %s, which has no `unsafe` block; remove @trusted
%s is @trusted, so it does not have the unsafe effect; remove `uses unsafe`
```

`@trusted` states that a function's `unsafe` blocks were checked by hand, and stops the unsafe effect there: callers need no `unsafe` block. A function without an `unsafe` block has nothing to trust, and a `@trusted` function does not declare `uses unsafe`.

Example: remove `@trusted` from a function that has no `unsafe` block.

#### E0998

```text
Ptr takes one type argument
Ptr<%s> is not allowed: %s; a pointer may point at numbers, bool, char, Ptr and structs of those
%s takes a Ptr, found %s
%s takes its element type from where the result goes, as in `%s`
```

A `Ptr<T>` is a raw pointer with no reference count. It may point at numbers, `bool`, `char`, another `Ptr` and structs whose fields are all such values, because a pointer to a string, array, map, box, enum or closure would bypass reference counting. The std/ptr functions take a `Ptr`; `Ptr.alloc`, `Ptr.null` and `Ptr.cast` take the element type from where the result goes.

Example: `Ptr<string>` is rejected; `const items: Ptr<int> = Ptr.alloc(4)` works.

## E1000 to E1099: C interop and unsafe code

#### E1000

```text
@extern is written on a function inside an `extern { } from` block
an extern block ends with `from "library"`, found %s
%q is not a library name; write the name cc takes after -l, such as "m"
an extern block declares at least one C function
@%s is not written on a function of an extern block; only @extern is
an extern block holds only function signatures, found %s
%s in an extern block cannot be generic or a generator
%s in an extern block has the unsafe effect already; remove `uses`
%s in an extern block has no body; the C library provides it
unknown key %s in [link]; [link] takes search
```

C functions are declared in a block that names their library: `extern { function sqrt(value: f64): f64 } from "m"`. A member is a signature with no type parameters, no `uses` and no body; it has the unsafe effect. Only `@extern("name")` may stand before a member. The libraries come from `from`, so `[link]` in narra.toml takes only `search`.

Example: `[link] libraries = ["m"]` is removed; write `from "m"` after the extern block.

#### E1001

```text
"%s" is not a C name; a C name is letters, digits and _, not starting with a digit
the C name %s clashes with %s that the compiler writes; give the function another name with @extern
```

A C function is linked by its C name, the member's name or the one `@extern` gives. That name must be a C identifier and must not be one the compiler writes itself: `main`, names starting with `narra_` or `lstr_`, string literal names such as `L1`, and the generated names of the program's functions and types, alone or with a helper's operation before or a suffix after (`release_E_Option_e088c655`).

Example: `@extern("narra_alloc")` is rejected; call the C function by its own name.

#### E1002

```text
%s of C function %s has type %s; a C function takes numbers, bool and Ptr<T>
C function %s returns %s; a C function returns numbers, bool, Ptr<T> or nothing
```

A C function takes and returns values C can pass: the number types, `bool` and `Ptr<T>`, and may return nothing. Strings, arrays and other counted values have no C form; pass a `Ptr<u8>`, for a string `CStrings.pointer` of a CString.

Example: `function strlen(text: string): u64` becomes `function strlen(text: Ptr<u8>): u64`.

#### E1003

```text
the type of constant %q is not known here; write it as `const %s: Type = ...`
```

`typeof` of a constant needs the constant's type, and a constant without a written type has its type only after its value is checked. In a declaration of the same module (a signature, a field, an alias) that type is not known yet, so write it.

Example: `const limit = 3` becomes `const limit: int = 3`.

#### E1004

```text
a source line or column must be below %s; split the file or the line
```

The compiler tracks a position as a line and a column below 1048576 each. A token past either limit is rejected, since it would share a record with another position. Split the file, or break the long line.

#### E1010

```text
a tuple index must be a constant integer; use a pattern such as `const #[first, second] = pair` to read the elements
```

A tuple element is read with a constant index, `pair[0]`, so the read is a field read and cannot fail. An index that is a `let`, a parameter or any other computed value is rejected, because the element type would depend on it. A top-level `const` works. To read every element, destructure the tuple.

Example: `pair[count]` becomes `const #[first, second] = pair`.

#### E1011

```text
index %d is out of range for %s, whose indexes are 0 to %d
```

A tuple has a fixed number of elements, and a constant index must name one of them, counting from 0. Tuple elements are read-only, so `pair[0] = 2` is E0226.

Example: for `#[int, string]`, the indexes are 0 and 1; `pair[2]` and `pair[-1]` are rejected.

#### E1012

```text
cannot derive %s for %s: its base type %s does not implement %s
```

A distinct type has the representation of its base type, so a derived trait is the base type's: `distinct type UserId = int derives Show` prints as an int. The derive needs the base type to implement the trait.

Example: `distinct type Handle = Ptr<int> derives Show` is rejected, since a pointer has no Show; write an `implement Show for Handle` block and list `implements Show`.

#### E1013

```text
%s cannot be used as a value: %s; wrap it in an arrow function, such as `%s`
```

A standard function is a value when its signature is fixed: `Int.toString`, `Str.length`, `Fs.readText`. A function whose types depend on the call (`Arrays.length`, `Maps.size`), one with a `mutable` parameter and one that takes a function argument have no single signature, so they are not values.

Example: write the arrow function `(items) => Arrays.length(items)` instead of `Arrays.length`.

#### E1014

```text
cannot implement %s for %s: %s on a distinct type compares the base value
```

`==`, `!=` and map keys on a distinct type compare and hash the base value, so an `implement Equatable` or `implement Hashable` block for it would never run and is rejected. Write the comparison as a function of the declaring module, or wrap the value in a struct.

Example: `implement Equatable for UserId` is rejected for `distinct type UserId = int`.

#### E1020

```text
%s does not implement %s, which %s needs for type parameter %s
%s does not implement %s, which %s needs for type parameter %s; declare it as <%s: %s>
```

A struct or enum can require traits of its type parameters, as in `struct Labeled<T: Show>`. Every use of the type with arguments must meet them: a written type, a struct literal and an enum constructor. A type parameter of the enclosing function or type meets a constraint only when it declares the same trait; constraints are not implied.

Example: `function first<T>(pair: Labeled<T>)` is rejected; write `function first<T: Show>(pair: Labeled<T>)`.

#### E1021

```text
`implement %s for %s` must name the type as %s, with the type parameters of its declaration in order
```

An implement block for a generic struct or enum names the type with the type parameters of its declaration, by the same names and in the same order. The block adds no constraints of its own: the members see the constraints the declaration gives, and the block holds for every instance.

Example: for `struct Pair<T>`, `implement Show for Pair<int>` and `implement Show for Pair` are rejected; write `implement Show for Pair<T>`.

#### E1022

```text
Dynamic takes one trait argument
Dynamic takes a trait, and %s is not a trait
```

`Dynamic<Trait>` holds a value of any type that implements one trait, so its one type argument is a trait name. `Dynamic<int>`, `Dynamic` alone and `Dynamic<Show, Ordered>` are rejected.

Example: write `Dynamic<Show>`.

#### E1023

```text
Dynamic<%s> needs Self as the first parameter of every function of %s, and %s.%s does not take it first
Dynamic<%s> needs Self only as the first parameter of every function of %s, and %s.%s names it elsewhere
```

A call through a `Dynamic<Trait>` passes the Dynamic where the trait writes `Self`, and the table of the stored type does the rest. That works only when every function of the trait takes `Self` as its first parameter, once and not inside another type, and mentions `Self` nowhere else, the result included. `Equatable` and `Ordered` take two values, and `Shape.fromValue` returns `Self`.

Example: `trait Drawable { function draw(value: Self): string }` can be used as `Dynamic<Drawable>`.

#### E1024

```text
Dynamic has no function %s; Dynamic.of(value) is its only function
Dynamic.of takes one value
Dynamic.of needs an expected Dynamic<Trait> type; annotate it, as in `const item: Dynamic<Show> = Dynamic.of(value)`
```

`Dynamic.of(value)` takes the trait from the expected type: an annotation, a parameter type, a field type or a result type. It takes one value and is the only function of `Dynamic`.

Example: `const item: Dynamic<Show> = Dynamic.of(42)`.

#### E1025

```text
%s.%s takes a mutable Self, and a Dynamic<%s> cannot be passed to it: its value is shared by every copy
```

Every copy of a Dynamic shares one stored value, so a trait function that takes `mutable value: Self` cannot be called through a Dynamic: the change would reach the other copies.

Example: call the function on the concrete value before wrapping it with `Dynamic.of`.

#### E1050

```text
@const function %s %s; an @const function takes and returns numbers, bool, char, string, bytes, Array, Map, FixedArray, Option, Result, tuples, and structs, enums and distinct types made of these
```

The compiler runs an @const function while it compiles and writes the result into the C, so its parameters and result hold only values the compiler can build and write: numbers, bool, char, string, bytes, Array, Map, FixedArray, Option, Result, tuples, and structs, enums and distinct types made of these. A function value, Cell, Ptr, Shared, a generator, a trait-constrained type parameter or an effect parameter has no compile-time value.

Fix: remove @const, or change the signature.

#### E1051

```text
@const function %s declares `uses %s`; an @const function may use only alloc
@const function %s uses %s%s; an @const function may use only alloc
```

An @const function runs inside the compiler, where nothing outside it can observe what it does. It may allocate, and nothing else: no io and no unsafe code.

Fix: move the effect out of the function, or remove @const.

#### E1052

```text
@const function %s %s; an @const function calls only @const functions, constructors and the std functions of %s that take no function
constant %s cannot be computed while compiling: %s
```

An @const function calls other @const functions, constructors and the std functions of std/string, std/array, std/map, std/int, std/float, std/range, std/char, std/option, std/result, std/regex, std/math, std/bytes, std/fixedarray, std/f32 and the sized number modules that take no function. It cannot use an arrow function, call through a function value or run a user implement block (through ==, a map key or a direct call).

Fix: mark the called function @const, compute the value another way, or remove @const.

#### E1053

```text
constant %s panicked while the compiler computed it: %s
```

The compiler computes a constant that calls an @const function while it compiles. A panic, a failed assert, an index out of range or a std function that would panic stops the computation, and the error shows the chain of calls from the constant to where it stopped.

Fix: change the arguments or the function so it does not panic.

#### E1054

```text
constant %s needs more than %s evaluation steps; %s
```

A constant may take 10 million evaluation steps (one per expression, statement and loop turn, plus one per 8 bytes or elements a std call goes through), so a mistake such as an endless loop cannot hang the compiler.

Fix: compute a table this large at run time in a function, or generate a source file; for Regexes.checked, compile the pattern at run time with Regexes.compile.

#### E1055

```text
constant %s needs more than 64 MiB of values (%s); %s
```

The values a constant builds while it is computed may take 64 MiB, counted as 8 bytes per number, element, field and entry, string lengths rounded up to 8, and 16 per array and map; `copy(...)` and storing a value read from a place count its outer level again. A std call whose result would pass the limit is stopped before it runs.

Fix: compute a table this large at run time in a function, or generate a source file; for Regexes.checked, compile the pattern at run time with Regexes.compile.

#### E1056

```text
constant %s makes more than %s nested calls; a self-call in tail position runs as a loop and does not count
constant %s holds a value nested more than %s levels deep; the compiler writes a computed value only up to that depth
constant %s nests calls, blocks and expressions more than %s deep; a self-call in tail position runs as a loop and does not count
```

A constant may make 1000 nested calls while it is computed, nest calls, blocks, loops and expressions 5000 deep, and build values nested 1000 levels deep, which keeps the compiler stack safe. A function that calls itself as its last step (`return f(...)`) runs as a loop and does not count.

Fix: write the recursion as a loop or as a tail call.

#### E1057

```text
constant %s is read by an @const function while it is computed, so it is defined in terms of itself
```

An @const function may read top-level constants. A constant whose computation reads the constant itself has no value to start from.

Fix: break the cycle, for example by passing the value as an argument.

## E1100 to E1199: Concurrency

#### E1100

```text
await is allowed only in an async function, an async arrow or an async block, not %s
```

`await` waits for a task, so it can stand only where the body is itself a task: an async function, an async arrow or an async block. A `function*` body and an arrow that is not async are bodies of their own, also inside an async body.

Fix: make the function or arrow async, or pass the handle on and await it in an async body.

#### E1102

```text
await takes an Async<T>, found %s; only the handle of a task can be awaited
```

`await` takes the handle of a task, an Async\<T\>, and gives its value.

Fix: await the call that returns the handle, or use the value without await.

#### E1103

```text
this Async handle is not used; await it, keep it, pass it on, or let the task run with Async.detach(handle)
```

A call of an async function, an async arrow or an `async { ... }` block starts a task and gives its handle. A handle that nobody uses hides a task that keeps running; `const _ =` does not let it go.

Fix: await the handle, keep it in a name, pass it on, or call Async.detach(handle) to let the task run with nobody waiting.

#### E1104

```text
async function %s cannot take a mutable parameter %s; its task outlives the call
```

A task outlives the call that starts it, so it cannot keep a pointer into the caller's variable.

Fix: take the value as a plain parameter and return the new value from the task.

#### E1105

```text
`for await (mutable ...)` is not allowed: a stream's values are not elements to change in place; write `for await (const x of stream)`
`for (mutable ...)` is not allowed in an async body; change the elements through an index, as in `items[index].field = value`
```

A `for (mutable ...)` loop holds a pointer to the element it changes, which cannot be kept in a task frame across an await. `for await (mutable ...)` is rejected too: the values of a stream are not elements of a place.

Fix: change the elements through an index; read a stream with `for await (const x of stream)`.

#### E1106

```text
cannot use == on %s: a task handle is shared by identity; await the handles and compare the values
cannot use == on %s: a stream is shared by identity; read the values and compare them
%s cannot be a map key: %s
```

A handle is an identity type: copies share one task, so == and a map key would compare tasks, not values.

Fix: await the handles and compare or key by the values.

#### E1108

```text
async must be followed by function, an arrow function or a block, found %s
```

`async` starts an async function, an async arrow or an async block.

Fix: write `async function`, `async (x) => ...` or `async { ... }`.

#### E1109

```text
Async takes one type argument, the value of the task
```

Async\<T\> takes the type of the task's value as its one type argument.

Fix: write Async\<T\>, with Async\<void\> for a task that gives no value.

#### E1110

```text
an async arrow or block cannot capture %s, which is %s: the task copies its captures when it starts; keep state that changes in a Cell from std/cell
an async arrow or block cannot change captured %s: the task copies its captures when it starts; keep state that changes in a Cell from std/cell
```

An async arrow or block copies what it captures when its task starts, so a `let`, a `mutable` parameter or a captured value it changes would no longer be shared with the code around it.

Fix: keep state that changes in a Cell from std/cell, or pass the value in and return the new one.

#### E1111

```text
parameter %s of async function %s has a function type, so it must be `escaping`: the task outlives the call
```

An async function keeps its parameters in its task, which outlives the call, so a function parameter must be one that may be stored.

Fix: declare the parameter as `escaping`.

#### E1112

```text
async generator %s must declare its return type as AsyncGenerator<T>, not Generator<T>; write AsyncGenerator<T>
async generator %s must declare its return type as AsyncGenerator<T>
```

An `async function*` produces a stream of values that may wait between them, read with `Async.next` or `for await`. Its result names that stream, with the effects of the body on it.

Fix: write the result as `AsyncGenerator<T>`, as in `async function* lines(): AsyncGenerator<string> uses io`.

#### E1113

```text
generator %s cannot return AsyncGenerator<T>, which needs an async body; declare it as `async function* %s`
```

An AsyncGenerator\<T\> body may wait between its values, so only an async generator can return one from its own body. A plain or async function may still return a stream it got elsewhere.

Fix: write `async function*`, or return a Generator\<T\>.

#### E1114

```text
AsyncGenerator takes one type argument, the type of the values it yields
```

AsyncGenerator\<T\> takes the type of the values the stream yields as its one type argument.

Fix: write AsyncGenerator\<T\>.

#### E1115

```text
`const %s = yield value` needs a coroutine, and an async generator has no input; write `yield value`
```

An async generator yields values to its readers and gets nothing back: there is no async coroutine.

Fix: write `yield value` as a statement, and pass input to the stream through its arguments or a Cell.

#### E1116

```text
yield* in an async generator needs a %s, found %s; write `for (const x of g) { yield x }`
yield* in an async generator needs a %s, found %s
```

`yield*` in an async generator passes on every value of another AsyncGenerator\<T\> with the same T, one per step of the outer stream.

Fix: delegate to an AsyncGenerator\<T\>; for a Generator\<T\>, write `for (const x of g) { yield x }`.

#### E1122

```text
for await is allowed only in an async function, an async arrow, an async block or an async generator, not %s
```

`for await` waits for each value of a stream, so it can stand only where the body is itself a task: an async function, an async arrow, an async block or an async generator. A `function*` body and an arrow that is not async are bodies of their own, also inside an async body.

Fix: make the function or arrow async, or read the stream with Async.next in an async body.

#### E1123

```text
for await reads an AsyncGenerator<T>, found %s; read a Generator<T> with `for (const x of g)`, which works in an async body
for await reads an AsyncGenerator<T>, found %s; loop with `for (const handle of handles)` and `await handle` in the body
for await reads an AsyncGenerator<T>, found %s
```

`for await` reads an AsyncGenerator\<T\>, the stream an `async function*` gives, one step at a time.

Fix: for a Generator\<T\> or an array, write `for (const x of items)`, which works in an async body; for an Array\<Async\<T\>\>, loop over the handles and `await` each one.

#### E1124

```text
for ... of cannot read %s, whose values may wait; write `for await (const x of stream)` in an async body
```

The values of an AsyncGenerator\<T\> may wait, so a plain `for ... of` cannot read them.

Fix: write `for await (const x of stream)` in an async body, or read one step with `await Async.next(stream)`.

#### E1150

```text
%s cannot take an Async<void>: type parameter %s would be void outside Async<%s>, and a task with no value gives none
```

An Async\<void\> handle binds the type parameter of its Async\<T\> to void. A generic function whose signature also uses that parameter as a value, such as Async.peek (Option\<T\>), Async.all (Array\<T\>) or Async.race (Option\<T\>), would need a void value, which does not exist.

Fix: await the handles one by one, or give the task a value, such as a bool.

#### E1190

```text
%s: %s is not Sendable%s
```

A value that crosses to another thread (a capture or the result of a thread function, the items of Parallel.map) must be Sendable. Sendable is automatic: a type is Sendable when nothing in it, at any depth, is a function, a Dynamic, a Ptr, a Cell, an Async, a generator or coroutine, a Scope, a Thread or a socket handle. These hold state that one thread changes in place without a lock.

Fix: share changing state through Shared from std/shared, send plain data, and declare a type parameter that crosses as \<T: Sendable\>.

#### E1191

```text
%s holds a Scope; a Scope can be passed to a function, but not stored in a field, element, tuple or constructor
a function cannot return a Scope (%s): every thread of a Scope ends when its Thread.scope returns
a generator, coroutine, stream or task cannot hold a Scope (%s): it can run after its Thread.scope returns
an escaping closure or a task cannot capture Scope %q; pass the Scope to a function as a parameter, or open a new Thread.scope inside the closure
```

A Scope joins its threads when its Thread.scope returns, so it must not outlive that call. It can be passed to functions, but not stored in a field, element, tuple or constructor, returned, captured by an escaping closure such as a thread function, or kept in the frame of a generator, coroutine, stream or task (a parameter or a capture), which can run after Thread.scope returns.

Fix: pass the Scope as a parameter to the function that starts threads, or open a new Thread.scope where it is needed.

#### E1192

```text
Thread.start takes a plain function; use Thread.startAsync to run an async function on a thread
```

Thread.start calls its function and keeps what it returns. An async function returns an Async handle, which belongs to the event loop of the thread that made it. Thread.startAsync runs the task on the new thread's own event loop and keeps the value the task gives.

Fix: write `Thread.startAsync(scope, async () => work())`, or pass a plain function to Thread.start.

#### E1193

```text
a thread function must be an arrow function written at the call or the name of a top-level function, so its captures can be checked
```

The checker must see what a thread function captures, and a function value does not show its captures in its type. So the function passed to Thread.start or Parallel.map is an arrow function written at the call or the name of a top-level function.

Fix: write the arrow at the call, as in `Thread.start(scope, () => work(input))`.

#### E1194

```text
cannot write `%s Sendable`: the compiler implements Sendable for every type whose parts can cross a thread
```

Sendable is only automatic: the compiler implements it for every type whose parts can cross a thread, so a type cannot list, derive or implement it.

Fix: remove the `implement Sendable`, `implements Sendable` or `derives Sendable`.

#### E1195

```text
cannot use == on %s: %s is shared by identity; compare the values it gives
%s cannot be a map key: %s
```

A Thread, a Scope, a Sender, a Receiver, a Shared or an Atomic is a handle shared by identity, so `==`, `!=` and map keys on it are errors, as for a Cell and an Async.

Fix: compare the values the handles give, for example the results of Thread.join or Shared.get.

## E1200 to E1299: Types and parameters: templates, defaults, refinements, effect lists, SIMD, ranges

#### E1200

```text
a template after an expression is a tagged template, and only a name or a dotted name can be its tag
a tag takes no type arguments; the tag's parameters give its type
```

A template right after a name is a tagged template: `tag`a${x}b`` calls `tag(["a", "b"], [x])`. Only a name or a dotted name can be the tag, so the function called is named where it is used.

Fix: put the tag in a constant first (`const tag = make()`, then `tag`...``), or write a space-free name before the template.

#### E1201

```text
a tag must be a function of (Array<string> or Template.Raw, Array<T>) with no mutable parameter, found %s
```

A tag is a function of two parameters: the parts, `Array<string>` (escapes decoded) or `Template.Raw` from std/template (the source text), and the values, `Array<T>`. Neither parameter can be `mutable`.

Fix: give the tag that signature, for example `function tag(parts: Array<string>, values: Array<string>): string`.

#### E1202

```text
value %s of the tagged template is %s, but the tag takes values of type %s; convert it inside the ${}
value %s of the tagged template is void; a value must have the tag's value type
```

Every `${}` value of a tagged template has the tag's value type T, the element type of its second parameter. A generic tag takes T from the first value.

Fix: convert the value inside the `${}`, for example `${Int.toString(count)}`.

#### E1203

```text
a template at the start of a line is not tagged by the name that ends the line before; join the lines to tag it
```

A line break ends the statement, so a template at the start of a line is not tagged by the name at the end of the line before.

Fix: write the tag and the template on one line, `const x = tag`a``, or remove the template.

#### E1210

```text
a parameter without a default cannot follow one with a default; give %q a default or move it before %q
```

Parameters with defaults come last, so a call can leave them out from the end.

Fix: give the parameter a default, or move it before the first parameter with one.

#### E1211

```text
a mutable parameter cannot have a default
```

A `mutable` parameter refers to a value that the caller passes, so it cannot have a default.

Fix: remove the default.

#### E1212

```text
a parameter default must be a constant
```

A parameter default is a compile-time constant: a literal, a unary operator on a constant, a constructor with constant arguments, or an array of constants. It cannot read another parameter, a local, a top-level constant or a function.

Fix: write the value as a literal, or take `Option<T> = None` and compute the value in the body.

#### E1213

```text
an arrow function parameter cannot have a default
a function type cannot have parameter defaults
```

Only declared functions take parameter defaults. An arrow function parameter and a function type parameter have none.

Fix: remove the default and pass the value at each call.

#### E1214

```text
a trait function cannot have parameter defaults
```

A trait function and the functions of its implement blocks cannot have parameter defaults.

Fix: remove the default and pass the value at each call.

#### E1215

```text
a function of an extern block cannot have parameter defaults
```

The functions of an `extern` block cannot have parameter defaults.

Fix: remove the default and pass the value at each call.

#### E1216

```text
optional parameters are written with a default; write %q
an arrow function parameter cannot be optional; write %q
```

An optional parameter is written with a default, not with `?`. An arrow function parameter cannot be optional.

Fix: `name?: string` becomes `name: Option<string> = None`. In an arrow function, write `name: Option<string>`.

#### E1220

```text
a distinct type's `requires` needs a pattern here, found %s
a distinct type takes one `requires` list; join its patterns with `&&`
`implements` and `derives` come before `requires` on a distinct type
```

A distinct type takes one `requires` list of patterns joined by `&&`, after its `implements` and `derives` lists.

Fix: write it as in `distinct type Port = int derives Show requires >= 1 && <= 65535`.

#### E1221

```text
distinct type %s cannot have a requires list: its base %s is not an integer type or string
```

Only a distinct type over an integer type or `string` can have a `requires` list.

Fix: remove the list, or base the type on an integer type or `string`.

#### E1222

```text
%s refines string, so its patterns are string literals; `%s` compares integers
the bound of `%s` does not fit %s's base %s
the bound of `%s` must be an integer constant: a literal or a top-level const
the literal %s cannot be proven for %s's base %s; the prover keeps integers as int and cannot prove 2^63 - 1, -(2^63 - 1) or a u64 from 2^63 up
the literal %s is not a value of %s's base %s
a refinement pattern is a comparison, a literal or alternatives of them, found %s
```

The patterns of a distinct type's `requires` fit its base. An integer base takes comparisons with a constant bound that fits the type, and integer literals. A `string` base takes string literals only.

Fix: write patterns such as `>= 1 && <= 65535` or `"GET" | "POST"`.

#### E1223

```text
%s does not satisfy %s (%s)
%s.from needs %s to satisfy %s; check it first or call %s.check
```

`T.from(value)` is proven at compile time against the type's `requires` patterns. Nothing is checked at run time.

Fix: pass a constant that matches, check the value first with an `if`, or call `T.check(value)`, which returns an Option and tests at run time.

#### E1240

```text
a type's `uses` list takes one effect, or several in parentheses: `uses (%s, %s)`
```

In a type, `uses` takes one effect, or a comma list in parentheses: `() => int uses io`, `Generator<int> uses (io, alloc)`. A `,` after the one effect ends the type, so the type can stand in a list of types or parameters. A function's own list, after its result type, is a bare comma list.

Fix: put the type's effects in parentheses, `Generator<string> uses (io, alloc)`. A function that makes a generator writes its own list after it: `(): Generator<string> uses (io, alloc) uses alloc`.

#### E1241

```text
`%s` is an effect, not a type
`%s` is an effect, not a type; a type takes several effects in parentheses: write `uses (%s)`
```

`io`, `alloc`, `unsafe` and effect variables name effects, which only a `uses` list holds; they are not types. In a list of types such as `Map<Generator<int> uses io, alloc>`, the `,` ends the generator's one effect, so `alloc` stands where a type belongs.

Fix: write the effects in parentheses, `Map<Generator<int> uses (io, alloc), int>`, or move the name into a `uses` list.

#### E1242

```text
`%s` is listed twice in this `uses` list
```

A `uses` list names each effect once, in a type and in a function's own list.

Fix: delete the repeated name: `uses (io, io)` in a type and `uses io, io` on a function both become `uses io`.

#### E1250

```text
%s is not defined on %s; compare the lanes with %s
%s is not defined on %s: no SIMD instruction divides integer lanes; read the lanes with v[i] and divide them one at a time
%s is not defined on %s; shift the lanes with %s
%s is not defined on %s, whose lanes are floats; it takes integer vectors
```

Vector operators work lane by lane, and some have no lane form. These are `<` and the other ordered comparisons, integer `/` and `%`, `<<` and `>>`, and the bit operators on float lanes.

Fix: call the std/simd function the message names, such as `Simd.shiftLeft`.

#### E1251

```text
%s needs two vectors of the same type, found %s and %s
%s needs two vectors of the same type, found %s and %s; make a vector of the scalar with Simd.splat(...)
```

Both operands of a vector operator have the same vector type. A scalar is not a vector.

Fix: `v * 2.0` becomes `v * Simd.splat(2.0)`.

#### E1252

```text
a lane of %s cannot be assigned, since a vector is a value; write `v = Simd.withLane(v, i, x)`
```

A vector is a value, so one lane cannot be assigned.

Fix: `v[i] = x` becomes `v = Simd.withLane(v, i, x)`.

#### E1253

```text
%s needs %d lanes, found %d
```

An array literal for a vector gives exactly one value per lane.

Fix: give as many values as the vector has lanes, as in `const unit: F32x4 = [1.0, 0.0, 0.0, 0.0]`.

#### E1254

```text
%s takes its vector type from where the result goes or from a type argument, as in `const ones: F32x4 = Simd.splat(1.0)` or `Simd.splat<F32x4>(1.0)`
%s takes its vector type from where the result goes or from a type argument, as in `const lanes: Option<F32x8> = Simd.load(items, 0)` or `Simd.load<F32x8>(items, 0)`
```

`Simd.splat` and `Simd.load` cannot tell from their arguments which vector type to build.

Fix: annotate the target, as in `const ones: F32x4 = Simd.splat(1.0)`, or pass a type argument, as in `Simd.splat<F32x4>(1.0)`.

#### E1255

```text
%s has no vector type: a vector holds 16 or 32 bytes of i8 to u64, f32 or f64 lanes
%s takes a FixedArray of known length, found %s
```

A vector holds 16 or 32 bytes of i8 to u64, f32 or f64 lanes. `Simd.fromFixed` needs a FixedArray of known length whose element type and length make such a vector.

Fix: pass a matching FixedArray, such as `FixedArray<f32, 4>` for F32x4.

#### E1256

```text
%s takes a vector, found %s
```

This std/simd function takes a vector, such as an F32x4, and the value passed is not one.

Fix: pass a vector, or build one with `Simd.splat`.

#### E1260

```text
the lanes of %s are a list literal of constants, one per lane, as in `Simd.shuffle(v, [3, 2, 1, 0])`
%s takes %d lanes for %s, found %d
lane %d is out of range for %s, whose lanes are 0 to %d
a lane of %s must be a constant, as in `Simd.shuffle(v, [3, 2, 1, 0])`
```

`Simd.shuffle` takes the lane order as a list literal of constants, one per lane, each a lane of the vector.

Fix: write it as in `Simd.shuffle(v, [3, 2, 1, 0])`.

#### E1261

```text
%s does not take %s, whose lanes are floats; it takes integer vectors
%s does not take %s, which is unsigned; it takes signed and float vectors
%s takes the mask %s for %s, found %s
%s writes %s into an Array<%s>, found %s
```

Some std/simd functions take only some vector types: integer vectors only, or signed and float vectors only. A mask must match the vector, and a store writes into an Array of the lane type.

Fix: pass the vector, mask or array type that the message names.

#### E1270

```text
the step of Ranges.stepped is 0, so the range is always empty; use a step other than 0
```

`Ranges.stepped` with a step of 0 never produces a value.

Fix: use a positive step to count up, or a negative step to count down.

## E1300 to E1399: Standard library modules for tools

#### E1360

```text
%s can only be the value of a top-level const; use %s
```

Regexes.checked compiles its pattern while the compiler runs, so a bad pattern is a compile error (E1053) instead of a panic. That works only where the compiler computes the value: the value of a top-level const. Anywhere else, including a function body or a use as a function value, the call would run in the program and could panic.

Fix: move the call into a top-level const, or call Regexes.compile and handle its RegexError.

## E1400 to E1499: Channels, Shared and Atomic

#### E1410

```text
the callback of %s cannot be async: it runs while the lock is held, and a task must not suspend there
```

Shared.update and Shared.read hold the lock while their callback runs. An async callback would give an Async whose task runs later, after the lock is released, or suspend while other threads wait for the lock.

Fix: pass a plain function, and await the work before or after the call.

#### E1411

```text
Atomic<%s> is not allowed: an Atomic holds bool or an integer type up to 64 bits; keep other values in a Shared from std/shared
```

An Atomic\<T\> uses the processor's atomic operations, which work on bool and the integer types up to 64 bits (int, i8 to i32, u8 to u64). A type parameter is not allowed either, since no bound says "an integer type".

Fix: use an integer type, or keep the value in a Shared from std/shared.

#### E1412

```text
Atomic.add needs an integer type, found Atomic<bool>; use Atomic.store or Atomic.compareExchange
```

Atomic.add adds to an integer. An Atomic\<bool\> has no sum.

Fix: use Atomic.store, Atomic.exchange or Atomic.compareExchange to change a flag.

## E1500 to E1599: Unreachable statements and unused let

#### E1500

```text
this statement is unreachable: the statement before it always leaves the block
```

A statement after `return`, `break`, `continue`, a call to `panic` or `Process.exit`, an `if` and `else` that both leave, a `match` whose arms all leave, or a `while (true)` loop without a `break` never runs.

Fix: delete the statements from the first dead one to the end of the block, or move the code before the statement that leaves.

#### E1510

```text
%q is never reassigned; declare it with `const`
```

A `let` tells the reader that the name gets a new value later. A name that is never assigned, never changed with `+=` or `++`, and never has a field, an element or a `mutable` argument written is a `const`.

Fix: write `const` instead of `let`.

## E1600 to E1699: Build targets

#### E1600

```text
unknown target %s; the targets are %s
```

`--target` takes a name from the target table.

Fix: use one of the names in the message. `narrac targets` prints them.

#### E1601

```text
-sanitize cannot build for %s: sanitizer runtimes do not cross-link; build without -sanitize
```

The sanitizer runtimes do not link into a build for another target.

Fix: build without `-sanitize`, or build on the target itself.
