# narra

`narrac` is the Narra compiler, written in Narra (`selfhost/`). It compiles a `.nra` file or a package to C and builds it with the system C compiler. A checked-in C file, `seed/narrac.c`, builds it with `cc` alone, so no other compiler is needed. The Go bootstrap compiler that came first is gone.

## Usage

```sh
sh selfhost/bootstrap.sh out    # writes out/narrac

narrac run testdata/numbers.nra          # build and run
narrac build -o app file.nra             # build a debug executable
narrac build -release -o app file.nra    # optimized
narrac test testdata/tests.nra           # run `test` blocks
narrac emit file.nra                     # print the generated C
narrac check [--json] file.nra          # report errors; --json prints one object per line
narrac explain E0003                    # explain a diagnostic code
narrac build testdata/packages/app       # build every [[binary]] of a package
narrac run -bin app testdata/packages/app
```

A single file's entry function is `export function run(args: Array<string>): int`.

A package is a directory with `narra.toml` and `src/`. The file `src/text.nra` of package `app` is module `"app/text"`. `narra.toml` sets the package name and the binaries:

```toml
[package]
name = "app"

[[binary]]
name = "app"
entry = "cli.run"     # module inside the package, then the function; "app/cli.run" also works
```

`[link]` takes only `search`, passed to `cc` as `-L<dir>` (relative to the package); any other `[link]` key is E1000, since libraries come from `extern { } from`. Other tables, such as `[build]`, are skipped. `[dependencies]` is an error.

Set `NARRA_CHECK_LEAKS=1` when running a program to report allocations that are still live at exit. The program exits with code 102 when any are found.

## Bootstrapping

`selfhost/bootstrap.sh` needs only `cc`. It builds the compiler from the checked-in C seed, `seed/narrac.c`:

1. Stage 0: `cc` builds the seed into `narrac0`.
2. Stage 1: `narrac0 emit selfhost > stage1.c`, then `cc` builds it into `narrac1`.
3. Stage 2: `narrac1 emit selfhost > stage2.c`. The script exits 1 when `stage1.c` and `stage2.c` differ.

`sh scripts/seed-update.sh` regenerates the seed from the stage 2 C. `seed/README.md` explains the seed rule and when to regenerate. The sanitized self-build is the `bootstrap` suite of the test runner.

## Commands of narrac

`narrac build`, `run`, `test` and `check` (`selfhost/src/driver.nra`) call `$CC` (else `cc`) to build the C. They add `-sanitize` (AddressSanitizer and UBSan) and, for `run` and `test`, `-stdin file`. `run` and `test` capture the program's output and write it after the program ends. `narrac check --json` prints one JSON line per diagnostic and `narrac explain CODE` prints the explanation, fixes included (`selfhost/src/fixes.nra` and the report sites). `narrac apply-fix [--diagnostic N] [--fix M] path` prints the file a fix edits with the fix applied: N defaults to the first diagnostic that has a fix, M to 0; exit 1 when there is no such fix. Every report site passes its diagnostic code; the table is `selfhost/src/diagnostics.nra`, and the `codes` suite of the test runner checks the sites.

## Formatting

`narrac fmt` (the self-hosted compiler, `selfhost/src/fmt.nra`) formats Narra source.

- `narrac fmt [paths]` rewrites the files in place. A directory means every `.nra` file under it (hidden directories are skipped); no path means the current directory.
- `narrac fmt --check [paths]` prints each file that would change and exits 1, or exits 0.
- `narrac fmt --stdin` (or `-`) reads one file from stdin and writes the result to stdout.
- A file that does not parse prints `error <path>:<line>:<col>: <message>`, stays unchanged, and the exit code is 1. A bad `[fmt]` key or value prints `error narra.toml:<line>: <message>` and the exit code is 1.
- Options come from the `[fmt]` table of the nearest `narra.toml` above each file (`printWidth`, `tabWidth`, `useTabs`, `trailingComma`; see `SPEC.md` section 2). Without one the defaults apply.
- Declarations and statements are printed by `fmt.nra`; expressions, types and patterns by `fmtexprs.nra`.
- The `fmt` and `fmt-stable` suites of the test runner run the goldens in `testdata/fmt/` and, for every `.nra` file under `testdata/` and `selfhost/src`, check that formatting twice gives the same text and that the tokens, the comment texts and the syntax tree are unchanged.
- The `sources` suite runs `narrac fmt --check` over `selfhost/src`, `selfhost/tests` and every sample under `testdata/` except `testdata/fmt/`, `lex`, `parse` and `habits`, whose inputs are unformatted or invalid on purpose, and the layout samples, which test a layout the formatter would change. A sample that does not parse is skipped only if its path contains `error` or `/diagnostics/`. `bench/` and `std/` are not checked. After editing Narra source, run `narrac fmt` on it. A sample whose `// error:` line or dump golden holds positions must be updated after formatting.

## Queries

`narrac query` (the self-hosted compiler, `selfhost/src/query.nra`) answers the questions of `SPEC.md` section 14 about a package. The command line and the `--json` shapes are the frozen contract `roadmaps/selfhost/contracts/query-output.md`.

- `narrac query [--package DIR] [--json] <command> <operand>`, where the command is `type-of FILE:LINE:COL`, `def NAME`, `refs NAME`, `callers FUNCTION`, `interface MODULE` or `recursion MODULE`. `DIR` defaults to `.`.
- The package is loaded and checked as `narrac types` does it. Load or check errors print as there (with `--json`: `{"errors": [...]}`, the diagnostic's code; `E0000` for a problem that is not a diagnostic) and the exit code is 1. Any other query error prints `error <message>` (with `--json`: `{"error": ...}` on stdout) and exits 1. A usage error exits 2.
- `type-of` reports the innermost expression, local name or function or constant name at the position. `type` is the type of the value there, function types with their `uses` list (from the declaration or the annotation; an unannotated local holding a function shows none). `effects` is what evaluating the expression there does: a name has none, a call has the call's. A builtin or constructor name in a call answers for the call, because the checker records nothing for the name. A generic function shows its type parameter names.
- `def` lists every declaration a qualified (`app/text.helper`, `app/text.Shape.Circle`) or bare (`helper`, `Shape.Circle`, `Circle`) name finds. `refs` and `callers` need a name that finds one declaration.
- `refs` finds functions, constants and enum variants (calls, values, constructors and patterns). Uses of a type name in annotations or struct literals are not tracked.
- `callers` and `recursion` read the call graph of the effect pass (`EffectState.calls`). Calls through function values are not edges. A call inside an arrow function belongs to the enclosing function.
- Only the package's own modules are searched, not std source modules.
- `selfhost/src/querysites.nra` builds the position index, `querysignature.nra` prints `interface` signatures, `querygraph.nra` finds cycles and `queryjson.nra` writes JSON.
- The `query` suite runs `testdata/query/<case>/queries.txt` (`> command` lines, each followed by `# exit N` when the exit code is not 0, the expected stdout, and `# stderr` with the expected stderr when there is any) against the package in that folder.

## Language server

`narrac lsp` (the self-hosted compiler) is the server of `SPEC.md` section 14. `selfhost/src/lsp.nra` has the framing, the lifecycle and the dispatch. `lspserver.nra` has the documents, the diagnostics and formatting. `lspserverjson.nra` reads fields of a `Value` and builds the messages. Messages are read and written with `std/json`.

- Supported: `initialize`, `initialized`, `shutdown`, `exit`, `textDocument/didOpen`, `didChange` (full text only, `change: 1`), `didClose`, `textDocument/formatting`, `hover`, `definition`, `references` and `documentSymbol`. The server sends `textDocument/publishDiagnostics`.
- Navigation (`selfhost/src/lspnavigation.nra`) loads and checks the package with the open documents' text on each request, and answers from the site index and checker results of `narrac query` (`query.nra` exports `buildViews`, `findTypeAt`, `findUses`, `listDeclarations` and `findTarget`). A document that is not a module of a package that loads gets `null`. A package whose bodies have errors is still answered, but the effect pass does not run, so hover shows no effects of expressions.
  - Hover: the `type-of` answer in a `narra` code block, with a `uses a, b` line when the expression has effects, and the site's range. No site gives `null`.
  - Definition: the declaration a name refers to (function, constant, struct, enum, variant, trait, distinct type), also from a type annotation, an import list or `Alias.Name`, and the declaring name of a local or parameter. Implement block functions, trait functions and std names give `null`.
  - References: the uses `refs` reports for a function, constant or enum variant, with the declaration first when `context.includeDeclaration` is true. Any other name gives `[]`.
  - Document symbols: the declarations in source order, with kinds Function 12, Constant 14, Struct 23, Enum 10, Interface 11 (trait) and Class 5 (distinct type), struct fields (Field 8) and enum variants (EnumMember 22) as children. `range` runs from the declaration's first token (`export` included) to its last token; `selectionRange` is the name. Tests and implement blocks are not listed.
  - -32602 for a navigation request with no `textDocument.uri`, or (except `documentSymbol`) no `position`.
- Errors: -32002 before `initialize`, -32601 for an unknown request, -32700 for a body that is not JSON or a header block with no valid `Content-Length` (the server keeps running), -32600 for a message with no `method`, a second `initialize` or a request after `shutdown`, -32602 for a formatting request with no `textDocument.uri`, a URI that is not `file://` or a file that cannot be read.
- Columns are converted from the compiler's characters to UTF-16 code units, or to UTF-8 bytes when the client offers `utf-8` in `general.positionEncodings`. Ranges are zero-width at the diagnostic's position. Every problem has severity 1 (error). A problem with no code gets `E0000`.
- The open documents replace the files on disk through `Modules.loadWith(path, overrides)`. `Modules.load` is `loadWith` with an empty map.
- Diagnostics are checked incrementally (`selfhost/src/lspcache.nra`). The server keeps the parsed sources (`Modules.loadCached` with a `ParseCache`): an unchanged source keeps its tree and node ids, and a changed one is parsed with ids after the highest so far, so a package's ids are no longer one gapless sequence there. After a change the server checks the bodies of the changed modules only, and also of every module that imports them, directly or not, when the change touches more than the bodies of non-generic functions (its tokens without those bodies differ). The other modules are declared but their bodies are skipped (`Body.checkModules`), and their errors come from the last check, per file and per phase (check, unused, effects). The published diagnostics are those of a whole check. The whole package is checked again on the first check, when the module list changes, when a generic struct default or generic function instance has an error, when an effect error is present, or when an error lies outside every module file. Navigation still loads and checks the whole package per request.
- `narrac lsp --full` checks the whole package on every change; `--trace` writes `check: whole package`, `check: modules <files>` or `check: no module changed` to the standard error for each check. The `lsp` suite runs each `incremental_*` case with `--trace` (the lines are in `expected.txt`) and again with `--full`, and requires the same protocol output.
- Diagnostics go to the package's modules, in package order. A load error goes to its file, or to the top of the changed document when it has no file. A document outside `src/` is not a module of the package, so it gets no diagnostics of its own. A document that had problems and is not mentioned in the next check gets an empty list.
- `didClose` rechecks from disk and sends the closed document one empty list, after the lists of the other modules.
- The server logs nothing unless `--trace` is given. Stdout carries only protocol messages.
- The `lsp` suite runs `testdata/lsp/<case>/session.txt`, a scripted session that the runner frames, and compares the server's output with `expected.txt`. The format is in the comment at the top of `selfhost/tests/src/lsp.nra`.

## Tests

```sh
sh scripts/test.sh                      # build narrac from the seed, run every suite
NARRAC=/path/to/narrac sh scripts/test.sh --suite errors
sh scripts/linux-check.sh               # the same in a Linux container
```

The test runner is written in Narra (`selfhost/tests`). `scripts/test.sh` builds it with narrac and runs it in shards. Every sample runs under AddressSanitizer, UndefinedBehaviorSanitizer and the leak check. `--suite NAME`, `--filter TEXT` and `--update` (rewrite goldens) go to the runner. Each sample in `testdata/errors`, `testdata/stage2/errors` and `testdata/packages/errors` has a golden with narrac's full `check` output: `<name>.err`, or `expected.err` inside a package folder. The `// error:` lines stay as documentation.

`scripts/linux-check.sh` runs `sh selfhost/bootstrap.sh` and `scripts/test.sh` in a Linux container (gcc with sanitizers, repo mounted read-only). Docker runs through colima on macOS: `colima start --cpu 4 --memory 8` first, and work from a path under your home folder.

- `testdata/*.nra` run and compare their output with the matching `.out` file. Each runs twice: a debug build with AddressSanitizer, UndefinedBehaviorSanitizer and the leak check, and a release build.
- `tests.nra` and `testdata/std_test*.nra` run their `test` blocks (`narrac test`) instead of an entry function. The `std-tests` suite checks failing `std/test` assertions.
- `testdata/panics/` must panic with a given message and exit code 101.
- `testdata/errors/` must fail to compile. The first line, `// error: text`, gives text the error must contain.
- `testdata/packages/*/` with a `run.out` build the package's binary, run it in both modes like `testdata/*.nra`, and run its tests.
- `testdata/packages/errors/*/` must fail to compile. The first line of `narra.toml`, `# error: text`, gives the text.
- Standard modules written in Narra live in `std/src/`. `selfhost/src/stdtext.nra` embeds their text and is generated from them; the `generated` suite fails when it is stale (`sh scripts/test.sh --suite generated --update` rewrites it, then `sh scripts/seed-update.sh`). The C runtime of the compiler lives in `selfhost/runtime/` and `selfhost/src/runtimetext.nra` is generated from it the same way. Samples that use the newest std modules are in `testdata/stage2/*.nra` (with `.out`) and `testdata/stage2/errors/*.nra`.
- `std/internal/<name>` modules hold the primitives behind std source modules. Only `std/...` modules import them (E0426). `std/internal/probe` is a test-only primitive in `selfhost/src/stdlib.nra` (the same code as `Char.code`).

## Supported

- The prelude has the types `Array`, `Map`, `Range`, `Box`, `Option`, `Result` and the functions `print`, `assert`, `panic`. The functions `Array.*`, `Map.*`, `Range.*` and `Box.*` come from `std/array`, `std/map`, `std/range` and `std/box` and need the import (error E0908, with an add-import fix; D67). By convention the aliases are plural: `import * as Arrays from "std/array"`, `Maps`, `Boxes`, `Ranges`, `Options`, `Results`. An alias may not equal a type name, two imports may not share an alias, and `import { map as mapOption }` renames a name (D72).
- Integer conversions (D82): modules `std/i8`, `std/i16`, `std/i32`, `std/u8`, `std/u16`, `std/u32` and `std/u64` (aliases `I8` ... `U64`) have `from`, `tryFrom`, `wrap`, `toString` and `parse`; `std/int` has `from`, `tryFrom` and `wrap`. They are builtins in `selfhost/src/stdsized.nra`: `from` and `wrap` emit a C cast, `tryFrom` a range check. `from` on a type that can lose values is E0940, a non-integer argument E0941. `parse` reports a value outside the range with the range in the message.
- `bytes`: `Type.TBytes`, C `lstr*` like `string`, so retain, release, `==`, hash and compare reuse `lstr_*`; `Show` is `narra_show_bytes` (`runtime.h`). `std/bytes` is `selfhost/src/stdbytes.nra` with the runtime `selfhost/runtime/std_bytes.c`; `Fs.readBytes` and `Fs.writeBytes` are in `stdfs.nra` and `std_fs.c`. `bytes` does not implement `Shape`.
- `f32`: `Type.TF32`, C `float`. A float literal is typed from the wanted type (`checkFloatLiteral` in `exprs.nra`; the range check against 3.4028235677973366e38 reads the digits, E0297) and emitted with an `f` suffix. `F32.from`, `F32.truncate`, `F32.toString` and `Float.from` are builtins in `selfhost/src/stdf32.nra`; the runtime has `lstr_from_f32`, `narra_eq_f32` and `narra_cmp_f32`.
- `std/option` and `std/result` (`import * as Options from "std/option"`) have the helpers `Option.map`, `andThen`, `withDefault`, `orElse`, `isSome`, `isNone`, `okOr` and `Result.map`, `mapErr`, `andThen`, `withDefault`, `ok`, `err` (D69). The callbacks are non-escaping, their effects flow to the call (`Builtin.Callbacks`), and a capturing arrow function gets a stack environment. There is no `unwrap` or `expect`.
- `std/math`, `std/time`, `std/random` and `std/hash` are Narra source (`std/src/`). Their primitives are `std/internal/math` (rows built by `internalMathFuncs` in `stdinternal.nra`; each calls the `math.h` function of its name, linked with `-lm`), `std/internal/clock` (`selfhost/runtime/std_clock.c`) and `std/internal/entropy` (`std_entropy.c`). `std/random` is SplitMix64 on a `u64`. `Ranges.stepped` is the builtin `Range.stepped` (`stdrange.nra`); a `narra_range` holds `low`, `high` and `step`, and a loop over a Range value advances with `narra_range_advance`, which ends the loop instead of overflowing. The parser accepts `of` as a function name and after `.` (`parseMemberName`, `parseFuncHeader`), so `Hash.of` works.
- `std/build` (SPEC section 12, D95) is Narra source (`std/src/build.nra`): the enums `Os` and `Arch` and the constants `os`, `arch` and `debug`, written with stand-in values. The driver picks a `BuildTarget` (`selfhost/src/buildtarget.nra`: `Build.hostTarget()` of the compiler, or `NARRA_HOST_TARGET=<os>-<arch>`, matched against the `TARGETS` table, read only when the package imports `std/build`; the language server caches it in `CheckCache.hostTarget`), and `checkModules` (`body.nra`) stores it in `Checker.buildTarget` and replaces the stand-in values in the module's AST before declaring it (`applyBuildTarget`, `buildconditions.nra`). `checkIf` (`stmts.nra`) records a condition made only of these constants in `Checker.foldedConditions` (condition expression id to the branch kept), and `emitIf` (`emitstmts.nra`) writes only that branch. `narrac emit`, `check` and the language server use a debug build for the host; dumps and `narrac query` use no target, so nothing folds there.
- `@target(os = ..., arch = ...)` (SPEC section 12) before a top-level function: the parser keeps it in `FuncDecl.target`, `declareFunc` resolves it into `Checker.functionTargets` (`resolveFunctionTarget`), `recordBuildCondition` records the source range of each dropped branch in `Checker.droppedRanges`, and `checkTargetUse` (called from `checkFunctionCall` and `checkFunctionValue`) reports E0991 for a use the target compiles. `narrac check --all-targets` checks the package for each row of `TARGETS` in a debug and a release build, prints each diagnostic once in source order, and merges the targets of one E0991 into its message (`checkEveryTarget`, `driver.nra`).
- A builtin std module can have a Narra part (`std/src/ext__<name>.nra`, module path `std/ext/<name>`): `extensionScope` and `memberScope` (`selfhost/src/scopes.nra`) find it after the builtins, and `addStdImports` loads it whenever `std/<name>` is imported. It holds `Float.PI`, `Int.compare`, `Int.divmod`, `Int.floorDiv` (an `Option`, so no divisor proof), `Str.find`, `Arrays.map` and `Arrays.slice`. `Arrays.withCapacity` is a builtin (`checkArrayWithCapacity`). A user can import `std/ext/<name>` too; that is not blocked.
- `std/shape` and `std/json` (D83) are Narra source (`std/src/shape.nra`, `std/src/json.nra`). `std/json` reads the text of a float through the primitive `FloatText.parse` of `std/internal/float` (`strtod`); `Float.toString` already gives the shortest text that reads back. `Json.parse` recurses only on nesting, which is capped at 512. A std source module comes after the std modules it imports, in single-file packages too (`addStdImports` in `selfhost/src/modules.nra`).
- `Shape` (D84) is a trait declared in `std/src/shape.nra`. The prelude implementations are private functions of that file (`intToValue`, `arrayFromValue`, `tuple2ToValue` and so on). In `checkTraitCall` (`calls.nra`), a `Shape.toValue` or `Shape.fromValue` call whose `Self` has no `implement` block and is a prelude type gets `Ref.Function` of the matching function, with a generic instance made by `addFuncInstance` for `Array<T>`, `Map<string, V>`, `Option<T>` and tuples (`setShapeRef`). `typeImplements` answers for `Shape` in `shapeImplements` (`traits.nra`), and E0530 replaces E0524 and E0525 for it. `checkBounds` returns false when a bound fails, and the call then makes no instance, so the generic body is not checked with a type that cannot fill it.
- `derives Shape` works on structs and enums, generic ones too. The loader (`addShapeDerives` in `selfhost/src/deriveshape.nra`) writes Narra functions `__shapeToValue_<Type>` and `__shapeFromValue_<Type>` for each such type, parses them after the file's last line and appends them with hidden imports of `std/shape` (as `__Shape` and `__Value`) and `std/string`; a bare `derives Shape` finds the trait through the hidden import, so the module need not import `Shape`. `setShapeRef` points a Shape call on the type at them, with an instance for a generic type. The body checker skips them when the derive is in error, so a bad field is reported once: E0531 for a field type without Shape, E0532 for an enum constructor field named `type`. E0533 reports the derived Shape of an opaque struct used from another module (checked at trait calls and `T: Shape` bounds outside instance bodies). In a file that derives Shape, the source may not name `__Value` or a name that starts with `__Shape` or `__shape`, as an identifier or inside a template: each is E0203, the error for an unknown name (`findHiddenShapeName`).
- Packages with several modules and `narra.toml`, or one source file. `import * as X from` and `import { a } from` for `std/int`, `std/float`, `std/string` and the modules of the same package. `export` on functions, structs and enums; other names are private. Import cycles are errors that list the cycle.
- `std/fs` (`readText`, `writeText`, `exists`, `listDir`), `std/process` (`run`) and `std/env` (`get`, `args`). Fallible functions return `Result<T, string>`; the string is `<subject>: <reason>`. `writeText` returns the byte count, `listDir` the sorted names (Err for the whole listing if any entry name is not valid UTF-8), `Process.run(command, args)` returns `#[exit code, stdout, stderr]` (stdin closed; killed by signal gives 128 + signal), `Env.get` returns `Option<string>`, and `Env.args()` equals the entry function's `args`.
- `std/fs` also has `isDir`, and `createDir`, `createDirAll`, `removeFile` and `removeDir`, which return `Result<bool, string>`: `Ok(true)` when the call changed the filesystem, `Ok(false)` when `createDirAll` found the directory already there, Err otherwise (with the path in the message). `std/io` reads stdin through C `FILE*` only: `Io.readLine()` returns `Result<Option<string>, string>` (the line without `\n`; a `\r` of a `\r\n` line stays, so the caller trims it; `None` at the end of input), `Io.readBytes(count)` exactly `count` bytes (Err at an early end, a negative count or invalid UTF-8), `Io.readAll()` the rest; `Io.write` and `Io.writeError` write to stdout and stderr without a newline and `Io.flush` flushes stdout. `std/path` follows Node.js `path.posix`: `join(left, right)`, `dirname`, `basename` (no suffix argument) and `extname`; `/` only, pure string work.
- `std/string` also has `slice`, `sliceFrom`, `byteAt`, `charAt`, `nextChar`, `charCount`, `indexOf` (returns `Option<int>`), `startsWith`, `trim` (ASCII whitespace), `split` (panics on an empty separator), `chars` (`Array<char>`) and a `StringBuilder` (`Str.builder()`, `Str.append(mutable sb, s)`, `Str.appendChar(mutable sb, c)`, `Str.build(sb)`). Slicing, `charAt` and `nextChar` panic on a position out of range or inside a character.
- `std/char` has `Char.code` and `Char.fromCode` (`Option<char>`). `std/int` also has `Int.parse(s, base)` (`Result<int, string>`, bases 2 to 36; no prefix, and a leading `+` or whitespace is rejected) and `Int.toHex`. `std/string` also has `endsWith`, `contains`, `replace` (an empty `from` returns `s` unchanged) and `join`.
- Names from a namespace import: calls `X.f(...)` and types `X.T`. Named imports bring functions, and structs and enums. Constructors come with their enum and are always written qualified: `Shape.Circle(1)`, `Geo.Shape.Circle(1)`, in expressions and in patterns (D71). `import { Circle }` of a constructor is E0425.
- Functions, `const`, `let`, `if`, `while`, `for (const x of Range.upTo(n))`, `Range.between(a, b)` and `Array.values(items)`, `Array.entries(items)` (yields `#[index, item]`), `for ... of` over any `Range` value, any `Array<T>` value and `Str.chars(s)` (a `Range` is the type `Range`: two ints, usable in a `const`, a field, a parameter or a result; `Array.values` and `Array.entries` outside a loop head are error E0920), `for (const #[i, x] of ...)` and `for (const { x, y } of ...)` heads (the parser rewrites them to a hidden loop name `__for_<line>_<column>` and a `const`/`let` declaration at the top of the body), `break`, `continue`, and the C-style `for (let i = 0; i < n; i = i + 1)` and `for (;;)` (D76; step is an assignment or a call, `++` and compound assignment come with compound-assign).
- Block expressions and `if` as a value (D75, SPEC.md section 2): a `{ ... }` in value position gives its value with `return`, which ends the block and not the function; `break` and `continue` cannot leave it (E0932), every path must end in `return value` (E0931) and a block with no `return`, such as `const o = { a }`, is E0933. `if (c) { ... } else { ... }` in value position needs the `else` and is parsed into a block expression holding an `if` statement whose branches each return a block expression. `{}`, `{ ...s }` and `{ name: value }` stay struct literals typed from context.
- Conditional expression `c ? a : b` (D75, SPEC.md section 2): parsed into a block expression holding an `if` whose branches each return one value; `return c ? a : b` is parsed into an `if` statement so a self call in a branch is a tail call. A missing `:` is E0934.
- `int`, `f64`, `bool`, `char` and `string`.
- Structs with constant field defaults, typed literals (`Point { x: 1 }`) and literals typed from context.
- Type arguments on map and generic struct literals: `Map<string, int> {}`, `Pair<int, string> { a: 1, b: "x" }` (D68). The checker resolves them like an annotation and reports E0237 when they differ from the expected type. Function types are not accepted inside them.
- Enums with fields, and `match` as a statement or a value, with guards and `_`.
- Patterns in `match`, `is` and `const`: nested constructors (`Some(Node(a, 0))`), struct patterns (`{ x: 0.0, y }`), tuple patterns (`#[a, Some(b)]`), literals (`0`, `-1`, `1.5`, `"a"`, `'c'`, `true`), bindings and `_`. `match` works on any value and checks exhaustiveness through nested enums, bools, structs and tuples.
- Or-patterns (D98) in `match` arms and inside patterns. The first alternative declares the locals; later alternatives resolve on their own, are checked against the first, and then their nodes point at the first one's locals (the locals they created stay unused). The emitter declares the locals before the test and assigns from the first alternative that matches. A pattern in `const`/`let` stays refutable unless one alternative always matches. An unreachable alternative is reported only for alternatives of an or-pattern; a plain arm that earlier arms cover is not reported.
- Destructuring: `const { host, port: serverPort } = config` and `const #[q, r] = divmod(a, b)`, nested too.
- Array patterns (D103) in `match`, `is`, `const`, `let` and `for ... of`: `[]`, `[x]`, `[first, ..._]`, `[first, ...rest]` over `Array<T>` and `FixedArray<T, N>` (`selfhost/src/arraypatterns.nra`, `emitarraypatterns.nra`). Lengths are constructors in the usefulness matrix. The emitter tests `->len` once and reads `->items[i]` (or `.items[i]` of a FixedArray) without a bounds check; a named rest is a new Array built with one allocation and a retain per element, owned by its local even in a `match` arm. A generic instance repeats its declaration's checks, so in an instance body a FixedArray length mismatch is not reported, no `match` is judged again for exhaustiveness or unreachable arms (the declaration's own body judged it), and an arm whose length cannot match emits a `false` test.
- Spread updates: `{ ...s, field: v }` and `Point { ...s, x: 1.0 }`.
- Tuples: the type `#[int, string]` (in every type position), the literal `#[a, b]`, and `const #[a, b] = t`. Tuples implement the standard traits when their elements do.
- `Array<T>`: literals, `Array.push`, `Array.length`, `Array.filled`, indexing and element assignment, with copy on write.
- `mutable` parameters, with the exclusive access check.
- Generic functions, structs and enums. Type arguments are inferred from arguments, the expected type and struct fields.
- `Option<T>` and `Result<T, E>`, declared in a prelude written in Narra.
- `is` patterns in conditions. `if (x is Some(v))` binds `v` in the branch. After `if (x is None) { return ... }`, `x.value` reads the value. Narrowing works on constants and parameters.
- Calls whose `Result` is not checked are compile errors.
- Template strings.
- Integer overflow wraps in every build (D92); bounds checks panic in every build. Integer `/`, `%` and shifts compile only with a proven divisor or count (D92, E0979 and E0980), so the emitted C has no division or shift panic.
- `requires` lines (D95, D102, SPEC.md section 13) between a signature and its body: clauses joined by `&&`, each a comparison or comparisons joined by `||`, of an integer parameter with an integer constant or with another integer parameter of the same type (a relation). E0984 for other conditions, with the rewritten condition for `!`. Each call proves one comparison of each clause from constants, narrowed names and relations (E0985) after every body is checked; the body starts with the clauses as facts, the hull for a `||` clause over one parameter. D92 checks give the same hull for a `||` over one local, and record relations between two integer locals that pass bounds one step (`selfhost/src/operands.nra`). A function with `requires` cannot be a value (E0986) or a `typeof` (E0982), nor be in an `implement` block. Code: `selfhost/src/contracts.nra`.
- `ensures` lines (D95, SPEC.md section 13) after the `requires` lines: a pattern each `return` value (each `yield` value of a generator) must match, proven where the value is checked (E0988): constructors, tuples and struct literals written in place, literals written the same, and comparison patterns (`>= 0`, `!= 0`, only in `ensures`; a caller learns non-zero from `!= 0` and nothing from another `!= c`) from integer facts. A comparison needs an integer place and a constant bound that fits its type; the pattern binds no names, and the function returns a value (E0987). A caller learns the pattern as facts about integer locals: `const n = f()`, `let n = f()` until assigned, the bindings of `f() is P`, of `match` arms and of destructurings, `r is P` for a `const r = f()` whose type has no contents, and the loop name of `for (const n of g())`. A direct `return g(x)` is not proven from g's `ensures`.
- Constant type parameters (D95), `const N: int` on functions and structs: the argument is an integer literal or a constant parameter in scope, inferred like a type argument or written (`repeat<3>(x)`, `Vector<2>`). An instance binds the parameter to `Type.TConst(value)`, which is part of the instance key and of the hashed C name, so each value is its own instance. In the body the name is an `int` known per instance (`Ref.ConstantParameter`), which the prover uses for divisors, shift counts and comparisons; the generic declaration leaves those checks to its instances. E0992 for the declaration and syntax (kind other than `int`, an enum or alias, arithmetic in a type argument), E0993 for an argument of the wrong kind. Code: `selfhost/src/constgenerics.nra`.
- Fixed arrays (D95), `FixedArray<T, N>`: a C struct holding `T items[N]` (one unused item for `N` of 0), stored and passed like a struct, with no heap allocation. A literal builds one when the expected type is a `FixedArray`. Indexes have no runtime check: a constant index is checked against `N`, and any other index must be a plain `int` local whose facts put it in `[0, N - 1]`: from `if` and `while` conditions, from the condition of a C-style for loop (a `let i = c` counter stepped by `i++` or `i += c` that the loop does not otherwise assign is at least `c`, when the condition bounds it with `<` so the step cannot wrap), and from `for (const i of Ranges.upTo(n))` or `Ranges.between(a, b)`. In a generic declaration with an open `N` the proof waits for the instances. `std/fixedarray` (Narra source) has `get` and `length`. One FixedArray value takes at most 1048576 bytes (1 MiB), so a local stays well inside a default thread stack and C accepts the array; a larger one is E0995 where its type is written, or at the struct that holds it when a generic instance or a later struct makes it large. E0994 for an index, E0995 for a length, a size or a literal. Code: `selfhost/src/fixedarrays.nra` (proofs), `selfhost/src/emitfixed.nra` (C).
- `test` blocks and `assert`. `std/test` (inside test blocks only): `Test.eq`, `Test.ne`, `Test.panics(f)` and `Test.panicsWith(f, message)` and `Test.golden(name, actual)`. A failed assertion panics with the call's position and both values written with `Show`. `narra test` runs each test in its own process, prints `ok - name` or `FAIL - name: message (file:line:col)`, then `N passed, M failed`, and exits 1 on a failure. `-filter text` runs the tests whose name contains the text and `-time` adds the milliseconds of each test. A test that runs past 10 seconds (or `NARRA_TEST_TIMEOUT`) fails with `timed out`. A filter with no match exits 1 (D66).
- Reference counting for strings, arrays, and structs and enums that hold them.
- Constant parameters over 16 bytes are passed by pointer (D50): direct calls, generic instances, trait implementations, function values, arrow functions, tail calls and the retain and release functions of large types. Reads of fields and elements still copy.
- An enum with fields is a tagged union held by value, unless a variant field contains the enum again through structs and enums held by value, or its largest variant is over 32 bytes (fields rounded up to 8 bytes). Those keep a counted, shared payload on the heap (D55, D99). The layout is chosen per generic instance in `decideHeapEnum` (`selfhost/src/check.nra`).
- Arrow functions `(x: int): int => x + 1` and `(x) => { ... }`, function types `(x: int) => int`, named functions as values (`apply(double, 1)`, `Alias.f`), calls through function values (`f(x)`, `make()(x)`, `button.onClick(x)`), and captures of constants. A closure passed straight to a non-escaping parameter also captures `let` variables and `mutable` parameters by reference (D77). Parameter types of an arrow function come from the expected type, also through a generic call such as `map(items, (x) => x * 2)`.
- `escaping` function parameters. A non-escaping closure keeps its environment on the caller's stack; an escaping one has a reference-counted heap environment.
- The `from` result marker (D94, SPEC.md section 6, Shared results) on declarations, arrow functions and function types: `function first(items: Array<T>): T from items`. A returned value that shares a parameter the marker does not name is E0976, with a fix that adds `from` or wraps the value in `copy(...)`; a function with `from` stored in a slot without it is E0977, with a fix that adds `from` to the slot's type. The check is one walk per body after it is checked (`selfhost/src/sharedresults.nra`). A std builtin's result counts as fresh, except that `for ... of` over a std iterator shares what it walks.
- The shared-write rule (D94), error E0978: a write to a place while another live name shares it or a place that contains it. Every command that checks a package runs it (`build`, `run`, `test`, `emit`, `check`, `apply-fix` and `narrac lsp`), also when the package has other errors; a write that another error already points at is not reported again. The fix wraps the value that started the sharing in `copy(...)`. One forward walk per body after the package is checked (`selfhost/src/sharedwrites.nra`). A function value made from an arrow function shares what it captured, so calling it uses those values. Two different integer literal indexes (`grid[0]`, `grid[1]`) are different places; any other index may name any element. A `const` or `let` holds its value until its block ends (D104), so a write that would copy an array, map, `Box`, `StringBuilder` or generator it shares is an error after its last use too.
- Traits: `trait`, `implements`, `implement Trait for Type`, `derives`, constraints such as `<T: Show & Ordered>`, and calls through the trait name such as `Show.show(x)`.
- The standard traits `Equatable`, `Hashable`, `Ordered` and `Show`, and the `Ordering` enum. `==` and `!=` work on structs, enums and arrays.
- Effects: exported functions must declare `uses alloc, io, unsafe` for everything they do; private functions and arrows are inferred; `<effect E>` and `uses E` on function types work. Function types carry their effects (D86): a function with fewer effects fits a slot that allows more, a store of one with more is a type error, and a call through a value charges the effects of its type. A function type inferred from an arrow or a name lists no effects, so a type argument inferred from such a value is pure; write the type to store an effectful one in a generic. On an exported function a function-type parameter without `uses` accepts only pure arguments; on a private function it acts as an implicit effect variable. `alloc` also comes from array literals, template strings, string `+` and constructors with fields. A function with effect variables used as a value keeps them (D91): a call through the value binds each variable to the effects of its arguments.
- Opaque structs and distinct types: `export opaque struct`, `distinct type A = B`, `export opaque distinct type`. Another module cannot build, read, assign, spread or match the fields of an opaque struct. `A.from(x)` and `A.toInt(x)` (`toString` for a string base, named after the base type) are generated and emit no code. A distinct type lists traits like a struct (`distinct type A = B implements T derives Show`); a derived trait uses the base type's functions, and an `implement` block is the type's own. `opaque`, `distinct` and `type` are contextual words, not keywords.
- Generators (SPEC.md section 8): `function*`, `yield`, `yield*`, `Generator<T> uses E`, generic generators and `for ... of` over a generator. Each `function*` is a state machine over a heap frame with a counted header (`narra_gen` in `runtime.h`): every C variable of the body is a frame field, and the drop and clone functions switch on the state to release or retain what is live at that yield. Every `Generator<T>` is the C type `narra_gen*`. A `for ... of` and a `yield*` resume their own copy, so iterating a generator variable twice runs it twice.
- Coroutines (D79): `Coroutine<In, Out>`, `const input = yield value` and `Co.resume` from `std/coroutine`. A coroutine is the same state machine as a generator; the resume input reaches the body through `narra_gen.in`, set by `narra_co_next` (`runtime.h`). `std/coroutine` is Narra source (`std/src/coroutine.nra`: the `Step` enum and `resumeGenerator`/`resumeCoroutine`) over the primitives of `std/internal/coroutine` (`selfhost/src/stdcalls.nra`, `selfhost/src/emitstd.nra`). The compiler maps `Co.resume` to one of the two by argument count (`moduleCall` in `selfhost/src/calls.nra`). In a test build `narra_co_next` catches a panic with `setjmp`.
- `std/lazy` (lazy-values): a compiler module, not Narra source, because `Lazies.force(name)` reads the getter of a top-level `const name = lazy expression`. The name has the type of the expression with a lazy flag on the declaration (`ConstDecl.lazyPos`), and any use but the argument of `force` is E1033. The checker skips the constant-expression rule for it; the effect pass gives a force the effects of the expression (E1034 for anything but `alloc`) and finds forcing cycles (E1035) over a graph of bodies; rules in `selfhost/src/lazyvalues.nra`, the module in `selfhost/src/stdlazy.nra`. The getter and `narra_consts_release` are those of D61, and reachability is by the getter name, so an unforced lazy value emits no C. Forcing is not thread safe; the threads node must add the once guard here as for other constants. A builder cannot print (E1034), so no sample counts its builds.
- `Cell<T>` (D90): `std/cell` is Narra source (`std/src/cell.nra`), an `opaque struct Cell<T>` over a `Box<T>`, with `create`, `get`, `set` and `update`. `set` and `update` write the box in place through the primitive `std/internal/cell` `store` (`CellSlot.store`, `selfhost/src/stdinternal.nra`), which skips the copy a write to a shared box makes. The type is `import { Cell }` and the functions are `import * as Cells`, not a prelude `Cell.*`. The checker does not keep a `Cell` off threads, because threads are not built. A bare `None` argument of a generic call takes its type from the earlier arguments (`hintNone`, `selfhost/src/closures.nra`). The `leaks` suite runs `testdata/leaks/*.nra`, which must print their `.out` and fail the leak check with exit code 102.

- Top-level `const` (`export const` too): literals, operators on constants, constructors, structs, arrays, maps, function names and other constants, in any order; cycles are errors. Scalar constants are emitted at each use. Other constants are built on first use (see Differences).

## Unsafe code

- `unsafe { ... }` is a `Block` with `isUnsafe` set, parsed as a statement when the identifier `unsafe` is followed by `{` (`parseStmtBody`), so `unsafe` stays an effect name. fmt prints `unsafe ` before the block; astdump adds the `unsafe` flag to the `block` line.
- `Ptr<T>` is `Type.TPtr(element)` (key `R(...)`, C type `T*`), resolved in `resolveType` when the module imports `std/ptr` (`importsPointers`, `selfhost/src/unsafecode.nra`). The element is checked once every struct has its fields (`flushPointerElements`, run from `flushMapKeys`): E0998 unless it is a number, `bool`, `char`, a `Ptr`, or a `FixedArray` or struct of those.
- `std/ptr` (`selfhost/src/stdptr.nra`, emitters in `emitpointers.nra`): `alloc`, `free`, `read`, `write` and `offset` have the `unsafe` effect; `null` and `isNull` are safe. `Ptr.alloc` uses `narra_alloc` and zeroes the memory, so the leak check counts it.
- The effect pass (`effects.nra`) collects each call's own effects apart and reports E0996 for a call with `unsafe` outside an `unsafe` block (`EffectState.unsafeDepth`). `@trusted` (`KNOWN_ATTRIBUTES` row, no arguments) drops `unsafe` from the function's inferred set; `checkTrusted` reports E0997 for `@trusted` without an `unsafe` block or with `uses unsafe`. `@trusted` is the one attribute allowed on an implement block member (`parseAttributeList` in `parseImplDecl`).
- `extern { ... } from "library"` (`parseExternBlock`, `parser.nra`, when the identifier `extern` is followed by `{` at the top level): each member becomes a top-level `FuncDecl` with `externBlock: Some(ExternBlock)` (shared by the block's members), no body and `effects: ["unsafe"]`, so declarations, calls, function values and the effect pass need no new case. A member takes only `@extern("name")` (a string `AttributeArgument.text`). `funcEffects` reads a member's declared effects. `checkExternFunctions` (`selfhost/src/externs.nra`, run at the end of `checkEffects`) reports E1002 for parameter and result types other than numbers, `bool` and `Ptr`, and E1001 for a C name that is not an identifier or matches a name the compiler writes. The emitter (`emitexterns.nra`) writes no body for a member and declares it `extern <type> <generated name>(...) __asm__(NARRA_C_SYMBOL("<C name>"))`, so headers that declare the same function with other C types do not clash. `EmitResult.libraries` lists the libraries of reached members (not `c`); the driver passes them as `-l` after the C file. fmt prints the members of one block together (trivia key `x<pos>`); astdump adds an `.externBlock` slot to each member.
- `narrac audit [path]` (`audit.nra`) walks the parsed files of a package and prints the `unsafe` blocks (at the keyword) and `@trusted` functions (at the attribute), sorted by file, line and column; a trait or implement member is named with its trait or implementation (`writeType` from `querysignature.nra`). Comments between an extern block's `}` and `from` attach to the trivia record `r<pos>` of the closing brace. `ExternBlock.attributes` holds the `@target` written before a block; fmt prints it before `extern` and skips the copies on the members.
- `std/cstring` (`std/src/cstring.nra`): `CString` is an opaque struct over a string without zero bytes; `pointer` and `read` use the primitives `CText.pointer` (the string's zero-terminated `data`) and `CText.read` (`lstr_from_cstr`) of `std/internal/cstring` (rows in `externs.nra`, emitters in `emitexterns.nra`). The parser accepts `from` as a function name, like `of`.
- A `for` loop or `yield*` over a generator whose body has `unsafe` is E0996 outside an `unsafe` block (`walkGeneratorRun`). An implement block member may use `unsafe` only when its trait function declares it (E0800, `checkImplementationEffects`), and a `Trait.f(value)` call on a type parameter has the effects the trait function declares (`addTraitCallEffects`).

## Type aliases

- `type Name<T> = Body` and `export type`. A non-generic alias is entered in the module's type table as its resolved type, so constructors, patterns and struct literals work through it, also across modules. A generic alias is resolved again at each use with its arguments, so constructors through a generic alias (`Alias.Ctor`) are not available. Self reference and cycles are E0972, a wrong argument count is E0973. Diagnostics print `Alias (Type)` for a struct, enum or distinct type once an alias of it was used anywhere in the package, even where the source wrote the type name.

## @inline

- `selfhost/src/inlining.nra` checks the rules after every body: E1030 for an `@inline` function that reaches itself through `@inline` calls, E1031 for a generator. The parser reports E1031 for an extern block member. `selfhost/src/emitinline.nra` writes each call: the arguments into C temporaries in the caller, then the callee's body in a C block whose `return` stores the result and jumps to a label after it, reading the callee's side tables. An arrow argument for a parameter the body only calls (never inside an arrow, never passed on) is written where the body calls it, back in the caller's state. Loop labels in a copy get a suffix per copy. A generator caller writes the copy's locals as C locals, since no `yield` runs inside a copy.

## @const functions

- `selfhost/src/constfunctions.nra` checks each `@const` declaration after the effect pass (E1050 signature, E1051 effects, E1052 calls). `selfhost/src/consteval.nra` then computes every constant whose value calls an `@const` function, walking the checked syntax with each body's side tables, and keeps the result in `Checker.constValues`. The locals of the open calls are one array of slots; a write or a `mutable` argument moves the value out of its slot and back, so a push into a local array does not copy it. Std rows call the same std function inside the compiler after checking the conditions under which it would panic, and charge the memory budget from the arguments first. The driver, `narrac emit` and the language service run both after the effects. `selfhost/src/emitconstvalues.nra` writes the result: a scalar at each use (`isStaticConstant`, `constRef`), anything else in the D61 getter (`emitGetter`), with an array of scalars as a `static const` C array and one `memcpy`.
- The evaluator recurses on the compiler's C stack. Besides the 1000 nested calls, the calls, blocks, loops and expressions under way across all open calls may nest 5000 deep (E1056); a loop counts as a level of its own because it takes more stack. Measured on a release build: a level takes about 600 bytes on macOS (clang) and 900 on Linux (gcc), where an if-heavy body overflowed an 8 MiB stack near 9100 levels; 5000 keeps both near half of 8 MiB. Six nested additions per call allow about 600 calls. A computed value may nest 1000 levels (E1056), because the C writer recurses once per level; equality and map keys walk values with their own stack. A compiler built without optimization (`-O0`) uses about three times as much stack per level and can still overflow before the limits.
- Errors of a computation (E1053 to E1057) are one diagnostic at the constant whose message carries the call chain as `file:line:column: note: ...` lines; a call repeated by a recursion is one note with its count.
- A float literal is read exactly only when its significant digits fit in 53 bits and its power of ten is at most 22 after trailing zeros move into the exponent. An f32 literal is read as an f64 and rounded to f32; when the f64 read was inexact and lies halfway between two f32 values, the double rounding could differ from C's reading, so the literal is refused (E1052). f32 arithmetic rounds each result to f32.
- An array of strings in a computed value is still written as one store per element; pointing at the static string literals is a follow-up.

## typeof

- `typeof name` in a type (D96) is `TypeExpr.typeofName` (`name` is empty); the parser reads it in `parseTypeBody` when `typeof` is followed by a name, and `SourceFacts.hasTypeof` tells `checkModuleBodies` to check the module's constants first. `resolveTypeof` (`selfhost/src/resolve.nra`) resolves a parameter written earlier in the same signature (`Checker.signatureNames`), a local or parameter of the body, a constant or a function. A function declared further down the file is resolved from its declaration, so aliases and signatures may use it. A name already being resolved by its own type is E0981 (`Checker.busy`, key `typeof|name`); a type, a module, a generic function, a function with effect variables or with a `mutable` parameter is E0982. A constant without a written type has no type in the declaration passes (they run before any value is checked), so a declaration of the same module needs the written type (E1003); bodies and other modules see the inferred type. `narrac fmt` and `narrac query` signatures print `typeof name` as written; hover shows the resolved type.

## Not supported yet

- In `@const` bodies: arrow functions, calls through function values, explicit trait function calls, `Map.update`, and the std modules `std/char`, `std/option`, `std/result`, `std/math`, `std/bytes`, `std/fixedarray` and the sized number modules (E1052). A float literal in an `@const` body with more than 18 significant digits or a power of ten past 22 that does not reduce to an exact integer is not read yet (E1052 at the constant).
- Dependencies on other packages, `narra.lock`, interface files (`.nrai`) and incremental builds.
- Effects: trait function calls to user implementations are not followed, and an implementation may use effects its trait function does not declare, except `unsafe` (E0800). Implementations of pure trait functions such as `Show.show` allocate in existing programs and in the guide; enforcing the subset rule for `alloc` and `io` waits for a decision.
- Threads and channels.
- Async I/O, first build (`std/async/net`, `std/async/file`): `host` must be a numeric IPv4 or IPv6 address, with no name lookup. A `std/async/file` call does the blocking read or write, so it blocks the loop for as long as the file call takes, then gives the other ready tasks one turn. TCP only: no UDP, no Unix sockets, no shutdown of one direction, no timeouts other than an `AsyncTime.sleep` raced against the call.
- `@layout` and C-callable functions (node c-abi-export).
- `std/test` on Windows: `Test.panics` and `Test.panicsWith` use `fork` and `alarm` (D65), so they are POSIX only. A closure that runs past the timeout (10 seconds, or `NARRA_TEST_TIMEOUT`) fails. The test runner (D66) forks per test, so it is POSIX only too. Report formats other than the text lines are not there yet.

## Differences from the spec

- Build conditions: the host is the only target (no `--target`); `narrac check --all-targets` is the only way to check another one. `@target` applies to Narra functions and to `extern { } from` blocks (the parser copies the block's `@target` onto each member, so the function checks apply and an unreached member links nothing), and a `@target` function is type-checked on every target, while tree shaking leaves it out of the C of a target where nothing compiled reaches it.
- The identity types (`Sender`, `Receiver`, `Shared`, `Atomic`) are not built either, so the contents-type check of a `mutable` parameter knows struct, `Array`, `FixedArray`, `Map`, `Box`, `StringBuilder` and `Generator`/`Coroutine`.
- `for (mutable item of items)` (D85): an `async` body is E1105 and a `function*` body is E0957. The `#[index, mutable item]` head takes only that form, two names (`_` for the index too); other tuple patterns with `mutable` are parse errors. The borrow check compares names, not scopes, and an index matches any index, so `teams[0].players` overlaps a loop over `teams[1].players`.
- Fixed arrays: a literal argument does not tell a generic call its length, so `sum([1.0, 2.0])` with `sum<const N: int>(values: FixedArray<f64, N>)` is E0220; write `sum<2>(...)` or pass a typed value. A generic body cannot build a `FixedArray<T, N>` literal with an open `N` (E0995). `for (mutable item of values)` takes an `Array` only, not a `FixedArray`. A counter stepped with `i = i + 1` gets no proof; only `i++` and `i += c` do.
- Standard functions as values (`Int.toString`, `Str.length`, `Fs.readText`): only a function with a fixed signature is a value. A function whose types depend on the call (`Arrays.length`, `Maps.size`), one with a `mutable` parameter and one that takes a function (`Arrays.map`) are E1013; wrap them in an arrow function. The prelude functions `print`, `assert` and `panic` are not values either.
- Async (D109): at exit every unfinished frame releases what it holds before the loop drops any, which also frees a task that waits on its own handle through a `Cell`.
- `Co.resume` is not an importable name: `import { resume } from "std/coroutine"` is an error with a hint, and `Co.resume` works only through a module alias. A resume charges `alloc` for the `Step` payload besides the effects of the generator type. A panicked coroutine does not free what it held.
- A function that is not a `function*` and returns a generator type writes its own `uses` list after the type's (`(): Generator<T> uses io uses alloc`). A private function's `Generator<T>` parameter accepts only pure generators (D78).
- Storing a generator function in a function-type slot ignores the `alloc` that creating the generator charges, when the slot's result is a generator type: a function type cannot write that `alloc` apart from the generator's own `uses`. Instead, every call through a function value whose result type is a `Generator` or `Coroutine` charges `alloc` at the call (`holder.make()`, `pick()()`), whether or not the value is a generator function, because the type does not tell.
- Top-level constants that are not scalars (strings built by templates, structs, arrays, enums with fields, function values, and non-scalar results of `@const` functions) are built on first use, behind a getter, and kept until the program ends. The spec says modules have no initialization code; this keeps that, but the first-use build is not thread safe yet (the threads node must add a once guard). Struct and array constants are heap values, not static C data.

- An unused local or parameter is an error (E0921, E0922), and `_` or a `_` prefix marks it as unused on purpose. The `args` parameter of the entry function of a binary (the exported function that `narra.toml`, or the single-file build, names as entry) is exempt, because its signature is fixed; a `run` in another module is not. An assignment `x = v` does not read `x`, so a `let` that is only assigned is unused (`x = x + 1` reads `x`, and so do `p.x = 1` and `e[0] = 3` for `p` and `e`); a `mutable` parameter that is only written through (`out.total = 3`) counts as used, because the caller sees the write. The error is reported once per body, at the declaration (the `const`, `let` or `for` keyword, or the name of a parameter or pattern binding), and only when the body has no other error.
- An unused import name or module alias (E0946) and an unused private function (E0947) are errors, reported once the whole package checks clean. An import counts as used when its name is written anywhere in the module outside the imports and not after a `.`, so a struct field, a field key or a named argument with the same name also counts. A private function counts as used when a body other than its own refers to it (a function that only calls itself is unused); a function a binary names as entry, and the std/shape functions the compiler calls for `Shape` on prelude types, count as used. The import fix removes the name (or the whole import when no name of it is used); the function fix adds `_` to the name and its calls.
- `narrac check --json` ranges are positions only: `range.end` equals `range.start` for a diagnostic (fix edits have real ranges), and `file` is the base name for a single file.
- `Str.length` returns `int` instead of `ByteIndex`, and so do all string positions (`Str.indexOf`, `Str.slice`, `Str.nextChar` and the rest). Slices are copies, not views of the original buffer.
- Reference counts are removed in two cases only: a `for` item over an array borrows from the array the loop holds, and an `is` or `match` binding borrows from the subject the statement holds (the rules are in the comment at the top of `selfhost/src/emitstate.nra`). Every other copy updates the count. Moving a local into its last use and Perceus reuse of freed cells are not implemented.
- Generic functions and types are compiled once per set of type arguments in every build. The spec's layout tables for debug builds are not implemented.
- Generic function bodies are checked once with their type parameters left open, then again for each instance.
- One C file per program, not one per module. Declaration C names are `<kind>_<module hash>_<name>`, such as `f_3fa9c1e7_show`: the hash is xxHash32 (seed 0) of the module path relative to the package. Composite types (generic instances, tuples, function types, arrays) are interned as `<kind>_<head>_<hash>`, and a comment table in the C maps each to its Narra type. A single file `hello.nra` is module `"hello"`. A package cannot be named `std`.
- Modules are checked against the declarations of the modules they import, in memory. There are no `.nrai` files.
- Every line of a compile error starts with its file, as in `src/text.nra:3:4: ...`.
- Trait constraints do not compile to a hidden table parameter. Generic functions are compiled once per set of type arguments, so every trait call is a direct call, except a call through a `Dynamic<Trait>`, which reads the function from the table of the stored value's type.
- An `implement` block must be in the module that declares the type. The prelude (`Option`, `Result`, `Ordering`) and primitive and array types belong to no user module, so they cannot get `implement` blocks.
- Traits are imported by name (`import { Area } from "app/shapes"`). `Alias.Trait.f(x)` and `<T: Alias.Trait>` are not supported.
- A bare constructor is E0323 with a fix that writes `Enum.Name`, except `Some`, `None`, `Ok` and `Err`, which stay bare as prelude names. The fix picks the expected type's enum first, then the enum the module declares, imports or the prelude, in that order; when the module cannot name the enum in a pattern, the fix also adds `import { Enum } from "module"`. A bare name shared by two enums of one rank is E0324, with no fix. Two enums may share a constructor name; a duplicate name in one enum is E0194.
- `trait`, `implement`, `implements` and `derives` are keywords, so they cannot be used as names. `Ordering` (with `Less`, `Equal`, `Greater`) and the traits `Equatable`, `Hashable`, `Ordered` and `Show` are prelude names, like `Option`, so a program cannot declare its own type or trait with those names.
- `Hashable.hash(x)` returns `int`. `Hash.of(x)` is `std/hash` (`std/src/hash.nra`), which calls it.
- A function type carries no `escaping` marker, so the parameters of a function value are escaping: an argument passed through a function value must be escaping, and a parameter of an arrow function that has a function type may be stored.
- Only a parameter written with a function type can be non-escaping. A parameter whose type is a type parameter is escaping even when the type argument is a function type, so passing a non-escaping parameter to `id<T>(v: T)` is an error.
- An arrow function with a block body and no result type infers it from its `return` statements (void when none returns a value).
- Derived `Show` writes `Point { x: 1, y: 2 }`, `Some(1)` and `[1, 2]`, and quotes strings and chars inside: `"text"`, `'c'`. `Show.show` on a string quotes it too. A tuple shows as `#[1, "a"]`.
- A name in a pattern is a constructor when the matched value is an enum with that variant. Otherwise it binds a new name, except that a name starting with an uppercase letter is an error. The spec does not say how a pattern tells the two apart.
- `match` accepts any value, not only enums, and so does `is`. A match on `int` or `string` needs a `_` arm or a binding arm.
- `let { a } = s` is allowed and declares `let` variables. The spec shows only `const` for struct destructuring.
- A destructuring pattern must match every value (`const { x: 0 } = p` and `const Some(x) = o` are errors). A constructor works when its enum has one variant: `const Only(s) = u`.
- `Maps.update(mutable m, key, initial, change)` is a compiler builtin with a callback argument, like `Results.map`. A compound assignment on a Map index (`counts[key] += 1`) is rejected with E0226.
- `Map.keys(m)` and `Map.entries(m)` are arrays (of keys, or of `#[key, value]` tuples) outside a loop, not generators. `for ... of` over them reads the map directly and sees the entries as they were when the loop started. `Map.remove(mutable m, key)` returns `bool`. A `Map` has no `Equatable`, `Hashable` or `Show` yet, so it cannot be compared, used as a key or put in a `derives` struct. A key type must implement `Equatable` and `Hashable` together or neither, and the check looks at the key type and the fields inside it.
