# Log: async-api

- 2026-11-13: branch feat/async-api reset to feat/batch-12 (53a1f53a). async-core had `detach` and `idle`; nothing else of the node existed.
- Generic primitives need a check function (StdFunc rows have no type parameters), so `Tasks.then`, `cancel`, `finished`, `value` and `watch` use the check kind `checkTasks` (one `if` in `stdcalls.nra`). `emitAsyncCall` needs the walker to emit arguments, so its dispatch in `emitstd.nra` passes it.
- A `then` callback is stored as a closure over the finished handle, `(finished: Async<T>) => void`: its C function type is `void (*)(narra_env*, narra_task*)` for every `T`, so the runtime calls it with no per-type adapter. The source wrapper reads the value with `Tasks.value`.
- The closure runtime (`narra_env`) may come after the async runtime in the C file, so `std_async.c` names only `struct narra_env` and takes the release function as an argument (`narra_env_release` at the call site).
- `all` and `race` need a task whose value has the caller's type. A C task cannot build `Array<T>` or `Option<T>`, so both are `async { ... }` blocks in `std/src/async.nra`. The committed seed never compiles `std/src/async.nra` (it only builds `selfhost/`); the stage 1 compiler does. `race` awaits `Tasks.winner()`, a bare `Async<int>` that the first watcher sets to its index.
- Exit: `narra_async_exit` set `cancelled` directly, which left the callbacks of a task stuck at exit (a cycle through a callback that holds the handle). It now calls `narra_task_cancel`, one line in `std_async_loop.c`.
- `Async<void>` handles: `T` cannot be inferred as `void`, so no std/async function (also async-core's `detach`) takes an `Async<void>`. Not fixed here; listed for the orchestrator.
- Tests: `NARRAC=n3 sh scripts/test.sh --filter async`: PASS, 194 cases.
- Review of 250b129f: race watchers of losing inputs stayed in waiter lists (about 290 bytes per race). Fixed with a watcher list on the winner, swept when it settles; `narra_task_check_watchers` makes a stale watcher fail the leak check at exit (2000 stale watchers, exit 102, with the sweep removed).
- Rulings: `then` on a finished handle queues the callback (a `narra_task_later` in the ready queue); `Async<void>` binds `T` to void through `Async<T>`, void function-type parameters drop, and `peek`/`all`/`race` on void are E1150.
- Second review round: a void argument fills no parameter only in a generic instance body when its generic type is a type parameter; `g(voidCall())` stays E0316. Rebased on feat/batch-12 with event-loop (7b60aa95): generated files taken from the base and regenerated, `stdasync.nra` keeps both `Tasks.sleep` and this node's rows, `narra_task_cancel` calls `narra_loop_cancel_wait`, and the race winner gets a release of its own so the idle test in `narra_loop_cancel_wait` does not match it.
