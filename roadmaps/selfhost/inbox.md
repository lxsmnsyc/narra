# Inbox: selfhost

Ideas and gaps found during work, not yet nodes. Triage with the user.

- 2026-11-01, from the std-iterator discussion: async generators (`async function*`, "not in the first version" in SPEC section 8) would let `std/iterator` operators work on async streams, like IxJS AsyncIterable. Add time operators (`debounce`, `throttle`, `merge`) to `std/async` with them. Needs async and generators first.
- 2026-11-01, user direction: make closures more powerful and closer to TypeScript semantics after m11-closures. Candidates to weigh: inferring `escaping` where the cost is still visible in tooling, capturing `let` from escaping closures through an automatic `Cell`, and async closures. Each needs a decision record; run a goal debate before planning.
- 2026-11-05, from refining std-io-more: Path.basename suffix form (Node's basename(path, ext)) or a stem helper, if callers need it.
- 2026-11-07: named arguments decided (D87, `roadmaps/selfhost/debate/named-arguments/debate.md`): `move(x: 1, y: 2)`, any order, every argument passed. Planned as nodes after arg-eval-order. Parameter defaults are a separate debate, not started.
- 2026-11-07: async blocks and generator blocks parked (D88, `roadmaps/selfhost/debate/suspending-blocks/debate.md`). Rerun the debate when a program needs one.
- 2026-11-09, from effect-variable-values (D91): a function value with effect variables that passes through a generic type parameter still loses the variable's binding; the call through the value does not charge the bound effects. Out of scope for D91.
- 2026-11-09, from type-aliases: diagnostics decorate a type with its alias by type, not by what the source wrote: once `type Tok = Token` exists in a package, every message about `Token` shows `Tok (Token)`, and aliases of primitives are never shown. Showing the alias only where it was written needs the written name carried through the checker. Also: constructors through a generic alias (`Alias.Ctor`) are not available.
- 2026-11-11, from unsafe-ptr: an implementation's `alloc` and `io` are not limited to what its trait function declares, so a `Show.show` implementation can print and callers through the trait never see `io` (`unsafe` is enforced since batch-8). Enforcing it broke 21 cases, because pure trait functions such as `Show.show` have allocating implementations: closing it means adding `uses alloc` to such trait functions in the guide, SPEC, samples and `packages/traits`, and changing `effects_impl_through`. Needs a maintainer decision first. Also: SPEC could say in one line that creating an unsafe generator is allowed outside `unsafe`, and only running it is flagged.
- 2026-11-12, from checker-emitter-copies: storing a value that shares one parameter into a `mutable` parameter (`into.pairs = other.pairs` in `mergeInto`) leaves the caller's two arguments sharing after the call, and no rule checks it (1785 of the 1927 hidden copies came from it; that site now uses `copy(...)`). Treat such a store like a result without `from`. Listed in SPEC section 6 and D104.
- 2026-11-12, from checker-emitter-copies: a part taken out of a temporary copy of a heap enum (`let row = takeLeftRow(copy(tree)); row.cells[0] = 9`) compiles and copies (exit 103 under the debug copy check). D104 item 4 and a SPEC known gap. Needs a decision.
- 2026-11-12, from const-eval-design: a follow-up node const-functions-std lets `@const` bodies call the rest of the D105 std list (`std/char`, `option`, `result`, `math`, `bytes`, `fixedarray`, the sized number modules); const-functions covers string, array, map, int, float and range only.
- 2026-11-12, from const-eval-design: a top-level literal table constant builds one store per element in its D61 getter, so clang takes 25 s at -O2 for 4096 elements. const-functions writes scalar arrays as `static const` plus memcpy; literal constants should use the same writer.
- 2026-11-12, from const-functions: the language service computes `@const` constants before the shared-write check (its cache keeps effect and shared-write errors apart); `check`, `build` and `emit` do it after. A compiler built at -O0 can overflow its stack before the evaluator limits. Arrays of strings in `@const` results are written one store per element (16,384 strings take clang 16 s at -O2).
- 2026-11-12, from the batch-11 bench: `narrac emit selfhost` on the batch-10 source takes 2.408G instructions with the batch-10 compiler and 2.453G with the batch-11 compiler (+1.9%). A per-commit bisect puts the one lasting step at array-patterns (about +30M, +1.3%), but builds of an unchanged tree vary by up to 2% from C code layout. Profile the pattern passes on code with no array patterns before calling it a regression.
- 2026-11-13, from the async-core review: an indexed assignment evaluates its right side before its target. `grid[idx(0)][0] = loud(9)` calls `loud` before `idx` on feat/batch-12, and `grid[idx(0)][0] = await step()` evaluates the target after the await. TypeScript evaluates the target first. Needs a fix node with a failing test.
- 2026-11-13, from the batch-12 review fixes: a function value's type cannot tell an async function from a plain function that returns `Async<T>`, so a plain function with `from` that returns a handle shares its argument through the handle when called by name, but only through the awaited value when called through a function value. Also, `await h` of a stored handle tracks no shared result (documented gap in D109 item 9); carrying `from` through stored handles needs the marker in the `Async<T>` type.
