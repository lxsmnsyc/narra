# Outcome: from-marker

## Built

- **Syntax.** `from <parameter>` follows a result type in three places: a function declaration (`function first<T>(items: Array<T>): T from items uses alloc`), an arrow function (`(row: Row): Array<int> from row => row.cells`) and a function type (`(grid: Grid) => Array<int> from grid uses alloc`). `from` comes before `uses`. The parser reads it in `parseResultType` (`selfhost/src/parser.nra`), called for the result of `parseFuncDecl`, `parseArrow` and `parseFuncType`; it accepts `from` only when an identifier follows, so import syntax is untouched.
- **Where the marker lives in the AST** (`selfhost/src/ast.nra`):
  - `TypeExpr.resultFrom: string = ""` holds the parameter name, set only on a *result* type: `FuncDecl.result`, the `result` of `Expr.ArrowExpr`, and the boxed `result` of a function `TypeExpr`. No new AST node, no new variant field; `FuncDecl` and `ArrowExpr` are unchanged.
  - `TypeExpr.parameterNames: Array<string> = []` holds the names a function type writes (`""` for an unnamed parameter), so `from grid` in a function type can be resolved.
  - `SourceFacts.resultEnds: Map<string, Pos>` (key `getPosKey("r", resultType.pos)`) is where each result type ends, for the fix that adds `from`; `SourceFacts.valueEnds: Map<int, Pos>` (key: expression id) is where each `return` value and each arrow expression body ends, for the fix that wraps it in `copy(...)`.
  - `fmt` prints the marker in `printType` (`fmtexprs.nra`), `astdump` as a `from="name"` attribute on the result `type` line, `narrac query` signatures in `writeType` (`querysignature.nra`, which also writes the parameter names of a function type whose result has `from`), hover text in `writeFunctionType`/`writeLocalType` (`query.nra`).
- **Where the marker lives in function types** (`selfhost/src/types.nra`): `Type.TFunc(parameters, result, effects, binder, shared)`. `shared` is the index of the parameter the result shares, `-1` for a fresh result. The type key includes it (non-plain keys only), so `(Grid) => X from 0` and `(Grid) => X` are different types; the C name ignores it (`functionTypeName` in `cnames.nra`), so the emitted C is unchanged. Construction sites: `resolveType` (`resolve.nra`, from `parameterNames`), `checkArrowParts` (`closures.nra`, from the arrow's written result), named functions as values (`funcvalues.nra`, from the declaration), `substitute` keeps it; hint and std callback types use `-1`. `typeString` and the declsdump print the shared parameter as `source`: `(source: Grid) => Array<int> from source`.
- **Helpers** in `selfhost/src/check.nra`: `findSharedParameter(funcDecl): int` (the index a declaration's `from` names, or -1), `findParameterIndex(parameters, name): int`, `listSharedTypes` (private), `joinSharedTypes` (shared with the declsdump), `formatSharedSuffix`, `findFromNamePos`. `Checker.writtenFunctionTypes` (filled by `noteWrittenFunctionType` in `resolve.nra`) records the function types written without `from` in source modules by type key, for the E0977 fix. `Checker.sharedResultsUnchecked` mirrors the package switch below.
- **The body check (E0976)** is the new module `selfhost/src/sharedresults.nra`. `checkSharedResults(mutable checker, funcDecl)` runs at the end of `checkFunctionBody` (`body.nra`) for every function, implementation function and generic declaration body (not for generic instances, not for `function*`), and `checkSharedResultsIn(mutable checker, block)` for test bodies (arrow functions only). It is skipped when the body already has errors. How it decides that a result shares a parameter:
  1. One walk over the body records, per local (`BodyInfo.locals` index), the expressions it was given: its declaration value, every assignment to a place rooted at it (`a.b[0] = v` gives `v` to `a`), the subject of the pattern that binds it (`is`, `match`, destructuring), and, for a `mutable` argument, every other argument of the same call whose tracked types the mutable one has room for (`collectHeldTypes`/`haveCommonType`). A `for ... of` local records its iterable. It also records every `return` with its owner: the function, an arrow function, or a block expression (whose returns are its value), and which arrow function each local is declared in.
  2. For each return, `collectShared` follows the value: an `Ident` of a local goes to what the local was given, until it reaches a *stop local*; `FieldExpr`/`IndexExpr` follow their target; struct, array, tuple and map literals and enum constructors follow their parts (a struct spread `{ ...base }` follows `base` only when a field the literal does not write can share, because the spread copies the fields); `match` arms and block expressions follow their values; a call follows the argument `findSharedArgument` returns; `copy(...)` and every other call are fresh. A loop over a std builtin call (`Arrays.values(items)`, `Arrays.entries(items)`) shares the builtin's arguments. Any value whose checked type holds no tracked value (`canShareType`: not `isCopyTracked` and not an enum with such a payload) stops the walk, so `return board.size` shares nothing.
  3. Stop locals: for the function, its parameters; for an arrow function, its own parameters and every local declared outside it (a capture).
  4. Reported: a function parameter other than the one `from` names (E0976; without a marker the fix inserts ` from <name>` at `resultEnds`; with a marker naming another parameter the fix wraps the value in `copy(...)`); an arrow function's own parameter, the same way when the arrow writes a result type and no expected type forbids `from`, otherwise with the `copy(...)` fix (`ClosureInfo.expectsFresh`); a capture reached from an arrow function's result (E0976, fix `copy(...)`).
  - An arrow function that writes no `from` takes the `shared` of its expected function type (`checkArrowParts`, `closures.nra`), as it takes parameter types, so `(row) => row.cells` fits a `from row` slot. The arrow's node type carries the result; `findArrowShared` reads it.
  - `valueEnds` is recorded for each branch of a ternary too, so the `copy(...)` fix works on `return useFirst ? first : second`.
  E0976 also reports a `from` that names no parameter, at the name (`findFromNamePos`, `check.nra`, from `SourceFacts.fromNames`): in a declaration (`checkResultFrom`, `resolve.nra`), a function type (`findTypeShared`, `resolve.nra`) or an arrow function (`closures.nra`). The parser reports `from` with no name after it as E0976 (`` `from` needs the name of a parameter ``).
- **Assignability (E0977)** in `expectType` (`exprs.nra`): when parameter and result types match, a value whose `TFunc.shared >= 0` fits only a slot with the same `shared`, unless its result type holds no tracked value (`canShareType`). A fresh function fits any slot. The fix (`buildSharedSlotFix`) edits the slot's written type when the current module writes that function type exactly once: it inserts ` from <name>` at the type's result end and, for an unnamed parameter, `source: ` before the parameter type. Trait implementations (`traits.nra`): an implementation may drop the trait function's `from` but not add one.
- **The API a later node calls:** `findSharedArgument(checker, call): Option<Expr>` in `sharedresults.nra` answers "which argument does this call's result share": `Some(argumentExpression)` or `None` for a fresh result. It handles `Ref.Function`, `Ref.Implementation`, `Ref.TraitFunction` and calls through function values (`Ref.Value`, reading `TFunc.shared` from the callee's node type); `copy(...)` and std builtins give `None`. Call it while the call's body is current (it reads `getRef`/`getNodeType`). For "does it share argument N", compare with the argument at position N, or use `findSharedParameter(declaration)` / the callee type's `shared` directly. `canShareType(checker, type)` tells whether a value of a type can share at all.
- **Package switch.** `shared-results = "unchecked"` in `[package]` of `narra.toml` (`manifest.nra`: `Manifest.sharedResultsUnchecked`; `modules.nra`: `Package.sharedResultsUnchecked`) turns E0976 off for the whole package, including the std modules it loads. `selfhost/narra.toml` sets it. Any other value is E0409.
- **Marks added.** `std/src`: `Cells.get` (`from cell`), `Options.withDefault`/`orElse`/`okOr` (`from option`, the other parameter copied), `Math.min`/`max` (`from first`, `copy(second)`), `clamp` (`from value`), `readStep` in `coroutine.nra`, the `Shape` trait's `toValue`/`fromValue` and their `Value` implementation, `tupleItems` in `shape.nra`; `selfhost/src/stdtext.nra` regenerated. Test runner: `newCommand`, `buildSample`, `planCases`, `chooseShard`. Sample programs, packages and dump/error/query/cnames samples whose generic or struct-returning helpers share a parameter got `from` or a `copy(...)`. Guide: chapter 9 has a new section, "Return part of a parameter", that introduces `from` and why the other value is copied; `cheapest` in chapter 7 and `firstOr` in chapter 11 got `from items` and link to it; chapter 9's `knockOut` now copies with `copy(player)` and the sentence before it says so.
- **Samples.** `testdata/from_marker.nra` (+ `.out`): a fresh function and a sharing one in the same `from` slot, an arrow function with its own `from`, generic results with `int` and `Array<int>`, `Some(kept)` through a local. `testdata/errors/from_capture.nra` (arrow returning a captured array; passing generic `lastItem<T>(items: Array<T>): T from items`), `from_unmarked.nra`, `from_unknown_name.nra`, `from_slot.nra`, `from_arrow_slot.nra` (arrow into a fresh slot; passing inherited `from` and a spread whose shared field is written), `from_missing_name.nra` with `.err`. `testdata/diagnostics/from_unmarked_fix.nra`, `from_capture_fix.nra` (fix `copy(...)`), `from_slot_fix.nra` (E0977), `from_arrow_copy_fix.nra` (arrow passed to `Options.map`), `from_ternary_fix.nra` (copy fix on a ternary branch): the habits suite applies each fix and the result checks clean. `testdata/fmt/from_marker.nra`/`.fmt`, `testdata/astdump/from_marker.nra`/`.ast`, `testdata/query/from_marker/` (interface and hover).
- **Docs.** SPEC.md section 6, new subsection "Shared results", with two checked samples. DECISIONS.md D94: status line and an amendment with the closure and generic answers, the check, the order of `from` and `uses`, and the rollout switch. `compiler/README.md`: the marker and the switch.

## Deviations

- **The compiler does not check itself yet.** Under the rule, `selfhost/src` has 185 returns that share a parameter (most return a struct built from parameters, or a `Pos`/struct parameter field; all-scalar structs count as tracked, as D94 says). The compiler cannot carry `from` until the seed reads it, and a hard E0976 would fail `narrac build selfhost`. So `shared-results = "unchecked"` exists and `selfhost/narra.toml` sets it. The switch was not in the brief; the maintainer accepted it on 2026-11-10. shared-write-sweep undoes it once the compiler carries its marks:
  - `selfhost/narra.toml`: remove the `shared-results = "unchecked"` line and its comment.
  - If no other package needs the switch, remove it: `Manifest.sharedResultsUnchecked` and the `package.shared-results` key in `selfhost/src/manifest.nra`; `Package.sharedResultsUnchecked` and its copy in `loadPackage` in `selfhost/src/modules.nra`; `Checker.sharedResultsUnchecked` in `selfhost/src/check.nra`; its assignment in `checkModules` and the test in `skipsSharedResults` in `selfhost/src/body.nra`; the switch sentences in SPEC.md section 6 (Shared results), DECISIONS.md D94 (amendment, Rollout) and `compiler/README.md` (package section). The debate estimated 30 to 50 marks; the real count is about 185 return sites in about 150 functions, and about 15 of them share two parameters and need a `copy(...)` too.
- **New module** `selfhost/src/sharedresults.nra` (inside the shared path `selfhost/src/**`).
- **Files outside the owned paths, all in shared paths:** `selfhost/src/{ast,astdump,body,calls,check,closures,cnames,declsdump,diagnostics,effects,emitclosures,emitexprs,emitstate,emittail,exprs,fmtexprs,funcvalues,generics,manifest,modules,parser,query,querysignature,resolve,stdresult,stdtest,stdtext,traits,types}.nra`, `selfhost/narra.toml`, `selfhost/tests/src/{main,shell,spec}.nra`, `std/src/{cell,coroutine,math,option,shape}.nra`, about 40 existing samples and goldens under `testdata/` (marks, copies, `.err`, typesdump and query goldens), `testdata/diagnostics/from_*`, `testdata/astdump/from_marker.*`, `testdata/query/from_marker/`, `SPEC.md`, `DECISIONS.md`, `compiler/README.md`, `docs/guide/{07-traits,09-memory-and-mutable,11-narra-for-typescript-programmers}.md`. `selfhost/narra.toml` is not in the brief's shared list.
- `parser.nra` edits are small: one new function `parseResultType`, three call sites, the name capture in `parseFuncType`, two `valueEnds` lines, the facts constructor. After the rebase onto parser-token-kinds the token test is `isAt(parser, SYMBOL_KEYWORD_FROM)`.
- Function types printed by the checker name the shared parameter `source`, because `TFunc` keeps no parameter names (names are not part of type identity). Signatures and hover text of declarations use the real names.
- E0977 is not reported when the function's result holds no tracked value (for example `first<T>` instantiated with `int` stored in `(Array<int>) => int`). This follows "when T is a scalar the marker changes nothing".

## Gotchas

- **std builtins are fresh.** `Arrays.get`, `Maps.get` and the other builtins registered in `selfhost/src/std*.nra` have no `from`, so `return Options.withDefault(Maps.get(table, key), x)` is fine but `Maps.get(table, key)` itself counts as fresh. Only `for ... of` over a builtin call shares the builtin's arguments. shared-write-check should decide whether builtin rows need a `shared` column.
- The walk is flow-insensitive: a local shares everything it was ever given, so `let list = items; list = copy(list); return list` is still reported. Reassigning a local whole does not end its sharing in this check.
- A `mutable` argument takes every other argument whose tracked types it has room for (by type key, with type parameters matching anything). This is conservative: `readComment(mutable sample, lines, ...)` makes `sample` share `lines` because `SpecSample` holds an `Array<string>`.
- `copy(...)` of a type parameter is allowed in a generic body, so `copy(fallback)` is the fix for a second shared parameter in generic code; for an instance with `int` it emits the value itself.
- A trait function's `from` applies to calls through the trait (`Ref.TraitFunction`); an implementation's own `from` applies to direct calls (`Ref.Implementation`). The `Shape` trait now has `from value`, so derived `toValue` results share their argument for callers.
- Generic instances are not checked again (only the declaration body), the same as the missing-return check.
- E0976 is skipped for a body with other errors, and the effect pass does not run when the checker reports errors, so an E0976 can hide effect errors in a sample (seen in `testdata/errors/generator_bound_*`).
- `Checker.writtenFunctionTypes` grows with every function type written in source; the E0977 fix gives up when the module writes the slot's type more than once.
