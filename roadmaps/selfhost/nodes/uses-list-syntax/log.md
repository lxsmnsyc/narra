# Log: uses-list-syntax

- Base `feat/batch-13` at a2c7f01d. Base compiler: `sh selfhost/bootstrap.sh /private/tmp/claude-501/uses-list-syntax/base` (release build, `-O2 -DNARRA_RELEASE`).
- Proof on the base: `base/narrac run testdata/uses_list_types.nra` prints `uses_list_types.nra:8:52: expected a name, found "("`, exit 1. The branch compiler runs it and prints the checked output.
- `Map<Generator<int> uses (io, alloc), int>` cannot run: a generator is not hashable (E-message `cannot be a map key`). The sample puts the generator first in `Pair<Generator<int> uses (io, alloc), int>` instead, and keeps the Map form in `testdata/parse/uses_list_forms.nra`.
- Parser: `parseTypeUses` (type form) for the generator branch of `parseType` and for `parseFuncType`; `parseUsesList` stays the bare declaration loop. `isParamAfterComma` is gone. E1240 comes from `reportTypeUsesComma`, which looks at the tokens `uses name , name` around a comma: after a declaration's result type, and before a parameter name with no `:`. No newline tokens occur inside parentheses, so the token walk needs no newline skipping.
- Checker: `reportEffectArgument` at the top of `resolveType` gives E1241 with the parentheses hint when an argument that is an effect name follows a type that ends with a `uses` list (the generator's own, or a function type's result); `reportUnknownType` (E1241 without the hint, else E0118) replaces the two E0118 sites in `resolve.nra` and `traits.nra`. An effect name is `io`, `alloc`, `unsafe` or an effect variable of the function being checked, and only when no type of that name exists.
- Display: new module `selfhost/src/typeuses.nra` with `writeTypeUses`, used by `check.nra` (generator and function types), `declsdump.nra`, `query.nra` (type-of of a named function and of an arrow) and `querysignature.nra` (`writeType`) and the two type printers in `fmtexprs.nra`. `usesSuffix` had only type callers, so it is removed rather than kept beside the new helper. Declaration lists (`querysignature` line for a FuncDecl, hover `uses a, b`, query `effects:`) never went through it and stay bare.
- fmt: `endsWithUses` and `canEndWithComma` are gone; `printParameterList` lost its trailing-comma parameter (one caller, always true now).
- Sources rewritten with `/private/tmp/claude-501/uses-list-syntax/rewrite.py` (base `narrac parse`, every type node with `uses=` holding a comma): 34 files, 44 lists, including the two in `selfhost/tests/src/registry.nra`. None in `selfhost/src` or `std/src`.
- A comment inside the parentheses moves like the known `uses /* c */` bug: `Generator<int> uses (io, /* c */ alloc)` formats as `Generator<int /* c */> uses (io, alloc)`. Not fixed; a line went to the inbox.
