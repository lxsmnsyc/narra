# Premortem: batch-7

It is a week from now and batch-7 is late or reverted. Why?

1. **Tree shaking dropped a function that only C-level code reaches.** Trait implementations called from generated eq/hash/show/map helpers, generator resume functions, closure environments and the test main are reached from emitter-written C, not from checker references. A missed edge is a C compile or link error in some sample, or worse, in the stage 2 compiler only. Change: tree-shake takes every implementation of a trait for a reachable type instead of tracking dispatch; acceptance needs the bootstrap fixed point and the full suite; types and helpers move to a separate node (tree-shake-types) so the function graph lands and is reviewed first.
2. **place-ids changed which shared writes are reported.** The string keys encode literal indexes (`[=N]`), "any element" (`[]`) and field paths with ad hoc matching rules that a structural rewrite can subtly change. Change: acceptance requires identical diagnostics, fixes and positions on every `shared_write_*` sample, plus the compiler and std staying clean of E0978. The worker diffs `check` output on all samples before and after.
3. **A contract condition proves something unsound.** `requires` facts feed the prover that removed runtime zero and shift checks (proven-operands), so a wrong fact is undefined behavior in C, not a panic. Function values could bypass the condition. Change: a function with `requires` cannot be a function value (maintainer decision recorded in the contracts brief); conditions outside the prover's known forms are an error at the declaration; the fresh review of the batch probes calls through generics, closures and `typeof`.
4. **Build-condition folding emitted no branch, or both.** `else if` chains, `&&`/`||`, and a condition mixing build constants with runtime values must fold exactly; the release flag must reach `Build.debug`. A wrong fold builds and runs on the host and fails only on the other OS (Linux check). Change: acceptance has debug and release runs; the batch's Linux check runs every sample on Linux; build-targets' `check --all-targets` exercises the non-host branches.
5. **The emitter nodes conflicted and the seed needed an extra round.** return-trailer, copy-check-macros and the two tree-shake nodes all edit the emitter, and copy-check-macros edits runtime text, which can need two seed updates. Change: the four land in a fixed order through hard edges, each rebasing; the story brief plans the possible seed, switch, seed sequence at the end.

Accepted risk: contracts and build-conditions share the parser, checker and `fmt` switches with no split node first. Every syntax batch has edited them this way; new logic goes into modules of its own, so conflicts are dispatch lines.
